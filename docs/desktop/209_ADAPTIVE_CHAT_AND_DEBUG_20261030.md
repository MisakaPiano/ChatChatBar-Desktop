## 用户确认的界面规则

- 自动增长先把对话阅读宽度补到 880dp，再增加人物栏到姓名／较宽状态模式，最后预留右侧导航空间；人物栏可手动拖宽并持久记忆，空间暂时不足不覆盖偏好。
- 缩窄先回收人物栏富余宽度，再退到头像，空间仍不足才先收会话列表、后收人物栏。恢复自动收栏使用 64dp 回差；手动收栏不自动恢复。
- 唯一展开／收起柄放在分隔条上，收起仍可就地展开；双击分隔条恢复自动宽度。计数与齿轮同一块、单行；顶部快速浮层只在最窄模式出现。
- “原地展开状态”下新增“允许同时展开多个状态”，默认关闭并持久记忆。开启后逐个人物独立点开／收起；关闭后保留最近展开的一个。此偏好只影响显示，不改驻场、注入、角色开关或原状态文字。
- 管理／设置／数据左侧导航和工具页侧栏的进一步统一暂缓，以后参照 Studio Suite Desktop；本轮不借机重组原操作。

## 调试入口与维护

官方 Android 的聊天顶栏在 `DebugConfig.SHOW_DEBUG_UI` 下打开 `DebugLogDialog`。Desktop 工具页原“高级／诊断”是请求组装预览，不冒充该聊天日志。

新增入口位于聊天已有“模型详情”展开区，避免常驻额外按钮。`DesktopChatDebugPanel` 按会话查看本次运行的实际请求 JSON、从实际请求提取的 System 消息、计划中的 RAG／世界书记录、服务端 usage、原始输出／推理、有限 SSE 片段、重试与错误；记录有界、脱敏、截断可见，只在内存保存。打开、选择、复制或清空日志不重组请求，不额外调用模型。

用户明确要求日志与维护工具一起补：

- RAG 重建与官方当前 `ChatViewModel.rebuildRagIndex` 一致，作用于当前角色卡参考文档，不替代历史 RAG 或长期记忆。复用 `DesktopDocumentIndexService` 的严格源／配置复核和 journal 发布；每份文档成功后替换，失败保留该文档旧索引，已完成文档不伪称撤销。
- 消息顺序先只读预览，共享 `ChatRepository` 原顺序备份、预览基线与撤销检查；应用／撤销均单独确认。保留正文、媒体、时间和 source-turn 身份。占用会话时拒绝，关闭调试页不取消应用拥有的操作，应用退出先排水；顺序写入完成后只检测记忆来源，不启动 AI 修复。
