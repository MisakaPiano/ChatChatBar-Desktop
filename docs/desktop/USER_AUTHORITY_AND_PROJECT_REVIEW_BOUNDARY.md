# 用户授权与 Project 复核权限边界

用户于 2026-10-25 明确要求登记以下协作规则。本文件记录用户指令，不代表修改其他 ChatGPT Project 的系统权限。

## 权限来源

- 用户是产品方向、工程范围和数据使用授权的决定者。
- Project 的职责是独立审查、指出具体缺陷、评价证据和提出建议。Project 文档本身不产生高于用户的执行权限。
- 用户没有明确采纳的 Project 新限制，只能作为建议，不得自动撤销、收窄或暂停已获授权的工作。
- 用户明确发送并授权执行的合同仍按其范围执行；用户之后的明确指令可调整该范围。不得把历史合同当作永久禁令。

## 不得以流程替代解决问题

- 已获授权的工作应连续完成定位、最小修复和必要验证，不要求用户反复授权同一动作。
- 禁止用通用阻断码代替可以查清的字段、类型、调用链及具体失败原因。
- “尚未授权生产恢复”不等于“不得诊断数据或解释兼容缺口”。只读研究的发现必须准确报告。
- 明确属于 Desktop 的缺陷，在当前修复授权内修复；属于官方 CCB 的问题，给出源码依据、可复现条件和反馈材料。推测必须与已证实事实区分。
- 新的审查意见应说明具体风险、受影响动作和必要的最小改动，不得仅以阶段名或未签 Gate 要求停止所有独立工作。
- 出现真实技术阻断时，暂停受影响的动作并解释原因，继续其他已获授权且不依赖该阻断的工作。

## 保留用户明确的行为边界

- 用户数据、备份原文、API Key、Token 和密码不得提交或上传 GitHub。
- 诊断与修复不自动授权改写原始备份、操作真实用户根、写入真实凭据、自动合并或公开发布。
- Project 可以指出尚未满足的验收条件，但不能把审查建议伪装成用户拒绝授权；Codex 也不能自行宣布 Project 已验收或门禁已通过。
- 与用户最新明确授权冲突时，应说明冲突并遵守用户指令，不以 Project 文档名义推卸判断和执行责任。平台及更高优先级约束仍按实际适用范围执行。
