## 本轮用户方向与范围

用户在协调对话明确提出：“目标是正式版的发布……先补全还没做的部分，然后进入验收和不断打磨，最终发布”。本机授权回执：`I:/CCB-Desktop-Continuity/updates/20261101-081021-desktop-1-0-goal-authority.json`。该方向调整此前“小修之后仍暂停所有新大 phase”的总体调度；当前具体小修仍优先，之后按依赖继续原路线。它不把具体暂缓项重新纳入，不自动确认真实资料合并选择，也不改 Prompt 文案权限。

原 P12–P18 范围来自路线历史 `98cb65e5:docs/desktop/17_ROADMAP.md`，再对照当前 AppContainer、桌面路由／编辑器／任务／备份代码、`.github/workflows`、207–215 和功能维护技能核实。旧 `13_FEATURE_PARITY.md` 的 PENDING 只作查漏索引，不能据此重做已交付语音、RAG、记忆、迁移、更新器或格式修复；本次不批量提升 parity 或上游 baseline。

状态含义：**已实现且验证**＝已有对应工程证据，未必包含所有真人环境；**已实现待验**＝实现或指定验收缺口仍在；**未做**＝桌面入口／编排未接通，即使 Android 服务存在也不算桌面完成；**外部依赖**仅挂对应实际步骤；**明确暂缓**保留用户原决定。一个功能的结果不能代表整个 phase 完成。
