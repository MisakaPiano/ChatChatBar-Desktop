# 历史缩略图的独立读取与解码预算

当前源码：`256d8daa`；工程检查在 R144 进行中，尚未交付。

上游 `1d2850` 的图库加载器有独立有限的读取／解码通道。桌面现有缩略图已按格子尺寸采样，也保留了重组不重复读取、原图方向及字节不变等检查；但 `DesktopHistoryThumbnail → DesktopOwnedImage → readBytes` 没有图库级并发预算。多格同时可见会并行分配多个原图，不据此宣称已经复现内存溢出，也不撤回旧尺寸／像素检查。

`DesktopStudioHistory` 现在为自己的网格持有两个名额，传到实际缩略图及图片加载器。名额从读取文件前开始持有，贯穿首次解码和发布；实际网格调用已有的 32 MiB 有界 owned-image 读取入口。完整图片和详情预览保持独立，不增加全局锁或持久化缩略图缓存。

APNG 与普通动画路径保留。等待下一帧前释放名额，等待完成后重新申请，再继续解码；退出、读取失败和取消在原调用的 finally 中释放。同步读取不能被立即中断，名额会等该读取实际结束才归还，避免释放后启动更多并行读取；取消后的内容不进入解码／发布。

R144 只选择新增的两个完整场景方法与原有两个邻接方法：八个缩略图阻塞时只开始两个读取、完整详情独立、离开页面取消队列、失败后重开，以及两张 APNG 十秒帧等待不会阻塞第三张静态图。邻接检查为格子尺寸／重组稳定和 metadata-only 零读取。排队或编译成功不等于这些方法已通过，最终结果另记。

此项不改变源图片、历史元数据、选择／删除／导出、配方和 Seed 操作，也不涉及提示词、付费调用、日常资料或公开发行。
