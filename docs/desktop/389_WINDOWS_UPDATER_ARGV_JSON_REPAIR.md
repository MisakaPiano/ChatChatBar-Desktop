# Windows 更新器参数传递修复 / 2026-11-08

1244 的真人更新至 1245 在下载前报 `JSONDecodeError`。这不是 1245 功能验收失败，也不撤销此前其他功能的限定 PASS。

只读保全后的安装配置、签名缓存和旧下载回执均可解析；更新器与安装清单相符，未清理或修改现用缓存。云端 run `42426373935` 使用冻结 1244 helper、实际 JDK 17 ProcessBuilder 和合成无凭据路由复现：185 字符、24 个引号变为 161 字符、0 个引号，JSON 在位置 1 解析失败。Python subprocess 对照保留原文。故障发生在读取安装身份、联网或写入缓存之前。云端 JDK 为 17.0.21；本机安装清单为 17.0.20.1，尚无本机 JVM 复测。

当前源码将同一 UTF-8 路由文档以有界 canonical Base64 参数传给 Python，保留 legacy JSON CLI。解码限制、非法编码和格式拒绝发生在身份与缓存读取前；HTTP/SOCKS/DIRECT 路由选择、TUF 信任根、版本、签名、重定向及下载二验保持原逻辑。坏参数不会改为直连。既有 `test_proxy_cli.py` 的直接 Python 调用不能覆盖 Windows JVM 参数边界，新增云端 Java bridge 验证该边界。

原公开 1245 也包含旧调用方式。签名元数据更新不能给已经安装的 1244/1245 增加源码修复。普通官方安装包可用于手动升级；1245 安装包只提供原功能，不解决这个更新器错误。[私有 1246](390_PRIVATE1246_UPDATER_REPAIR_CANDIDATE.md) 已完成必要定向验证、普通包隔离生命周期和最终签名验包；尚未发布、安装或取得新版真人结论。私有原报告及缓存快照留在 I 盘，不上传真实资料。
