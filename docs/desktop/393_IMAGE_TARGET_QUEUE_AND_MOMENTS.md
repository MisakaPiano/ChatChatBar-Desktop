# 聊天图片与朋友圈的目标保护和安全排队

2026-11-08，源码与受影响工程验证完成，尚未打包交付。公开仍1246／签名更新28。

用户D1反馈三处聊天图片锁和朋友圈只能提交一个任务。源码原因是：聊天 `DesktopAssistantImageActions.running` 使用同会话任意RUNNING；旧图编辑窗口能打开，但提交到 `DesktopTaskRuntime.launchNovelAi` 会被全局任意NOVELAI直接拒绝；朋友圈单worker和全页busy同时封锁其他卡/动态，creative child又以会话为键。

本轮保留串行真实工作，允许准备和安全排队，不开放双NovelAI并发：

- 手动聊天图片按来源消息保护，不再把其他来源任务当总锁。生图要求可继续编辑，同一来源已有任务时不重复提交。
- 提交前捕获会话、角色、辅助模型、上下文、玩家、偏好与NovelAI账户；旧图编辑重生保留原草稿、参数和消息锚点。排队期间改其他配置不会回写正在执行任务。
- 原运行任务继续，其他来源任务进入同一可取消工作通道。等待任务显示等待阶段；停止、重试、维护和退出仍由原任务owner负责。默认其他入口原有拒绝条件保留。
- 朋友圈按新动态所属卡或现有动态编号保留目标归属，其他目标可以提交。其原正文/图片/原子Store/清理流程进入同一通道串行执行；等待时不持有数据操作租约。停止单项不停止其他排队项，暂停和退出排空所有owned jobs。已保存图片版本的浏览/选择沿用原流程。
- 新动态建立占位记录后，同一worker也登记该确切post编号，避免刷新后通过占位记录重复提交；取消或完成时连同原卡目标一起释放。

必要合成验证将覆盖：其他来源按钮保持可用、同源重复拒绝、等待取消不提前放行后继、明确重试、维护排空、排队参数与账户快照、图片来源不串挂、朋友圈不同卡/动态及确切停止、原图片版本完成/失败/取消与原子写语义。云端执行，无本机JVM、真实数据或收费复现。
