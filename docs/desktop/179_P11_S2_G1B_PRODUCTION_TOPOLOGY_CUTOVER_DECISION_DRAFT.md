## Project's conditional recommendation, **not yet a user decision**

Prefer further design of **B: per-data-root credential namespaces**, specifically investigate **B + prepare-into-fresh-root + authority-switch-on-restart** as a Preview-oriented alternative to in-place mutation of shared profile keys. A (profile-shared keys + coordinator) remains a compatibility comparator only: T0 proves an undeclared/offline C and noncooperating old writer defeat claims that all shared-key consumers are closed. B's synthetic smaller blast radius is **not** a proof of actual Windows protected key portability, legacy-key migration, or downgrade enforcement.

**Candidate user-visible flow:** user chooses and authenticates the original `.cbbackup` (original remains theirs); CCB verifies complete source graph, known credentials/accounts/resource ownership and capacity; prepares a **separate inactive destination** and **fresh isolated protected key namespace**; offers a complete replacement/cutover confirmation; on proven prepare/authority commit, seals restart-required; next startup verifies data/Key/receipt consistency *before business hydration*. The old authoritative root and old shared key blobs remain intact. Import is not successful until the new state is reverified. This is **not** a claim that existing D2/D3 can already restore external archives or secrets; only their copy+authority+restart safety principles may be reused after source audit.

## Candidate contracts requiring exact-source audit and approval

1. **Identity/provenance.** Proposed root binding is not a copied UUID/path alone: reconcile data-root native volume/file evidence, an independently owned versioned identity/generation authority, Windows user/protector context, and explicit clone/move/rebind rules. Native IDs may change on copy/relocation; lost profile authority must fail closed rather than silently generating a replacement binding. No path, marker, registry or schemaVersion is selected yet.
2. **Credential scope.** Root-local NovelAI/Fish/SiliconFlow global defaults, model IDs, legacy embedding and singleton embedding require exact account/provider/endpoint binding. New namespace cannot borrow a mismatched legacy shared key. Existing profile-shared ciphertext remains retained/readable by old versions until user-directed and independently verified migration. No automatic removal, fallback, rebind, or overwrite. Account conflict requires explicit user confirmation or safe refusal; archive password alone is not overwrite consent.
3. **Atomic cutover.** Prepare fresh target payload/media/seal + protected new credentials independently; respect current root owner, task/scheduler drain, snapshot, and capacity. Protect independently recoverable old/new artifacts. Design **one discoverable authenticated authority** and monotonic generation/fencing; the root authority switch and startup admission must have unambiguous recovered outcomes. Lost/conflicting receipt, foreign mutation, unsupported atomic publication, wrong Windows protection context or missing domain = BLOCKED, evidence retained. `ALL_OLD` is import **not applied**; `ALL_NEW` requires actual complete bytes and readable protected participants. No multi-file physical atomicity claim.
4. **Portable and clone.** Profile DPAPI ciphertext must not be represented as portable. Root switch D-023–D-026 only covers bootstrap-controlled provenance, not `PORTABLE` or `CLI_OVERRIDE`. Define relocation/rebind and secrets re-entry or explicit, authorized encrypted transfer before claiming Portable/full-app parity; missing protector/profile means no invented credential recovery.
5. **Legacy old-binary barrier.** A marker or new lock checked by new binaries does **not** constrain old binaries. Prior old EXE may open an upgraded root using its own root-selection path; user-approved R03 demands **enforceable isolation or refusal**, actual isolated old-binary/Portable/root-switch countertests, and no unsupported downgrade writes. No automatic execution of historical EXEs is approved. **This is an unresolved release blocker**, not cured by side-by-side roots or a warning alone.
6. **Other source domains.** CommunitySession has **no current protected target** and needs a bounded protected session lifecycle/sink or justified precommit incompatibility decision. R01/R02 **C-A MomentPost/Task archival** requires original JSON bytes + independently owned three-path media, no live scheduler or automatic deletion. D-038 also requires `.cbsave`, RAG/Memory/voice/drafts/full-backup round-trip and independent Android/Windows evidence. Do not let credential topology silently replace these obligations.

## Threat model and evidence boundary

Initial target may defend against accidental crashes/cancellation, concurrent **cooperative** CCB processes, immutable/synthetic interrupted state and outside profile/root unavailability. This alone does **not** prove resistance to a malicious same-user process/legacy binary or physical power loss. Windows file-ID is an object witness on one machine, not a durable root/account identifier. OS DPAPI is tied to protection context; copying ciphertext is not portable authentication. Process-acquired mutexes and existing root `FileLock` are not global old-writer exclusion. Exact threat model, supported filesystem/volumes, authority durability, ACLs, profile identity and negative tests must be frozen before persistent code.
