# 现代导入模式

固定上游12e420a5的BackupMergeEngine提供UPDATE_EXISTING、ADD_COPIES和按scope的REPLACE_ALL；旧Desktop只做显式冲突合并，相同内容过滤后不能靠BOTH实现新增副本，也不能处理已选但为空的集合。新DesktopMergeRestoreModes在既有实际导入Panel加入三个明确模式，默认仍是逐项合并。

新增独立副本：相同内容也进入准备，所有采用的primary/embedded IDs及消息、草稿session按typed domain独立。已有目标或重名时，使用上游trim/空白未命名/80字/NFKC去重的副本命名；源卡片、原文和默认逐项BOTH不改名。设定、singleton偏好和凭据不是凭空复制成第二份全局设置，按所选范围及独立凭据选择处理。

更新已有：编号优先；会话匹配限制在最终所属卡片域；唯一规范名称可采用电脑身份。非命名历史按去掉id/updatedAt并归一媒体hash的指纹匹配；歧义或重复声明不覆盖多个目标，保留原件并创建副本、显示提示。保留会话中的全局消息ID冲突只重写导入消息及真实引用，不改电脑的另一会话。

替换所选范围：现代scope中明确勾选的模型、embedding、格式/世界书、编辑草稿、玩家、历史和动态等集合即使为空也处理；卡片/会话只匹配采用的对象，不因空列表清空全部电脑卡片。未选内容仍引用的模型/格式/世界书，以及明确未含原图的历史记录按归属保留并提示。未带入的已选设定字段恢复默认、未选字段保留；lastSeen随相应会话/动态范围，动态自动启动确认重置。tagCatalog单独按pair选取或明确空集合重置；旧无scope全量替换准备只含导入内容的新根，原根和原包始终保留。内部完成marker仍取已完成高值，不重放已完成迁移。

预览不在Compose调用栈做磁盘遍历。Service持同一Preview mutex在IO计算；Controller有可取消job、代数及精确Preview身份，仅发布计数和提示。切换立即清旧摘要及确认；计算中或失败不能提交，失败提示与受限代码详情可查看；discard/reinspect/close等待同owner后释放scratch。真正提交重新计算方案，再复用真实源复查、runtime排水、exclusive快照、新根准备与受保护凭据回读/启动位置发布，不直接清电脑根。

新合成检查待云端原件：相同/独有对象及内嵌人物/草稿复制、规范名称与歧义、空范围/依赖和设定、消息碰撞与catalog空选择、历史指纹、实际Service三种提交/新Store读取/凭据与原件保全，以及实际Controller后台切换/取消/失败/释放生命周期。未据此提前称完整Engine等位、真人验收或已交付；现有原件有效检查继续分源保留。本轮不另行打包或公开，待完整批次收敛再集中交付。
