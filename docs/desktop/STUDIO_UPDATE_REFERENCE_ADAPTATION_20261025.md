## 最小实施顺序

1. 用 Desktop 自己的阻塞操作复现关闭准入窗口；先停止新任务，再保持原有任务取消/完成与持久化合同，最后释放根锁。
2. 完成当前原始记录/独立媒体保全、真实合并预览与引用重映射、凭据隔离提交及重启验证。程序回滚与资料回滚分开，不让旧程序直开新格式。
3. 为 native 安装版本建立独立、可追踪且严格递增的构建身份；固定 Desktop 自己的产品升级身份。不要复制 Studio 标识、端点、DPAPI 配置、根信任或签名材料。
4. 从准确源码生成 Desktop 独立包与清单，使用专用合成安装身份/目标与数据根完成下表；确认日常安装不会被替换后才执行。
5. 依据 Desktop 实际证据推进已有 Preview 授权；未覆盖的人工/平台项如实列出，不等待新研究阶段。

## 独立合成安装与升级验证方案

| 情况 | 操作与预期 | 必须保留的证据 |
|---|---|---|
| 首次安装 A | 专用测试产品身份、新目标；程序和合成资料/凭据目录不重叠 | 包/安装文件清单、实际 version/commit/channel、根选择、正常启动/关闭及全部所属进程退出 |
| A→B | 不同 native 版本；A 退出排水、B 读取同一合成状态和受保护假密钥后才记成功 | 前后数据/媒体长度及 SHA、凭据仅等值结果、bootstrap 条件、B 重启后验证 |
| 安装失败/空间不足 | 可控拒绝或故障注入；不改变旧入口/资料 | 真实退出码和失败阶段；A 可重开，未完成 B 保留为失败现场 |
| 文件占用 | 持有专属合成安装文件句柄；不得杀死无关进程 | 明确失败/延迟状态；旧包与资料保持，不能记 COMPLETE |
| 并发/延迟提交 | 两份合成计划竞争；重新核对旧入口和根身份 | 仅匹配期望状态者提交，过期计划拒绝；锁本身不替代条件核对 |
| 回滚 | B 失败后使用 A 兼容的原始合成根；新格式保留在独立根 | A/B 身份及各自资料副本，未知兼容时阻断；不把程序降级当数据降级 |
| 清理/卸载 | 仅认证安装清单内且字节未变的专属程序文件 | 未知/改动/重解析/占用文件保留；不进入资料、备份、导出或凭据目录；证据置于清理目标之外 |
