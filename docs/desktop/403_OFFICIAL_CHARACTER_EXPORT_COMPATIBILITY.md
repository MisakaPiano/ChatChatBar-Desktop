# 角色卡默认导出兼容性修复

## 问题与边界

官方1.4.11固定源码 `87d1ab5e209233b66f0db9129e984cce0d437499` 的角色卡读取器仅接受 schema3–9。Desktop 保存旧 PNG 的独立原图后，原默认导出会升为10，导致普通旧卡仅编辑文字后也无法再交给该官方读取器。这是交付前必须修复的默认流程回归；旧源码 `28180574` 的打包不能作为成熟1247交付。

## 当前改动

- 核心默认 JSON／package 导出为官方兼容9，不读取或输出仅独立封面使用的资源，不改写本地封面、头像、背景、正文或 Prompt。
- JSON、PNG 的实际界面均默认“官方 CCB 兼容”，可以明确选择“Desktop 完整格式”。完整格式输出10，界面说明当前官方不支持，不据此宣称 Android 双端传输已验收。
- PNG 外观与数据格式独立：兼容文件仍保留原 PNG 尺寸及编码图片块。仅更新当前角色数据，不要求先清除原图。
- 兼容投影仅去掉独立封面引用及仅供封面使用的资源；头像、背景或人物图片若引用同一资源，该资源继续保留。复制角色仍保留独立原图。
- 导出取消后旧草稿不能再次写入。完整 JSON 选择会重新核对卡片及关联资源，避免把不同时刻的数据拼在一起。原文件覆盖保护继续生效。

## 必要验证

共享投影、真实核心与控制器 JSON／PNG 默认和完整导出、普通旧 PNG→改文字→导出、原图字节与本地引用保全、取消／重入／资源改变、缺失的独立封面不妨碍兼容 JSON、真实管理入口和格式选择界面列入定向检查。

测试命名空间 `desktop.interop.official1411` 保留官方 DTO、读取校验和两个依赖，只有 package namespace 变化；旁置 origin JSON 记录固定源码、Git blob 和 SHA256。它校验实际输出的兼容9，并应拒绝完整10。这是固定官方读取器的工程证据，不能代替 Android 设备、完整图库或双向往返验收。

当前检查结果等待新源码的云端实际回执；不得把旧原图16项或旧源码集成结果当成本次默认格式修复已通过。公开版本、签名信息和现用根保持原状态，1247仍只准备未公开候选。
