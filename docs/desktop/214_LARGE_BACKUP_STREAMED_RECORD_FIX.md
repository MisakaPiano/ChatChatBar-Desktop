# 大备份逐条处理修复

2026-10-31 JST。用户同意按文件逐条处理，并同步修读取、合并与导出。保留全部RAG、记忆、存档内容；不改Prompt或正式上游基线。

## 实现

- 现代生产读取逐条验证完整实体，只保留scope使用的紧凑字段；code84字段兼容仍按最终认证manifest检查。取消、CRC、散列、清单、schema、scope和ZIP32边界保留。
- 移除现代整包JSON累计64MiB和单实体8MiB格式门槛。每条解析仍有独立工作内存预算（最大堆的八分之一，且不超过现有256MiB条目上限），不足时保留数字化资源类别；元数据、旧Prepared和S0路径边界不混用。
- 暂存与预览使用按需文件视图；规范化会话指纹逐条送入同一散列序列，不改变分组、冲突选择或附件散列语义。计划重映射写入受所有权管理的临时记录文件，避免重复保留向量和正文对象。
- 新根Result计划在凭据准备／提交过程保持有效，由Service在操作结束关闭。失败清理计划scratch并使Pending失效；源根与备份原件不变。PC快照仍逐条重验typed／credential-free约束。
- 现代导出逐条处理，保留凭据覆盖与源复核。大内联SaveSlot及原包保全使用同样的单条工作预算。UI区分密码缺失、资源不足和结构错误；不向用户暴露原始异常片段。
