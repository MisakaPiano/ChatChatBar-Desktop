每份快照必须显式声明完整 `coveredTypes`；双方当前覆盖必须一致。后续范围可由旧共同基线的子集扩容，保留旧revision/hash/删除权，不允许静默缩小；新增独立单元没有旧hash，只按新增比较，双方共同完成后才取得后续删除证据。不把未参与的数据解释成删除，也不清空基线或重建资料根来扩容。`excludedTypes` 为本次本机观察到的未参与类别。共同基线绑定证书设备身份、协议/覆盖及双方完成回执。单侧已应用时保留事务，不宣称两设备原子提交。

已交付首包按持久ID识别对象。两端各自首次安装的同一预置可能具有不同随机ID，首包尚未按唯一来源证据对齐；会作为两项保留，不能把名称相同当成同一对象，也不能为去重重写本机ID而破坏未参与同步的资料引用。

后续候选沿用协议2已验证的来源映射：只在双方来源key唯一、版本相同且完整业务内容/声明结构一致时对齐，手机在新鲜快照下复核后持久化本机到同步身份的双向映射。原物理ID与未参与资料的引用保持；后续内容变化沿用映射进入三方比较。协议2的专项云端测试已通过，尚未随首包交付；协议3的范围能力握手/增量扩容另行验证。初始内容分歧、来源重复/缺失、版本不同的对象仍分别保留，初始人工归并尚待后续实现。

已交付首包使用协议1，文件与回执冻结不覆盖。当前候选协议5需两端匹配，hello显式核对两端当前完整范围；不同版本或不同当前范围应在信任、映射和资料写入前拒绝，并说明需要配套版本。协议4增加关联动态的共同成员证据和明确选择的记录范围；协议3即使覆盖类别相同也不能混接。比较时联合两端当前任务关联与旧共同成员关系，避免新增更小任务ID或删除旧任务把同一动态拆成重复的新增与冲突；多个旧组相连且两端不同时必须明确选择，不推测旧哈希的合并内容。协议5增加明确的电脑暂停响应和按原始内容校验的氛围编码资源；旧端不能按覆盖相同假定支持新消息。旧协议1–4的已知待确认计划按原范围核验接续，不清空基线。Android各次云构建的调试证书已观察到不同，后续同包名换版必须先闭合签名连续性；不能要求卸载或清资料来绕过，也不假定用户尚未产生测试资料。
