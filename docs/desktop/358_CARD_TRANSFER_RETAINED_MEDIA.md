# 删除或覆盖角色卡后的历史媒体

官方1a DeletionCoordinator保留朋友圈历史作者头像/图片；Desktop MomentStore.begin直接保存人物appearanceImage或card.avatar的原reference，complete/edit保留它。普通管理删除和typed导入覆盖走shared Core，原Core.cleanupOwnedResources却直接调用Desktop资源Store.deleteOwned，因此可能删掉仍被历史动态和其他卡引用的文件。这不是R87容错可以授权的主动删除。R98原件319B、SHA256 0a3f57f09ed657607b2c7816e15f6bbcb53c1f5465ff84f47d8ac65e364cb1f0仅source/0XML；原job日志确认新夹具误用不存在的saveSession，编译失败，0业务方法运行，不当作旧真实删除反例。后继改真实createSession API。

Core新增可选postCommitResourceCleanup：仅在已提交的overwrite/delete捕获候选，文档RAG清理保持原normal边界，退出该normal operation后才调用Desktop全引用exclusive cleaner。默认/Android未注入时保持原inline清理；未提交的新资源物化回滚仍按精确新资源归属清理。AppContainer对普通管理/typed/Core共同入口注入既有DesktopOwnedImageCleanup，历史post/message/draft/其他卡的持久化引用可保留文件，无引用的旧图片/文档正常回收。

若其他实体记录损坏而无法核实引用，保留文件并使用现有已提交transfer warning，不复活已删卡、不改写旧post或假装覆盖没保存。清理等其他normal工作释放后取得exclusive，不能在normal里升级锁。实际合成验证覆盖MomentStore产生的历史作者与正文图、其他卡共享图片、无引用人物图/文档、真实Core删除/覆盖，以及持有normal工作时已提交删除等待清理、损坏authority时Management的已提交警告。无真实根/provider/本机JVM/新包或公开发布。
