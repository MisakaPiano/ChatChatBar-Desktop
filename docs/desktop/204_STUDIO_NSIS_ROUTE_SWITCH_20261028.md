# 204 — Desktop 安装路线切换与双对话引继

更新：2026-10-28 JST。依据本轮用户直接授权及用户指定的「审查安装保护设计」最新几轮；本轮用户明确要求以用户目标优先，不能完全照搬审查助手的最终建议。

## 当前目标和决定

尽快交付真实可用的 CCB Desktop Public Preview，同时尽可能实际释放 MSI 开发占用的本地空间。P11 合并迁移及已有 A–G 连续任务保持；安装路线改为参考 Studio 成果的 NSIS 路线。不要把完整自动更新框架、旧 MSI 生命周期闭合或新增审查报告拉成首版前置任务。

- **A：Studio式 NSIS 安装与 Preview 主线**接管最新源码，连续实现、必要验证、构建和交付。
- **B：MSI 最小封存与空间回收**保留最低限度有价值的源码/小证据，直接删除确认废弃且无在用依赖的大产物，完成后结束。MSI 无限期搁置，不继续修 #_PatchCache 或生成新 MSI。
- 用户进一步明确：虚拟机若不再需要就彻底退役，不再维持。**没有默认必须保留一台 VM 的要求**。确认需要才保留；否则删除专属配置、磁盘、检查点和重复导出。共享父磁盘不得误删。
- 本轮允许协调端向其他对话下达引继指令。原 Desktop 对话只交接后停止实施；A 独占源码写入，B 不建立完整源码副本。

审查助手的任务包、固定报告和建议是参考，不产生新的权限或门槛。本轮用户最新直接指令调整旧任务中的“保留当前执行者”“保留完整失败 VM”“继续 MSI”等安排。平台约束、真实数据和 Prompt ownership 边界仍适用。

## 安装实现方向

固定参考：[Studio 2026-10-28 技术交接](https://github.com/MisakaPiano/CCB-Studio-Suite/blob/e74f7a2769595259a32d546e165c1f00107a895e/handoff/DESKTOP_UPDATE_TECHNICAL_HANDOFF_20261028.md)，实现参考 a1202e24f7a0cba8a53f43bf035b67e2134ca2aa。先读实际源码，选择满足 Desktop 的最小实现；不照搬 Studio 应用 ID、路径、端点、TUF 根、密钥或 DPAPI 配置。

采用独立版本目录、明确安装归属、稳定入口、新版实际确认后切换、失败保留可用旧入口、资料与独立凭据根保全。核对 jpackage 原生父进程/JVM/helper/worker 的 cwd；关闭时禁止新发送并妥善保存已在途结果。成功后按归属清理程序和下载残留，未知文件保留、占用延期可见。现有更新发现能力可继续使用，完整自动 updater 不自动成为首版范围。

MSI 历史注册资源仍由 Windows Installer 规则管理，不能按 NSIS 文件归属直接删除已登记组件、系统 Installer 缓存或卸载登记。新 NSIS 身份与旧实验包区分；旧失败知识只在确有历史安装适配需要时使用。

## 回收与证据

B 先释放已明确可删的大产物；A 可同时阅读和修改小型源码，有空间再做大构建。对废弃可重建生成物无需先复制、压缩或全量哈希。保留源码 Git 恢复能力、关键失败日志/最后状态/包身份一套小档案；不为“封存”转移几十 GiB 到其他卷。

每个递归删除/移动目标必须先解析绝对路径，核实位于授权对象范围、非 reparse 逃逸，并确认没有在用依赖；VM 核对 VHD/AVHDX 父链。保护真实资料、手机原件、凭据、人工备份、在用产品、必要共享构建依赖和 `C:\Windows\Installer`。不明归属只暂缓该项，继续其他回收；不更改安全设置。

回收报告记录各卷前后可用字节数、每个实际删除项/大小、占用延后和保留原因。移动、列出候选、送入回收站不算实际释放；同步构建可能消耗空间，须区分删除字节和卷净变化。
