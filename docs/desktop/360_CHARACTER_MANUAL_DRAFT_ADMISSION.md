# 手动编辑资源与维护受理

角色编辑器是app-owned；Shell在整备份busy时切Data不等于原文件选择回调已失效。chooseAvatar等先canMutate、阻塞picker、返回stageResource；crop和文本stage也没有data admission。R102用实际AppContainer/Editor入口和持有picker，在另一独立Job取得exclusive后才释放picker，检查不能跨维护写入与赋值；该实际反例仍待原件，不称已运行失败。不是直接调用资源utility后推断race或数据丢失。

AppContainer现在注入短同步normal lease，只包返回后的stage+赋值；不包用户等待picker。维护pending/active或root已关闭时拒绝文件IO并保留原草稿，以现有资源错误提示稍后重试；正常阶段仍使用原stage/decoder和编辑逻辑。生成图片apply保留它现有外层normal，而非借这个同步入口。

persistDraft/cleanObsoleteDraft先取得normal再取draftMutex；已确认draft删除和对应session资源清理共用normal。失败后重试的session资源删除也单独持normal；旧图片全引用exclusive cleaner仍在保存normal释放后调用，不重新引入normal→exclusive升级。只给短同步IO增加登记，不在UI上等待维护锁，不改变模型Prompt、正式卡保存/恢复marker/用户选择。

必要定向覆盖：实际返回picker、crop与文本五入口的拒绝与维护后重试；真实已落草稿discard等待维护、文件保持到受理；同步工作阻止exclusive提前进入及pending/exclusive/closed拒绝；原实际卡保存/后提交清理四方法仅受影响回归。待原件，不提前PASS。其他EditorDraftAssetService调用方仍待逐项核对，不能借本次字符卡入口关闭整份上游差异；新发现catalog维护写入和冷安装缺口另行处理。
