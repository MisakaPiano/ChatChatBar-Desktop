- 整应用备份导出、受支持对话存档导入/导出、目录选择，以及手动检查 Desktop 更新和打开可信发行页。不会自动下载、安装或重启。

## 使用、备份与失败处理

1. 首次使用先在“数据”页确认当前资料目录。不要把资料、备份或凭据放进程序安装目录。
2. 手机迁移前保留原始导出。选择正确密码，核对冲突和凭据来源，再选择新位置并确认合并；不要把单独加载手机内容当作保留电脑数据的合并。
3. 成功后正常退出，再打开并检查双方独有会话、消息版本、图片和录音。旧资料目录和旧凭据保留。不要因为新目录能打开就立即删除旧目录。
4. 更换资料目录时，已绑定凭据或含图片/录音的目录使用受控重新绑定与媒体路径重映射。历史快照和旧恢复现场留在原目录，界面会说明；它们没有搬到新目录。
5. 升级前导出备份并正常退出。资料目录、bootstrap 和外部受保护凭据要保留；单独保存程序文件不等于保存全部资料。普通导出不含密钥，需要自行保留可重新配置的凭据。
6. 检查、准备或取消失败时保留原档案、原资料目录及失败现场。不要清空目录、删除锁文件、手工改版本 ID 或用旧程序直接打开新格式来排障。无法确认安全关闭时保留提示窗口并使用“重试安全关闭”。
7. 向开发者反馈时，可在“版本与更新”复制基本诊断并附操作步骤。该入口只输出固定版本/系统类别/更新状态，不收集聊天、资料路径、模型配置或凭据。不要公开上传原始备份、API Key、密码或完整私有日志。

## 兼容范围和已知限制

- 正式验证上游基线仍是 ChatBar 1.4.1 `5e76a9cb841736bbbf3499a2e35e5789af4c5ca8`。对选定官方 1.4.5–1.4.7 的备份格式作有界适配，不等于同步或验证了这些版本的全部功能。
- 实际 Android code86/v2 来源已在用户授权的隔离 Windows 副本执行严格认证、合并、重开、离线续聊和 Desktop 再导出/再发布。原 Android APK 的产生身份未独立认证；物理 Android 往返尚未完成。不能将 Desktop 专有保全域宣称为 Android 可恢复。
- 对话便携存档仍有 256 MiB 上限。已观察到大旧会话的恢复前安全存档超限；此时拒绝恢复，不跳过安全存档或删除旧会话。全应用流式路径目前同时限制源文件 4 GiB、展开总量 4 GiB、单文件 256 MiB、结构化内容合计 64 MiB，并另有单 JSON 和文件数量限制；压缩包小于 4 GiB 不代表展开后一定可接收。受控资料目录迁移复用这组全备限制，不承诺任意目录或任意容量均可搬移。
- 文件损坏、未知结构、缺失资源、源资料在预览后变化或超限会拒绝提交。不是所有历史/未来格式都已支持。
- 当前 Windows 账户的真实保护往返已测；跨 Windows 账户、断电、主机重启、旧二进制防写和全局消费者闭合没有由这些结果证明。程序回滚不等于资料回滚。
- P12–P17 的后续 AI 编辑、完整 Moments/Community、完整自动更新/系统集成和广泛 hardening 仍按实际功能状态说明；Preview 不代表 1.0 parity。既有基础功能验收与新增迁移、安装验收分开。
