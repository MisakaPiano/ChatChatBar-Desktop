## 链路 1：日常聊天、菜单和语音（用户核心 UI 优先）

打开“统一验收 A · 对话、语音、资料与记忆”，完成一次正常的宽窗/窄窗聊天操作：

- User 工具栏在右侧，仅复制/编辑；助手右键与 `…` 菜单一致，首行两操作等宽居中，窄窗不越界。
- 左生成状态、中固定播放器、右音色选择同一行，不重叠；角色名称优先完整、宽度不足才省略。Alice 配有合成音色，Bob 是第二角色，当前不配置独立音色，不能据此报告 Bob 音色丢失的产品缺陷。
- 从已有长录音播放：同一条再次点击暂停、继续原位恢复；停止/关闭、切会话按预期排水。录音条只保留紧凑内容，`…` 和右键使用同一浮窗。
- 在离线假服务已就绪时发送一条合成消息，核对 streaming、取消、最终显示以及复制/编辑链路。fake 回复只用于 UI 交互，不作为真实模型质量或真实 provider PASS。

Codex 同步记录 fake 请求数和所属进程，不让用户逐个复测已可靠覆盖的锁顺序、alias、失败注入和 lease 边界。Fish 新 TTS/真实语音库、真实生图和真实模型请求不属于本轮离线材料的完成声明；如要纳入本次集中验收，应先明确对应服务授权和请求预算。

## 链路 2：选择聊天内容并导出

用 A 会话的 User 图片、分段助手回复及 B 会话的长文本，连续完成“选择 → 独立预览 → 导出 → 返回聊天”：

- User 上下文和完整回复分组；展开/折叠及批量选择直观，录音不进入选择或 PNG。
- **预览是选择窗口之外的独立窗口**；适应宽度、100%、滚动和缩放可用，关闭预览/工作区后主窗口仍可继续聊天。
- 保存一张有图片和多条消息的 PNG 到本轮 `exports/png`，用 Windows 图片查看器核对。长图已具备材料，只在观察到长图特有问题时追加，不强迫重复普通已证实边界。

不重复分成四轮单独的 Close/Esc/X 测试；在这条正常使用链路中集中观察窗口归属，Codex 核对没有意外 Main CLOSE_REQUESTED。

## 链路 3：资料、记忆、存档和会话生命周期

在同一会话查看合成资料、RAG 状态和记忆/HEAD，然后完成“建存档 → 复制会话 → 在副本编辑 → 恢复 → 删除一份不要的存档”：

- 角色、图片、已有录音、草稿、版本、资料与当前记忆显示合理；复制得到独立会话，源会话保持不变。
- 存档入口、范围、进度、恢复前确认及删除确认可理解；删除后列表刷新，其他存档和当前媒体仍可用。
- 导出 `.cbsave` 到本轮目录，必要时导入一个副本核对可继续使用。
