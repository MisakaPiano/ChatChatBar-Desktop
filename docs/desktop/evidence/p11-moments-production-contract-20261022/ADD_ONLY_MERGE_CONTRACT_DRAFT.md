# NON_DESTRUCTIVE_ADD_ONLY 严格合并合同

2026-10-22。DRAFT，不设置生产默认、不改UI。依据 [审计](UPSTREAM_145_146_147_IMPACT_AUDIT.md) O07–14和D04–14。正式替换恢复与严格合并导入必须是不同产品操作。

## 官方ADD_COPIES审计

| 对象 | 固定1.4.6/7源码行为（SOURCE_PROVEN_ONLY） | 严格合同所需变化 |
|---|---|---|
| 主要实体 | 新ID/副本名称、图重绑定 | 可借鉴，但不能只改文件名 |
| AppSettings/默认模型/世界书等 | 所选字段覆盖，legacy无scope按全选；部分read-seen标记、Moments确认标记更新 | 保留目标所有现有设置；源全局配置不能直接落为目标单例 |
| Preferences/秘密 | 未选通过retainedPreferences保留；选中值可替换/null可清空 | 保留目标SecretStore和偏好bytes；任何迁移秘密另批C2 |
| 模型及alias | 新映射主要ID；同namespace/id alias归一化取first | 同ID不同端点/apiKey/modelName不能丢一份；全字段冲突拒绝/预览 |
| 当前会话/草稿 | 导入会话新ID、草稿跟随；不等于全局当前选择一定不变 | 当前打开会话、输入草稿、read位置、UI选择均保持 |
| Memory/source-turn | 重映射父子/coverage证明，source-turn保留新session内身份 | 检查原历史完全不变和新历史完整；不能拿当前快照替代历史 |
| RAG/媒体 | 克隆引用和搬运资源，新目录；派生对象随映射 | 新所有权与目标旧GC隔离；embedding配置/索引不能串到旧对象 |
| Moments/未来Task | 新ID不阻止被scheduler扫描或新建未来Task | 仅封存，遵循C-A；来源ID改变不能当禁止执行机制 |
| SaveSlot | 新slot/package与包内引用重写 | 目标列表旧条目/旧包不改；新增包和媒体分别证明 |
| pending_deletions | incoming不导入；本地针对恢复对象的条目可能移除 | 不改旧删除队列，新对象不复用可命中ID |
| migration/version/preset marker | 可merge最大seen版本、单例和全局值 | 不覆盖旧标记；不能因此误跳过目标未来迁移 |
| Studio/其他单例 | 选中scope可移除/替换既有家族；tag资源冲突亦有特殊规则 | 单例无新增空间须冲突或拒绝，不能隐式更新 |

以上为源码审计，不宣称已经在新版运行复现缺陷。官方模式有自身产品语义；问题是它不等价于用户要求的严格目标不变。

## 两个必须同时满足的承诺

**目标保全：** 成功后，既有目标记录、全局设置、偏好、SecretStore、草稿、Memory、RAG所有权、SaveSlot包、删除与迁移标记的内容/身份不变；保留现有根和恢复证据。新增列表条目使集合变大可以是预期，但已有条目不能被重排改名重写。时间戳/格式化变化也不能偷偷免检。

**来源完整：** 用户选定范围的每个实体、字段、版本、资源和依赖都有新增/精确等同跳过/明确拒绝状态；拒绝对象不能被忽略后仍报全量成功。未能导入的单例、未知字段和未来资源引用必须在确认前呈现。默认整次拒绝无法完整映射的计划，不能默认部分成功。

全局派生索引若必须重建会改变目标文件，应先证明其仅为可重建缓存并批准精确排除清单；首版推荐新对象独立索引命名空间、读取时聚合，不把所有SQLite文件都排除字节比较。正式不可重建内容仍完全受保护。

## 身份与冲突规划

1. 在隔离输入中完整检查类型、秘密、资源和图；记录目标root generation和现有域hash。来源未知字段先保留raw，无法解释关系则拒绝。
2. 为每个需要新增的顶层/内嵌对象分配稳定计划ID，按 `(sourceDigest,type,oldId,owner)` 生成映射。同包重复身份拒绝；不能全局字符串替换ID，以免误改正文、Prompt或不同命名空间。
3. 重绑定card/session/message/version、child character、document/world entry、RAG source、voice anchor、Memory节点及proof、SaveSlot manifest/package/嵌套实体。会话内source-turn和消息版本不得与其他会话混同。
4. 模型配置复制到新身份但不自动带凭据；目标已存在同ID/端点都不赋予绑定旧秘密的权限。配置无凭据时为不可运行待配置状态；若当前实现不能保证阻止隐式fallback/秘密绑定，则拒绝，不能偷用目标账户。
5. 全局AppSettings、默认卡/世界书、单例、迁移标记不能“新增第二个同名单例”。可以在来源保全域保留且标明未迁入运行状态，但这需用户接受有限子集；要求全量时整次拒绝。
6. 完全相同跳过须全字段、资源、关系及语义上下文一致，不用名称、ID或忽略updatedAt的内容指纹当证明。只读媒体共享须SHA+长度一致、独立持有计数、禁止写穿；首版独立复制。

Prompt自然语言、历史聊天正文不变；系统仅改明确协议ID字段与必要派生proof。不得重生成Memory或AI修复来弥补不懂的历史。无法重算正确proof就拒绝该计划。

## 事务与结果

预览必须列出新增/副本/精确跳过/冲突/拒绝/未运行封存，以及凭据不迁移类别。计划密封后取得coordinator独占及root lock，再校验目标未变；任何目标写入使计划失效，不自动重新匹配覆盖。所有新增对象与资源拥有权作为同一逻辑事务提交，失败回到原根且无半套可见对象；即使先写了内容寻址blob也只属暂存，不能被业务扫描。

提交后比较目标旧域清单并验证新增图和资源；只有两项都成立才成功。原包不改；结果manifest保存source/target generation、映射、计数、原因码、schema/工具版本和SHA，不记录正文/Prompt/凭据。禁止默认切换当前会话、运行Task、网络索引构建或发起生成。

## 测试与授权

合成测试覆盖所有上表对象、目标已存在密钥但源端点不同、大小写/Unicode同名、重复alias异配置、嵌套ID冲突、source-turn重复但不同会话、voice版本归属、Memory证明、已有草稿/SaveSlot、同图跨拥有者、删旧卡后新媒体仍存、未知类型、单例冲突和每阶段崩溃/磁盘满。成功断言目标全保护清单不变且来源选择范围完整；负例断言零业务新增、原档/目标/历史保留。

运行官方ADD_COPIES与拟议严格模式用同一夹具对照差异，但不得修改官方行为来迁就测试。GUI、Android版本验证和用户真实数据均需另批，本轮没有执行。新增产品操作、秘密关联防护、单例有限子集及持久事务均列入 [决策](DECISIONS_REQUIRED.md)。
