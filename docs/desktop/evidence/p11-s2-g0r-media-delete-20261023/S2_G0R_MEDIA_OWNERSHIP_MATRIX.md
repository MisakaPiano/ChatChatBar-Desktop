## Evidence mapping

`raw/final/probe-records/<scenario>-<stage>.json` contains complete inventories of that synthetic parent, including its source root, copy namespace, export destination, inspection staging and any backup workspace. The twelve scenario labels are `live-owner`, `two-owners`, `external-only`, `isolated-copy`, `unlink-primitive`, `corrupt-authority`, `repeated-cleanup`, `cancel-cleanup`, `partial-unlink`, `backup-registered`, `backup-unknown`, `backup-hidden`.

Each has `created`, operation-specific before/after stages, `released-final`, an outcome and cleanup receipt. Six-byte fixture files and the two actual resulting `.cbbackup` archives are preserved. `raw/evidence-sha256.json` indexes source snapshots, fixtures, receipts, commands, logs and XML by original length/SHA. Initial execution is retained separately; it is not added to final counts.

## Adapter implications, not implementation permission

Future preservation needs an explicit owned-resource contract across **all** GC/unlink/queue consumers, a registered enumerable backup domain, and atomic publication/recovery. A physically separate copied file reduces shared-path deletion exposure but presently conflicts with full-backup admission if placed under an unknown top-level directory. Hiding it instead creates silent backup omission. Neither layout is a production solution.

At delivery, concurrent CURRENT157 confirms the principles of C-A, original JSON/independent copies, no automatic deletion, space fail-closed and no unsafe downgrade writes. Detailed schema/quotas/retention enforcement, old-binary protection and R07 source-archive secrecy remain open. S2 production, S3–S6, C1/C2, task activation, P11 acceptance, D-038 and Public Preview are not promoted by these observations.
