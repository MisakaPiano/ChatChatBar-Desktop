# Synthetic journal state machine — experiment, not deployable authority

Implementation isolated in tools/desktop/interop/lr5/src/SyntheticJournal.kt, injected only into test source set. No old production tests rerun or current main changes. Schema label LR5-SYNTHETIC-1 has bounded strict field count/keys/types/canonical form/checksum; profile/authority -> exact manifest -> retained old/new5-participant byte sets -> exact context/registry/source proof. Fixed participants: data, two fake keys, dummy voice bytes, dummy Moment bytes. No official serializer or runnable Task.

## Candidate protocol exercised

NEW_TEST_SANDBOX(OLD baseline) -> copies old/new snapshots + manifest with profile/root/native witness/account/endpoint/purpose/generation/declared consumer set -> BEFORE_INTENT -> atomic INTENT authority -> AFTER_INTENT -> KEY_FIRST or DATA_FIRST individual atomic participant replacements -> BEFORE_RECEIPT -> receipt + readback -> AFTER_RECEIPT -> context/evidence/full-set reverification -> BEFORE_PUBLICATION -> authority NEW/OLD referencing receipt -> AFTER_PUBLICATION -> BEFORE_REOPEN -> independent reads of authority/manifest/receipt/context/source/participants -> synthetic ALL_NEW/ALL_OLD.

The parent kills nothing to fake a crash: child Runtime.halt(71) is invoked at named stage after event flush. Cuts are before or after atomic moves, NOT during filesystem rename internals. Recovery is a new process, not the original actor's memory. A second recovery hard-exit is also planned. The cooperating lock order is profile -> OLD -> NEW inside one test sandbox; no production deadlock/fencing claim.

No authority + empty WAL + exact OLD is ALL_OLD/NO_IMPORT. No authority + any tentative evidence is BLOCKED (conservative retention, no automatic scratch deletion). INTENT + independently valid OLD/NEW snapshots/context and recognized OLD/NEW targets permits deterministic roll-forward; explicit rollback restores complete OLD only and keeps NEW evidence. Foreign target/context/source or missing participant blocks BEFORE recovery writes. Published NEW/OLD additionally requires exact completion receipt; missing or corrupt post-publication evidence cannot be reconstructed from apparent matching payload. Incomplete/corrupt pre-publication receipt handling is directly falsified by negative tests; consult actual RED/GREEN ledger, not this design intention.

`businessAuthorized=false` on every result. RESTART_REQUIRED after post-intent cancel prevents normal business; source, OLD keys and both snapshot generations remain. There is no actual active-root switch, trusted native protection, durable profile discovery, distributed CAS, transaction signing, application hydration or secret migration.

## Durability boundary

Every experimental write uses a CREATE_NEW temporary, complete buffer write and FileChannel.force(true); ATOMIC_MOVE is required, then exact readback. Parent-directory force is attempted and a fixed category logged if unsupported. Published files retain old/new evidence; failed/partial temporary files are retained. Hashes only detect accidental corruption under the synthetic threat model, not a malicious actor able to rewrite all evidence. Filesystem/controller cache, Windows reboot/power loss, unsupported volumes, removable disks and real old executables are NOT TESTED. Synthetic IO-fault/space injection is not a real full disk.

Final observed refinement: an existing malformed/conflicting pre-publication receipt is preserved and blocks BEFORE recovery mutations; a valid receipt also requires every claimed participant already uniform, so reverted recognized OLD cannot be hidden. Missing pre-publication receipt can be recreated only from valid INTENT plus exact OLD/NEW evidence; published receipt loss blocks. Unknown/partial WAL, target or alternate profile authority files refuse. Native directory IDs come from the unchanged Windows read-evidence helper because JDK fileKey was actually null. Final29 tests pass; detailed round/matrix attributions are separate.

The inactive target is seeded with synthetic OLD bytes solely to make mixtures observable. This one-shot generation1→2 experiment does not implement authenticated absence/tombstones, repeated production transactions, arbitrary provider/account mappings or actual fresh-root bootstrap. Native observations cover local directory object identity, not durable user/protector identity. Directory force returned unavailable in all recorded attempts (887 events in final retained fixture states); process halt recovery is verified, power-loss durability is not.
