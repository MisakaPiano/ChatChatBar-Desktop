# Explicit modern full-backup transport writer and strict input correction

New DesktopFullBackupWriter consumes only a frozen mapped credential-free file set. It writes explicit code86/v2 transport (Desktop producer label), authenticates/revalidates the exact output with bounded streaming validation, rechecks source hashes before no-overwrite publication, clears the password buffer and uses invocation-owned scratch. It has no SecretStore, root activation, Prepared or restore capability. The existing v1 encoder/decoder and restore admission remain separate. Selected wire compatibility does not update baseline1.4.1 or claim Android whole-app portability. Desktop-only domains remain Desktop-only. Service/UI export is not switched until modern merge/restore is ready.

DTO EncodeDefault.NEVER annotations now match the fixed official declarations for scope, sessionChoices, sessionDefaultChoice and retainedPreferences; other defaults remain encoded as official backupJson requires. Independent R1 wire DTOs and the pinned official fixture decryptor verify plain/password output; source bytes, output conflict/cancel, invalid model/preferences secrets, structured-size refusal and selected-empty media are tested. Known secrets are not exported; arbitrary user text is not asserted secret-free. Media/dependency/activation closure is separate from format validation.

**Preserved failures:** initial45 PASS used incomplete semantic coverage. Adding S0 acceptance exposed an invalid external retainedPreferences marker (47 tests/1 FAIL). Fixed official BackupArchive requires this marker empty in source archives; BackupMergeEngine computes nonempty local instructions only in target preparation, and BackupPreferenceTransfer applies them there. The writer now omits it; the old S0 rejection was kept unchanged. An independent negative then proved streaming Source had accepted a known nonempty marker (1 test/1 FAIL); Source now rejects it before preferences callback. Intermediate70/1 FAIL was an incorrect expected diagnostic stage: the ZIP reader intentionally sanitizes callback failures as ZIP_ENTRY_CALLBACK_OR_STREAM. Test oracle corrected without changing ZIP behavior.

Final actual run:6 suites/70 PASS/0 failures/errors/skips/exit0. Nine new writer tests, one new source refusal test. Historical rounds are not added to70. No real archive/keys, DPAPI, GUI, Android, Provider or user root in these tests. No large real-archive write/restore or platform restart claim. Full raw commands/exit/JUnit and pre-test changed-source snapshots are retained. Source snapshots may differ from Git blobs only through configured CRLF normalization.
