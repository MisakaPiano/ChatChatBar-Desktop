# Legacy unbound root media relocation

An independent synthetic root has a task-owned conventional credential store, valid image/MP3 bytes and an owned recording with an absolute path. Source graph validation passes before migration. The existing byte-copy route reports migration success, but the target VoiceAudioStore rejects the copied recording because its path still belongs to the original root. Actual RED: **1 suite / 1 failed test / exit 1** at DesktopVoiceAudioStore.verifyOwned.

The default directory-switch service now uses the already tested verified publisher when the source contains registered images/audio, as well as when it already has a native credential binding. A legacy source does not pretend to have a fresh-root fence; its existing effective known-key store remains read-only, and the newly prepared target gets its own protected namespace. Both source and target raw/transport checks remain exact. Ordinary byte-copy refusal for native bindings remains, and raw non-media directory handling is retained.

Final affected execution: **13 suites / 170 tests / 0 failures, errors or skips / exit 0**, with CCB_PREVIEW_NATIVE_DPAPI=1 explicitly set. This is one execution, not 168 plus a historical native run. The conventional-store counterexample now verifies target-root audio ownership and unchanged MP3 bytes, new protected values and unchanged old data/keys. Other cases retain external-change, protection-failure, cancel, final-writer, global-restart and truthful presentation checks; the real DPAPI case uses invented values and task-owned paths only.

No user archive, ordinary user credential directory, real key or Provider was used. No actual DPAPI/context blobs or runtime test roots are included here. The 1006 package predates these changes; a new package is required. Historical snapshots/recovery workspaces remain at the retained old directory with the explicit UI notice described in protected-root-relocation. Whole-backup limits and unknown-data refusals remain; this is not arbitrary raw-folder migration or complete Android portability.
