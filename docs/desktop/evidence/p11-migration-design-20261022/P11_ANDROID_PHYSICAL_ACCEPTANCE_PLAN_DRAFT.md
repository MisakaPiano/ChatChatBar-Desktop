独立用户的应用数据隔离不等于安装隔离：同包名 APK 的代码/签名可能影响其他用户，不能在这类环境安装本地 debug 包来“避开”正式版。最保守可执行路径是专用无正式数据设备加已核验官方发行 APK；另一条路径是既有相同官方包代码、无需任何全局更新的独立用户，且隔离证据充分。发生 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 或版本冲突即停止，不能卸载、改签名或绕过降级保护。

## 4. 离线服务接入及新增授权边界

首选 USB ADB reverse：PC fake 仅监听 `127.0.0.1:<PC_PORT>`，仅提供 `/v1/models`、`/v1/chat/completions` 所需离线固定响应；不转发、不代理、不解析真实 Provider 请求。选择未占用端口并记录进程所有者。手机的 `127.0.0.1:<PHONE_PORT>` 必须通过已批准的 reverse 才可访问 PC fake。

执行授权必须包含：指定 `<SERIAL>`、ADB server 端口 `<ADB_SERVER_PORT>`、`tcp:<PHONE_PORT> → tcp:<PC_PORT>` 的新增和删除权限、测试用户 ID、fake 进程和允许路由、请求元数据记录范围。下列为**执行模板，本轮未执行**：

```text
adb -P <ADB_SERVER_PORT> -s <SERIAL> reverse --list
adb -P <ADB_SERVER_PORT> -s <SERIAL> reverse tcp:<PHONE_PORT> tcp:<PC_PORT>
adb -P <ADB_SERVER_PORT> -s <SERIAL> reverse --remove tcp:<PHONE_PORT>
```

reverse 映射是设备级操作，不能当成按 Android 用户隔离的网络权限。已有同端口映射不得覆盖；不得 `--remove-all` 或停止共享 ADB server。未获 reverse 授权则不建立连接。LAN 监听或手机本地服务均是另一个方案，需要另批网络暴露/安装权限，不能自动将 fake 改为 `0.0.0.0`。

在官方设置中明确许可该 HTTP 本地端点，模型无 API Key。禁用测试环境自动 AI/图片/记忆维护及 Moments 调度，保留原导入快照；不得联系 Fish、NovelAI 或真实 LLM。运行前证明测试包非授权出口被隔离或有可验证的限制；若设备无法提供该保证，续聊阶段 BLOCKED。服务日志只存时间、路由、计数、状态，不存请求正文、Prompt 或 Authorization。发现其他出口尝试停止相关流程，保留安全诊断，不声称“未抓包所以没有外连”。

## 5. 一次集中执行顺序

现场每次引导最多 1–3 个连续动作，继续使用同一隔离环境，不拆成重复人工任务。

| 步骤 | 操作 | 预期与证据 |
|---|---|---|
| 0 准入 | 填写第 2–4 节全部身份、隔离、授权和网络记录 | 未通过不启动；保留未执行原因 |
| 1 Android 导入 | 用户在官方应用选择 `desktop.cbsave`，打开合成目标会话 | 无覆盖正式数据；导入成功，4 条原消息可访问 |
| 2 版本与媒体 | 查看备选版本、合成图片、播放一条已持久化录音；保留/恢复原当前版本选择 | 图片/声音可用，版本和语音绑定正确；不触发 TTS 或生图 |
| 3 Android 续聊与回传 | 通过批准的 fake 发送一条唯一合成请求，等待一条固定回复；创建新存档，明确选原图与包含录音，导出为新文件 | 应为 6 条消息；源 4 条不变。记录实际导出选择，默认不含图片不可误当丢失 |
| 4 回传核验 | 用户通过已授权文件选择/定向传输回传档案；PC 对导出物离线对比 | 来源、长度、SHA，版本/图/音/RAG/Memory 图对照；禁止拉取整个应用私有根 |
| 5 Desktop 接收 | 在新隔离根启动经过身份核验的候选（须新 Windows GUI 授权），正式导入并恢复回传档案 | 原回传文件不变，媒体所有权映射正确，恢复前快照及 journal 保留 |
| 6 Desktop 续聊 | 向批准的 loopback fake 再续聊一轮，创建并导出新存档 | 若双方各一轮，8 条消息；核验新增消息与原消息关系；不重做一般功能测试 |
| 7 收尾 | 用户确认结束后正常关闭双方测试应用，撤销仅本次 reverse，正常停止自有 fake | 按第 8 节核对状态；不自动再次启动验证 |

图/音选择、取消和失败时保留原文件即可，不强制反复测试已通过的普通边界。若需要在物理设备制造中断/损坏恢复场景，须作为额外明确授权，不能借此强杀正式应用。

## 6. 数据对照方法和不能扩大声称的范围

对照的是用户主动导出的**合成归档**，不是设备私有文件。复用 D17 的规范化规则，但既有脚本是自动化 fixture 目录约定，不能声称直接适用于所有 UI 导出。执行前在隔离副本上适配路径/报告名称，禁止覆盖历史 proof；若 UI 导出身份重建不同于 fixture，先追踪正式代码、列出双射关系，不扩大忽略字段列表以获得 PASS。

| 项目 | 对照方式 | 范围限制 |
|---|---|---|
| 消息 | 原消息 ID/次序、正文、role、source-turn、备选内容和 version IDs、当前版本；目标 session 重绑定另表记录 | 新续聊消息单列；时间变化须有正式规则依据 |
| 图片 | 解包资源按引用逐一匹配原始 SHA-256/长度；generatedImageMetadata 路径关联也匹配 | 用原图策略，不能用缩略图肉眼相似代替字节一致 |
| 录音 | MP3 SHA/长度，messageId、messageVersionId、片段次序与文本/音色元数据；record/anchor ID 重建有对应表 | 播放成功不能代替绑定检查；不要求重新生成语音 |
| RAG | 原 1 块内容、向量、消息/source-turn 引用；允许正式目标 ID 重建且保持图一致 | 不证明全局文档库、数据库索引、检索模型迁移 |
| 当前 Memory | HEAD 和 LEGACY_REFERENCE 内容、节点/子节点/根引用；ID 双射；timeline 对回传消息、memoryWasEnabled 对会话设置单独校验 | 嵌套 Episode/Arc/Era、修订历史、运行任务仍 NOT TESTED；不能称全量记忆覆盖 |
| 草稿 | `.cbsave` 没有输入草稿字段；记录目标草稿行为但不要求源草稿迁移 | `chat_drafts` 属于另一项全应用合同 |
| 外部定义 | 合成角色、模型及额外世界书/格式卡引用逐项确认 | 单会话档案不能替代全应用库迁移 |

## 7. 失败与退出

任何步骤失败保存：输入原档案、首次失败回传、长度/hash、应用身份、精确步骤、阶段类别、仅合成截图。不得删除录音、删除字段、重写原档案或清空数据来消除错误。测试应用原数据保持，PC 接收根的恢复快照/journal 不清扫。

需要日志时只按新增授权收集目标测试包、限定时间段的安全日志；不得全设备 logcat、bugreport、Token dump 或读取正式角色。发现日志包含秘密或真实数据立即停止收集，隔离已有材料，不纳入 Git/支持附件，不在聊天复述。可复现错误用错误类别代替正文。

隔离失效、签名冲突、未知进程/根锁、非授权网络、主程序意外退出：停止受影响步骤，不强杀、不自动重启。未完成项目记 NOT TESTED；证据不能确认则 INCONCLUSIVE。再次启动、扩大取证或修复手机环境需新增明确授权。
