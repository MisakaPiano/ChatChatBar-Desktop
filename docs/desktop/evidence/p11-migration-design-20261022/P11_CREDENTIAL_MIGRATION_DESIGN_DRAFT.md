# P11 外来凭据迁移：两份独立安全方案

**DRAFT / NOT IMPLEMENTED / 非凭据读取或写入授权**，2026-10-22 JST。

Desktop 控制提交 `8c378e8cf487f6dbcb0df3f3a6f1408028185091`；官方目标 1.4.5 `1198a13cf3008de1358b8a69aa5e40b64797c8d9`；正式 baseline 仍为 1.4.1 `5e76a9cb841736bbbf3499a2e35e5789af4c5ca8`。**本轮及批准实施以前，外来非空凭据继续整包拒绝。** 不读真实 Token，不写 SecretStore，不改变备份恢复行为。

## 1. 源码事实与共同边界

精确来源见 [SOURCE_AUDIT](SOURCE_AUDIT.md) O09–O20、D01–D09、D12/D13。

- O13/O14：`BackupPreferences` 可携带 `novelAiToken`、`fishAudioKey`、`communitySession`；brushSize/brushType 是非秘密偏好。capture 会通过 Android CredentialStore 解密读取，restore 会替换；NovelAI/Fish 的 null restore 会清空现有值，不能照搬到 Desktop 的“跳过”语义。
- O18–O20：communitySession 含 accessToken、refreshToken 及账户信息；ModelConfig/EmbeddingConfig 有 apiKey，AppSettings 有 siliconFlowApiKey。仅排除 preferences 的三个字段不能算排除全部已知凭据。
- O10：现有 `configureExport(password)` / export 流程没有凭据排除选项，capture 直接进入 archive。**所审计官方 1.4.5 正式流程没有源端“无凭据导出”开关**。不能建议用户先清空正式凭据再备份。
- O17：密码为可选；加密模式使用 PBKDF2-HMAC-SHA256（600,000 次）派生包裹密钥，AES-GCM 包裹 Tink streaming keyset，内容使用 AES256_GCM_HKDF_1MB。密码解密成功只证明容器可读，不授权安装凭据；明文容器没有密码加密带来的真实性保证。
- O09：官方 extract 会写临时 `payload.zip` 及 preferences；不能直接借用该路径处理 Desktop 秘密而宣称不落明文。D03 的当前拒绝检查先于明文 staging，必须保留这一边界。
- D06–D09：Desktop 当前只有逐 key load/save/delete；Windows DPAPI 保护位于 LOCALAPPDATA 下、独立于选定数据根。单文件替换不是多凭据和数据根的原子事务；API 中 String 无法保证内存可完全擦除；当前没有 communitySession 的目标 key/账户运行合同。

共同禁止：记录凭据值、前后缀、可猜测 hash/指纹，写普通 JSON 或诊断包，自动访问 Provider 验证 Token，静默覆盖/删除目标秘密，因一个类别不支持而跳过它并报告完整恢复。原来源档案始终不变；若本来是明文含密包，不能声称本方案消除了它已有的暴露风险，也不能自动删除或重写原包。

## 2. 已知类别及拟议动作

| 来源类别 | 精确字段/来源 | C1 无凭据迁移 | C2 加密迁移候选 |
|---|---|---|---|
| NovelAI | preferences.novelAiToken | 主动批准后排除 | NovelAiToken，指定目标 Windows 用户及服务账户语义 |
| Fish Audio | preferences.fishAudioKey | 主动批准后排除 | FishAudioApiKey，指定账户 |
| 模型 API Key | model_configs[*].apiKey | 排除每项密钥，保留非秘密模型配置 | ModelApiKey(modelId)；先证明逻辑模型 ID/端点/目标账户一致 |
| Embedding API Key | embedding_configs / embedding_model_config 的 apiKey | 分类列明旧/单例配置，排除密钥 | LegacyEmbeddingApiKey(id) / SingletonEmbeddingApiKey；禁止猜测二者等价 |
| SiliconFlow | app_settings.siliconFlowApiKey | 排除 | SiliconFlowApiKey |
| 社区会话 | preferences.communitySession 的 access/refresh tokens、会话及账户状态 | 整个社区登录会话不迁移，明确同时不迁移登录状态及内嵌账户信息 | 当前无 Desktop 目标合同，首版建议拒绝；需独立账户/刷新/撤销/过期策略后才可能支持 |
| 未知秘密类别/未来字段 | 未审计 store/字段、扩展中无法判定的内容 | 拒绝，不用字段名猜测清洗 | 拒绝，不把未知 payload 包装进 DPAPI 当作支持 |

界面可显示类别、数量和安全的目标标识；不得显示值或提供“显示所有秘密”便捷入口。模型名称、URL 等也是不可信输入，展示须限制且日志只记内部事务标识。对 metadata/extensions 中任意用户文本，不能保证没有用户手填秘密；不将已知字段清洗宣传为任意文本秘密检测器。未审计结构影响保证时拒绝该迁移配置，不自动重写用户内容。

## C1：用户明确授权的无凭据迁移

### C1.1 产品承诺和授权

这是“**恢复应用数据，明确排除所列凭据及登录状态**”，不是原样全量无损恢复。C1 的批准独立于 C2，不授权读取目标秘密值或写 DPAPI。

拟议交互：选择原档案 → 有界认证/检查 → 显示实际检测类别和数量及全部影响 → 用户主动选择“排除这些凭据继续” → 完整数据预检 → 最终替换数据确认。默认维持拒绝，不预勾选、不把密码输入当作同意、不用通用恢复按钮隐含授权。按原档案 hash、检测策略版本和具体排除清单绑定批准；输入/目标改变则使批准失效。

### C1.2 数据流程

1. 输入只读、先固定副本/hash/长度；密码与解密内容限内存。完整认证/ZIP/inventory 验证后才能认为类别清单可信；初步显示应标为未完成。
2. 流式识别已批准类别；未经选择的非空类别、未知字段或 Moments 阻断继续整包拒绝。不能先将含秘密实体写入普通 staging 再删除密钥。
3. 用户主动批准后，第二遍验证源 hash 不变，只在明确允许字段生成无凭据派生数据。非秘密字段与资源保持，并有字段级差异白名单；生成新的校验清单。原包和原字段 bytes 留在用户来源中，不写进普通恢复证据。
4. 所有派生数据经正式数据/引用/资源验证才允许进入既有 data-root 恢复事务；失败时不发布任何 live 数据。清理仅本次拥有的派生暂存；原包与旧数据保留。
5. 显示独立结果：排除哪些类别、数量，数据恢复是否完成，哪些模型需要用户手动配置。未恢复的凭据不标为成功迁移。

### C1.3 现有 SecretStore 与逻辑 ID 冲突

“不写 SecretStore”并不自动等于不会误用旧凭据：若新模型沿用旧 modelId 但指向新端点，恢复后可能绑定旧密钥。必须在提交前识别这种语义碰撞；没有获批的绑定保护合同则拒绝恢复。不能通过自动删除旧 secret 解决，也不能启动网络请求验证绑定。

推荐后续设计明确的迁移后凭据绑定确认/禁用状态，或对冲突全部拒绝。前者需要新持久化/运行许可合同，超出现有单纯数据恢复；首版推荐拒绝冲突，保持旧 SecretStore 和所有旧绑定不受影响。全局 NovelAI/Fish/SiliconFlow 也必须向用户说明保留的是目标已有配置，不能在迁移后自动发起任务。

### C1.4 保证与限制

可以在新增批准和验证后达到：输入原包完整、不静默漏项、目标秘密不改变、批准的无凭据数据事务完整。不能达到秘密原样迁移或完整全应用保真；即使用户同意排除，也只能作为**有限兼容**路径。D-038 允许明确秘密策略，但 C1 不能自动解除其真实全应用迁移 Gate，需要 Project 与用户明确接受这个受限产品范围，不能在报告中自行修改 D-038。

## C2：用户逐项授权的加密凭据迁移

### C2.1 准入与选择

推荐首版只接受正确认证的加密官方容器。对明文含密原包继续拒绝；如未来要支持，必须另批本地输入风险及防明文派生措施。容器加密不证明档案来自官方作者，仍需输入来源及结构验证。

逐项列明类别、关联模型逻辑 ID、目标服务/端点、用户指定的服务账户、目标 Windows 用户和目标 key。源档案没有可靠服务账户信息时记 UNKNOWN，由用户确认或停止，不能从 Token 推断身份/联网查询。绑定选择与档案 hash、数据根/秘密根身份、现有目标版本共同封存为授权记录，不保存秘密值。

冲突选择必须显式：取消整次迁移；或保留目标值并将该项列为“经用户批准不迁移”（结果不再称完整凭据迁移）；或覆盖该特定 key 并保留可回滚的目标密文。默认取消，不提供“冲突自动覆盖”。不得把数据恢复成功、秘密失败拆成总体成功。

### C2.2 密钥材料和临时数据

- 解密以有界流完成；认证完成前不得发布；不产出普通 plaintext payload.zip/preferences/entity dump。重新使用官方 envelope 协议，不能声称沿用官方落盘 extract 就满足此项。
- 目标 secrets 立即保护为当前 Windows 用户 DPAPI 密文，保存在受限专用事务区；不得放入 app-data 普通 backups。旧秘密备份也只保存其保护后的 envelope，记录存在/不存在和安全版本标识。
- 密码 char[]、派生 key、解密 buffer、包装 keyset 在最短生命周期内清零；避免 immutable String 拷贝，若既有 API 必须 String，明确 JVM 无法保证彻底擦除，需后续接口审查。崩溃 dump、分页文件、同用户恶意进程不在单纯 DPAPI 可消除的风险内，不作绝对保证。
- 不把 plaintext、密码或密钥通过命令行、环境变量、剪贴板、普通 JSON、异常 cause、遥测/日志传递。原包可能含秘密，保留副本也不得进入 Git 或普通诊断包。
- 临时密文清理只操作可证明归属路径；磁盘安全擦除不是普通删除能保证的功能。密钥失效/用户改变时停止，不尝试绕过 DPAPI。

### C2.3 新的跨域恢复事务（尚不存在）

既有 Desktop journal 限于数据根，SecretStore 独立；两者不共享一个文件系统原子提交。必须新增受审计的协调事务，不能只是调用若干次 `save`。

拟议状态：`VALIDATED → CONSENT_BOUND → PREPARED → SCHEDULED → APPLYING_DATA_AND_SECRETS → VERIFIED → COMMITTED`；失败转 `ROLLBACK_REQUIRED → ROLLED_BACK`，证据异常转 `BLOCKED_RECOVERY`。

1. 获取数据根独占和秘密域互斥，停止后台网络/生成；检查与用户批准时相比目标 key 及逻辑绑定未变化。多根共享同一 Windows SecretStore，也必须参与同一互斥/冲突协议。
2. 写入数据旧/新快照及 DPAPI 旧/新密文，持久化完整意图、根身份、key 列表、预期版本及校验。授权标记最后写；未授权残留不得触发恢复。
3. 下一次明确授权启动时，在 repositories 和任何网络能力开放前恢复事务。记录每一步意图，替换 data 和 secrets 后逐项验证；所有项通过才发布统一 committed 标记并允许使用。
4. 任一秘密写入/解密/验证失败，阻止应用继续并回滚数据及所有已改秘密。不得只回滚秘密留下新数据，也不得用旧 Token 配合新端点继续运行。保留原始输入、快照和密文恢复证据。
5. 发生外部修改时不覆盖新值，进入 BLOCKED_RECOVERY；需用户决定恢复方向。重启恢复幂等，崩溃发生在 commit 标记前后都有明确证据判定，不靠“文件看起来存在”。
6. 仅在完成并核实保留策略后清理临时密文；旧秘密回滚副本保留期由用户批准。清理失败单独报告，不谎称秘密已销毁。提交之后的用户撤销是另一次有授权的恢复，不是删除日志即可撤销。

Windows DPAPI 用户范围保护可提高目标存储安全，但不解决跨机可移植密文、凭据过期、账户/端点错绑、跨根并发、明文源包或恢复事务一致性。社区会话在目标无功能/类型合同前仍是明确阻断，不能把其序列化 JSON 塞进未定义 key。

### C2.4 D-038 适配

若逐项授权、认证、无明文派生、目标保护、绑定检查、跨域回滚及真实迁移证据全部实现且审查通过，C2 **可能满足 D-038 凭据分支**。它不解决 Moments、未知字段、Desktop 专有类型，也不使完整 D-038 或 Preview Gate 自动 PASS。遇到不支持类别仍整包拒绝，或用户独立选择 C1 的有限方案；不能暗中降级。

测试必须使用唯一合成 canary；真实 Token 不进入测试或哈希清单。检查 secret 可恢复性需要独立批准的隔离秘密根/Windows 用户，不碰用户生产 SecretStore。
