## Moments：两种后续选择

1. 继续拒绝：保留整个原始档案，不提交任何 live root 改动。提示明确指出朋友圈数据尚不受支持。迁移者可继续使用 Android 原档案；不建议用户手工删除 ZIP 条目骗过检查。
2. 单独批准“不透明保留”：需要新的有版本数据合同。应保存原始字节、原路径、类型、schema/version、资源清单和哈希，并跟踪消息、角色、会话及图片引用；往返导出必须逐字节证明。Desktop 不解析执行任务、不调度 Moments、不宣称能编辑或显示这些数据。

第二种方案不能只增加两个 serializer。Moments 资源引用可能受路径映射、角色/会话删除和覆盖恢复影响。必须定义悬空引用、与本地同名实体冲突、未知资源、体积配额、未来升级接管、事务日志和 crash recovery 行为；无法证明的整包继续拒绝。存储目录/Entity/schema 变更须另获批准。当前不实施、不自动创建“附带 ZIP”绕开合同。

## 官方备份中的凭据

官方 1.4.5 可在 preferences 或实体中保存凭据。档案加密只保护传输/静态字节，不构成迁入 Windows SecretStore 的许可。

- 当前：检测到非空外来凭据立即整包拒绝，解析错误不回显值，原档案保留；Desktop 普通导出仍遵守既有凭据排除规则。
- 可评估的未来路径：专用加密凭据迁移功能，逐项展示类别与目标，不展示完整值；用户明确确认后才写入 SecretStore，凭据库已有值需独立冲突决策。数据恢复与秘密迁移的失败/回滚不能相互伪成功，所有日志与测试包不得包含真实 Token。
- 另一产品选择：由官方 Android 提供明确的“无凭据导出”。只有用户主动选择的导出合同可以排除秘密；Desktop 不能对收到的原始档案静默删字段后宣布完整导入成功。

本轮合成凭据仅用于拒绝测试，绝不把该路径推广到真实凭据。

## Desktop 专有类型与未知字段

官方 1.4.5 注册表不认识部分 Desktop 类型（包括 `retrieval_model_config`）。现有完整 Desktop 备份仍用于 Desktop 恢复；不能把两个实体的最小官方兼容档案称为全应用 Android 兼容。
未来“Android 可迁移子集导出”需要显式范围、缺失能力清单及用户选择，不能自动丢弃专有数据。未知字段维持提交前拒绝，不使用 `ignoreUnknownKeys` 放宽 Desktop 导入。

## 草稿及派生数据范围

官方 `.cbsave` 没有聊天输入草稿字段。草稿属于全应用 `chat_drafts` 域；存档不扩展私有字段来制造跨平台通过。
RAG 会话块、当前 Memory 快照与消息稳定身份需按正式 SaveSlot 合同验证；全局检索模型配置、引用文档库、运行中任务、索引数据库和 Memory 修订历史不能由单会话存档通过推定已迁移。
若要求单会话存档携带输入草稿，需要独立协议/产品决策，与当前兼容结论分开。
