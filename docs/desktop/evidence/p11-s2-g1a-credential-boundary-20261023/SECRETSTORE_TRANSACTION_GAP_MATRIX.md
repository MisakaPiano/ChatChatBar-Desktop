# P11-S2-G1A — SecretStore / restore transaction gap matrix

2026-10-23 JST. Test control `ed8f54236cd29b822f3a8875218b3ba7043eab5f`. Authority: CURRENT158–161. **Observation only.** All new runtime cases instantiate real `WindowsSecretStore` with explicit temporary paths and a reversible, NON-CRYPTOGRAPHIC Fake Protector. No DPAPI operation or real profile is used.

User policy158 is the desired product behavior: a valid user-selected official backup containing the user's own keys should support protected direct import with correct identity and consistent recovery. The current rejection below is an implementation gap, not the accepted final policy. No admission guard was removed.

## Required next design work, not authorized implementation

A future protected direct importer must freeze category/ID/provider/account mapping, independently protect old/new secret state, and bind data/secret participants to one durable commit/recovery intent. It must distinguish pre-publication failure from unknown post-publication outcomes, survive rollback failure/cancellation/restart, and keep source archives user-owned. Existing per-entity rollback and root ownership are useful building blocks; neither N saves nor the current registered-row journal closes this gap. Details belong to Project G1B and a separate production contract.

No new schema/SecretStore interface/GC/root/restore behavior was added. No S2-G2, C1 secret exclusion, C2 advanced UX, credential-inclusive export, baseline promotion, desktop merge, P11/D-038 closure or Preview acceptance follows.
