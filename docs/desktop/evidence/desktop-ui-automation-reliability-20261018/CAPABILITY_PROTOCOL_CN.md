# WIN-AUTO-001 后续诊断与回归合同

这是一份待 Project 评审的基础设施诊断合同，不是已通过的测试，也不批准修改系统设置或 CCB 生产代码。

每次新测试环境至少记录：精确 app/source/JAR 身份、工具入口和 bundle/helper 版本（未知就写 UNKNOWN）、caller/target session、Windows build、显示驱动/DPI/显示拓扑、目标进程创建时间、实际返回窗口、前台/焦点、错误阶段、截图是否真实取得、输入是否产生可验证效果、关闭及进程结果。不要导出用户名、其他窗口正文、真实数据或凭据。

| 步骤 | 证据与判定 | 拒绝规则 |
| --- | --- | --- |
| 1 发现 | 初始化并发现唯一的自有合成窗口 | DISCOVERY_FAILED；不拿旧句柄、猜测的字段或其他窗口继续 |
| 2 分开观察 | 独立记录 text-only 和 window-local screenshot；截图可见像素必须实际复核 | CAPTURE_BLOCKED、UIA_EMPTY 分开；不把两者混为全功能不可用 |
| 3 有界恢复 | 重新选择实际窗口，激活后最多一次 capture 重试 | 仍失败则保留原错误；不把重置/等待后的结果反写旧记录 |
| 4 输入准入 | 有效 UIA 值操作可单独试；鼠标必须有最新可信几何、坐标空间和目标归属；键盘须核实焦点 | INPUT_GEOMETRY_UNAVAILABLE / TARGET_OCCLUDED；不盲点，不清理用户窗口 |
| 5 结果 | 操作后刷新；结合测试夹具计数、字段值或合成存储身份核对 | 工具返回成功不等于效果成功；异步即时读回不确定就 NOT CONFIRMED |
| 6 生命周期 | 自有窗口正常关闭；独立确认真实进程，能获取实际退出码就保留句柄 | PROCESS_EXIT_UNKNOWN；不强杀、删锁或将窗口消失当作进程退出 |
| 7 差异实验 | 先复用固定夹具；如获单独授权，再一次只改变 helper版本、渲染器或显示环境之一 | 不同时改 GPU/权限/窗口/工具版本后宣称找到单一根因 |

建议后续专门切片按顺序验证：原生 WinForms → 独立 AWT/Swing → 精确 CCB Compose 包；每个目标分开记录截图、UIA、输入及进程能力。只有前一项产生新证据，才判断下一项的必要性。不要重新打包或重跑全部业务回归来代替基础设施定位。

Windows 显示/驱动/会话变化必须有用户授权、控制变量和恢复计划；禁止擅自关闭 Chrome、NovelAI、模拟器等用户程序。若需要修改 Computer Use 自身捕获后端，由平台维护方处理；不自行构造私有 helper 协议或绕过现有工具安全检查。

关闭 WIN-AUTO-001 至少需要：同一固定合成窗口在两次新的工具会话、至少三次 launch/normal-close 周期中，实际取得可复核的局部图像，完成点击/输入/滚动并有结果证据；明确记录任何失败及重试；再验证目标 CCB 的必要控件。这个重复次数是本调查提出的回归门槛，不是已冻结的产品验收或正式稳定性保证。

基础设施阻塞期间，如果 Project/用户另行批准人工替代，仍保留问题 ID 和未测分支。人工 PASS 仅证明对应用户观察，不关闭自动化问题。
