# Independent real WebDAV transport interop control

This additive cloud control changes no product source,85 candidate contract, signing identity or user profile. Root owns exact-source requests and dispatch. The current format-2 revision uses a direct Python server owner with bounded cleanup; its integration notes are in `REAL_WEBDAV_SERVER_CLEANUP_FIX.md`.

The fixed product source is `6ab083be4ee3de70757b06ea75ba49a77c558385`. The new request path is `.github/lan-next-real-webdav-interop-request.json`; no request is present here. Its exact schema is only integer `format:2`, that fixed `sourceSha`, and the LF fixture `fixtureSha256`. A different source, host, tool URL, selector or profile is rejected before any tool execution. After integration root can obtain the expected metadata from `RealWebDavControl.expected_request()`; no request writer or dispatch is run by this contribution.

The new workflow checks out the control with full Git history and prepares one clean detached source worktree under runner temporary storage. The helper verifies source/control HEAD, exclusive full-tree status, fixed source object type, absence of a tracked/old target, canonical paths and fixture bytes. It overlays only `app/sharedCore/src/test/kotlin/com/example/chatbar/domain/syncStoreProof/RealWebDavInteropSmokeTest.kt`. Existing product/Gradle files are untouched. A pre-existing original JUnit XML is rejected, not removed. The cloud script runs the single `RealWebDavInteropSmokeTest.realServerMethodsAndColdDifferentLocalRoutePreserveCompleteOpaquePayload` method with build cache disabled and tasks forced, then the helper rechecks bindings.

Official rclone `v1.76.0` Linux amd64 is pinned by archive SHA256 `b00f00b3266c3764413afe599d3ec316f6f43b3e0ea8a0bc1d186d2133e46df7`, from the previously recorded official release research. The script downloads only on the cloud Linux x64 runner, verifies the digest before extraction/execution and records actual archive length/hash plus version output. No current/latest version lookup or public-cloud account is needed. The server binds only `127.0.0.1:18765`, with a fresh local filesystem root/empty config and random synthetic Basic password. `real_webdav_process_owner.py` directly owns the new rclone child and remains in the outer job group. Its finally path waits five seconds after TERM and, if needed, five seconds after KILL. The outer finite group timeout remains a fallback; no process lookup or unrelated process is used. The module hash is part of the trusted control binding. No local service, download, bash, Gradle/JVM, SDK or device is invoked in preparing this draft.

The test retains CCB's actual `WebDavHttpTransport`, `WeakWebDavChunkAssembly` and `LanSyncGroupChunkCloudReadRoute`. It checks anonymous/wrong-password401 responses; writes196731 synthetic opaque bytes in seven physical chunks; closes the writer transport; and reads through an independent cold root with a different local route ID. It checks locator/attempt identity, complete metadata and original bytes, plus actual PUT/GET/PROPFIND/MKCOL usage. This is an independent server implementation instead of FakeDAV, with no replacement client sync algorithm.

Acceptance uses the complete original Gradle JUnit XML: exact suite/class/method, tests1/failures0/errors0/skipped0, exactly one testcase, no hidden failure/error/skip, finite duration. A summary/println marker or skipped `Assume` cannot pass. The helper copies failed XML unchanged too, and preserves compiler/runner stdout/stderr plus a typed failure result. Pure Python negative tests exercise this parser rather than asserting a PASS string.

The artifact upload is a fixed report-file allowlist: prepared/execution JSON, full runner stdout/stderr, exact JUnit XML, archive manifest, tool version and header-free method/path counters. No server payload, client private state, downloaded ZIP/binary, server log, config or password is in this upload list. All HTTP payload stays on runner loopback; the user's DD1 and other devices may be offline. Only ordinary CI/download usage is involved; no exact account charge is assumed.

Scope is deliberately small: real server HTTP/Basic/XML/path/framing and cold different-local-ID read interoperability. Opaque bytes are not proof of AEAD, ledger admission, native application, complete CloudRuntime/RecoveryOwner, TLS, commercial providers, quotas, OS lifecycle, interrupted/resumed large data or performance. The known separate6ab recovery-joining failure is retained; this transport control does not erase or gate it. The two network P2 findings also remain separate.

Actual local validation is pure Python/FS only. Initial local synthetic-path tests hit Windows legacy MAX_PATH in this long authorized scratch root; test-only temporary paths now use Win32 extended paths, with no Linux helper rule weakened. The final validation receipt records the resulting guard run. Git and cloud boundaries are injected only for scratch overlay tests; no real Git index is created or modified. Kotlin and shell syntax/runtime still require review and later cloud compilation/execution. This draft creates no new global approval gate.
