# Delivered84 to group-aware candidate85 control

`candidate85_group_control.py` selects the separate trusted group profile.
Its build/sign request paths, kinds, raw artifact name and workflows are distinct
from the original85 controls. The exact delivered84/e606 base, public31ef signing
block, package, 801f certificate, four roles, SDK inspection and original sixteen
repository/peer/Keystore checks are retained. No request/source is selected by
adding these files.

Seed84 uses real public application factories and production AndroidKeystore to
create a founder group, one source revision and a stopped synthetic HTTPS route,
then records public pins and protected-tree hashes. Verify85 opens the real sync
Activity while explicit pause stays set, because ordinary startup correctly does
not open a paused coordinator. It verifies original group/daily/root, ledger,
author/native records, stopped protected route and unchanged original baseline.
No private key, protected tree contents or password is added to artifacts.

An existing group correctly disables the legacy runtime, so the group UI phase
does not invoke the original legacy sample method. It runs the same group
verifier again through the original device helper with its mandatory opt-in.
If all phases pass, accounting is three actual invocations and two unique methods
(seed once, verifier twice). This does not prove an extra measured cold PID,
legacy runtime UI, Activity recreation, recovery/revocation/rotation, FGS,
commercial provider transfer, physical-device or human acceptance.

The shared engine adds only default UI scope/optional argument and their UI
passthrough. Old defaults remain exact. The new subclass additionally binds five
trusted control-file byte identities into its build request; exact equality is
rechecked throughout raw/public signing/upgrade validation. Request JSON cannot
select a profile, method, device API, role or arbitrary executable.

Installed pure guards read actual repository workflows and a uniquely named
hash/count transformation sidecar. They do not use workflow copies beside the
test. The two source workflows, all replacement counts and new workflow hashes
stay pinned. Local checks are Python/FS/mock only. Compilation, actual raw APKs,
signing continuity and native upgrade results remain cloud work after a mature
source is selected. A green pure guard is not native or delivery evidence.

Run each pure suite in a separate Python process. Combining the legacy suites
with the new group suite can expose their old shared import-name/path side
effects; those are not a native result. The installed new12, old85/15,
old84/14 and legacy14 checks have been verified independently without changing
their assertions. No candidate request, signature or native upgrade was created.
