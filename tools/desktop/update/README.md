# Desktop trusted updater

The manual Releases API check remains a discovery/notes surface. `DesktopUpdateRuntime` separately authenticates downloads through `desktop_update.py` and the hash-locked python-tuf runtime. The installed package supplies the public bootstrap, while the client cache lives under LocalAppData/ChatChatBarDesktopUpdates. No application entities, backup plaintext or credentials enter this runtime.

`prepare_runtime.py` downloads or reuses only the artifacts in `artifacts.json`, verifies their exact size/hash, isolates Python imports, compiles the native handoff, and records every runtime file. `attach_runtime.py` adds those inventoried files plus the public root and per-build identity to the generated app-image. `packageNsis` audits the whole resulting payload.

The Desktop transport uses `MisakaPiano/ChatChatBar-Desktop`, metadata branch `codex/update-metadata`, channel `preview`, platform `windows-x86_64` and target `desktop-installer.exe`. Studio R2 supplied a reference for the transport and lifecycle design; Desktop has distinct product identity, bootstrap and role keys. Release asset hashes do not substitute for TUF trust. Target version/source/reader and the version selected in the app must match before download or installation.

After download, `DesktopUpdateRuntime.install` refreshes trusted metadata and verifies the original bytes again. The native `UpdateHandoff.cs` locks that exact file, checks the confirmed PID/start time and current program pointer, waits for normal process exit and all program leases, and runs the NSIS installer. Normal application shutdown keeps the existing draft/task/audio/storage drain. The installer requires a new-program ready acknowledgement and compares the original pointer before activation. No writer is killed.

The standalone installer has an explicit repair checkbox. Fresh installer code stages a new `-r<nonce>` directory. A same-version repair requires the exact original manifest receipt; a newer package must not downgrade. Damaged originals and entry copies remain. The new bytes and ready acknowledgement are checked before publishing the pointer. Data/root selection and credentials are unchanged. Invalid ownership/receipts are not repaired by guessing.

`release_metadata.py` signs public metadata offline. Private role keys are supplied explicitly from a separately protected directory outside the repository; they are never package inputs. The committed public `update-root.json` is the bootstrap. Signing requires the exact final installer, its final install manifest, matching source/version, user-facing notes and an increasing metadata revision. Timestamp metadata expires after 30 days and must be renewed using the retained keys even when no new installer is released. The tool prepares files; publishing them is a separate action.

Validation layers stay separate: `test_client.py` uses independent synthetic keys and real python-tuf without network; `test_handoff.py` uses tiny invented native executables and never installs an app; NSIS lifecycle tests use their own registration namespace. A successful build or these tests alone do not establish ordinary installer/real-data/public-channel acceptance. Independent ZIPs retain their manual Program/UserData upgrade route.
