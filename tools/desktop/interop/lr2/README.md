# P11-LR2 opt-in tools (not application features)

Authority: CURRENT 182 and the user's explicit LR2 instruction. JDK17 only. All Kotlin is injected into the **test** source set; application Gradle and `src/main` are unchanged. `Run-Jvm.ps1` captures per-run arguments, exit, fresh JUnit and pre-run source snapshots in the new LR2 evidence directory. Never reuse a round label.

- `LargeArchiveTool`: one explicitly selected ordinary `.cbbackup`, no directory discovery. Native source read lock denies writes/deletion, existing reparse checks, source equality checked privately. At most 4GiB source/decrypted ZIP/aggregate expansion; 256MiB entry, 8MiB JSON entry/central directory, 64MiB aggregate structured input, 40,003 outer entries, expansion ratio1,000 after a1MiB tolerance. No plaintext archive file or media extraction. Nested ZIP has separate 256MiB/16MiB/4,096 limits. JSON/DTO Strings cannot be reliably zeroed by the JVM; no heap dump/attach permitted, process lifetime is bounded. Password only through Java Console.readPassword; no argv/env/file fallback. Encrypted stream EOF, local/central descriptors/CRC/offset/name/count, inventory and manifest must all match before any report. Plain archives are integrity-checked, not cryptographically authenticated.
- Typed existing Entity serializers, official transport DTOs and S1 graph owner are reused. Unsupported Entity fields stay unsupported, unknown data is not dropped. Scope counts/explicit choices are distinguished from aggregate-only ambiguity. Portable resource and selected owner links are checked, but **all-domain reference closure remains incomplete**. Nested v8 checks include strict ZIP, shared typed records, declared counts, image/audio availability and explicit message-version references; they are not a substitute for the complete official package runtime or all Memory/RAG semantics. Reports always say `SEMANTICALLY_BLOCKED` and `restoreSupported=false`; this is intentional until all domain adapters exist. Never convert this result into Prepared or census trust.
- `SlotProcessProbe`: **writes only newly created, explicitly task-owned isolated test roots**. It is not a read-only tool. First child uses the existing SaveSlot service via the prior accepted probe; another JVM reacquires the root lock, recovers the existing session journal, compares source semantics and all saved file hashes. Private witness/root/source-hash files stay ignored. Synthetic post-commit Runtime.halt is not mid-commit crash or Windows reboot evidence. Root tampering refuses before repository hydration. No providers, app container, SecretStore, GUI or installed roots are used.
- `CaOwnershipPreflightTest`: synthetic candidate/raw-byte/copy-capacity tests. Explicit deletion of a synthetic original is not live GC evidence. No sealed production domain, persisted app schema, task activation or scheduler.

Prepare test classpath:
`powershell -NoProfile -File tools/desktop/interop/lr2/Run-Jvm.ps1 -Round UNIQUE_LABEL -Prepare`

After preparation, use the recorded JDK17 and ignored `app/desktopApp/build/readonly-r0/runtime-classpath.txt`. Run the selected main class with `-Xmx256m -XX:+DisableAttachMechanism -XX:-HeapDumpOnOutOfMemoryError -Djava.awt.headless=true`. LargeArchiveTool takes one path and optional literal `--password`; the password is entered only at the masked console prompt. File paths may appear in local process arguments. Reject inherited JAVA_TOOL_OPTIONS, JDK_JAVA_OPTIONS and _JAVA_OPTIONS. Do not record a real console transcript or upload a private source/digest. Do not run SlotProcessProbe against an existing application root. This is an engineering harness, not a released user migration utility.

No background autonomous monitoring, release, installer, Android, G2C or real credential write is enabled.

Local `.gitattributes` preserves exact tested source bytes; the new evidence `raw/.gitattributes` preserves original logs/XML/fixtures without Git newline conversion. Early checkpoint indexes used implicit Git filtering, including absolute-path hash calls: their raw SHA/length remain valid, but their `gitBlob` may describe a line-normalized candidate. The collector now explicitly uses `hash-object --no-filters`; the final `checkpoint-sealed` index and committed tree are authoritative for byte-preserving Git blob identity. Keep the earlier indexes as history, not silently repaired evidence.
