# Desktop Studio generation presets

- Desktop global editing uses `DesktopStudioHistoryRepository` over the shared repository's overridable draft write. It stores a bounded metadata-only timeline and pending write intent in `desktop_studio_edit_history`; undo/redo restore through the original durable draft writer. Keep original single undo for legacy custody, and keep all timeline media references visible to exact-candidate cleanup. Truncated history contributes cleanup candidates only after commit. Selected backups carry the timeline with Studio settings; merge preview treats the draft, legacy undo, guidance checkpoint and Desktop timeline as one explicit choice when a Desktop timeline is present.
- `DesktopStudioTextHistory` is separate field-local Ctrl+Z/Y, keyed by stable person ID/field and model parameter scope. Whole-Studio arrows replay the durable timeline. Expanded fields fork local history until confirm; cancel discards only that editor. Global replay rebases changed field histories and does not publish programmatic restoration as new typing. Typing merge uses the actual changed span and a bounded interval; paste/replacement, cursor moves and explicit load/reset boundaries remain separate actions. Android's one-undo behavior is unchanged.
- IME composition stays in the active field until commit, which publishes one undoable operation; transient Latin preedit never becomes a global history step. History byte trimming keeps at least the current valid edit reversible instead of imposing a smaller input limit. Vibe payloads remain content-addressed, including history-only references.

- Shared `domain/image/NovelAiGenerationPreset.kt` is the explicit versioned generation contract. Include both model settings, continuous-mode semantics and paused guidance resources. History `toRecipe()` is intentionally incomplete. Existing `NovelAiStudioPromptClipboard` is separate positive-text interchange, not a full preset.
- Complete settings transport includes V5 effort/transparency and dormant High sampling choices; omitted defaults preserve legacy bytes. These are Desktop/shared extensions, not a claim that official147 or Suite implements the new controls. The separate full-Prompt clipboard deliberately leaves generation settings with its target.
- `DesktopGenerationPresetArchive` writes `.ccbpreset`: first `preset.json`, then declared content-addressed image/vibe members. Sequential ZIP inspection bounds manifest/member count, checked total/available disk and actual member bytes/digest; image decoding keeps `DesktopImageEditing` limits. Vibe payloads use `NovelAiInlinePayloadStore.copyResolved/retainStream/validateStream`, never whole-resource reads.
- `DesktopNovelAiStudioController` resolves actual default model at export, owns preview baseline and explicit apply under original admission/mutex, and preserves repository undo. Publish and applied outcome are one non-cancellable segment. Post-commit cleanup failures are APPLIED_CLEANUP_PENDING, not permission to reapply. `DesktopAppContainer` closes an initialized preset owner without creating one during exit.
- `DesktopStudioPresetExchange` supplies the normal tool-window shell; its `DesktopStudioPresetExchangeContent` is the same fixed-header/footer, scroll-body content used by Scene tests. Studio's original Prompt toolbar entry remains separate from AI design and positive-text actions.
- `DesktopPresetCustody` writes metadata-only staging and write-before-publication claims. Finish only exact IDs from the current action. Existing or racing content-addressed files are not newly owned; unknown publication retains its claim. `DesktopOwnedImageCleanup` recognizes payload markers in existing JSON and refuses deletion on unknown backup/large/corrupt authorities. Cleanup uncertainty keeps files/receipts; startup exposes pending state without automatic broad recovery.
- Tests: shared `NovelAiGenerationPresetTest`, `NovelAiInlinePayloadStoreTest`; Desktop `DesktopGenerationPresetArchiveTest`, `DesktopPresetCustodyTest`, `DesktopStudioPresetControllerTest`, `DesktopStudioPresetExchangeTest`. Scene PNGs use existing `CCB_MEDIA_USAGE_REVIEW_DIR`. See `docs/desktop/264_STUDIO_COMPLETE_GENERATION_PRESET.md` for exact transport and supported-platform scope.

## Separate full Prompt text

Variety+ and its normalized custom `varietyPlusSigma` stay in generation settings (draft, history recipe and full preset), not the separate full-Prompt clipboard. PNG metadata imports normalize V4.5 effective sigma by its source canvas; final requests scale once for the target canvas, leaving unsupported model choices dormant. The actual Studio toggle/controller/preset/undo/final-wire chain is covered by `DesktopStudioVarietyPlusTest` and `NovelAiVarietyResolutionTest`.

Authority direction: Desktop aligns with official CCB; the separate Studio Suite consumes CCB-authoritative formats. `CCB-FULL-PROMPT/1` and the retained ForkAndroid reader are unpublished extensions, not official147 support or a reason to distribute a new phone reader. Preserve original positive-text interchange and label the extension explicitly; no destructive removal of existing source/tests.

`NovelAiStudioFullPromptClipboard` and `DesktopStudioFullPromptExchange` own the distinct `CCB-FULL-PROMPT/1` readable, escaped text format and preview/confirm/original-undo flow. It carries all Prompt fields and ordered role controls/model/natural mode, including the selected model's `useCharacterPositions` control; other generation settings, continuous mode, references and AI design state stay with the target. Original positive clipboard must refuse the new preamble rather than ingest negative/control labels. Configuration is canonical metadata, not model-facing text. Tests `NovelAiStudioFullPromptClipboardTest` compare actual generation payloads and opposite coordinate switches for both models; `DesktopStudioFullPromptExchangeTest` uses the production controller and reusable content. See266; no Android/Suite parser or generic direct-positive-input compatibility claim.
