# LAN Sync

- Copied conversations persist optional `ChatSession.lanSyncOrigin` (parent, transaction, source device) in their user-data record; cumulative peer receipts retain mappings as well. Message physical keys follow the existing `<sessionId>_<messageId>` contract. Android observes the repository's sync revision to refresh messages/memory/slots without replacing its composer.
- Android `lanPreview` is a separate `com.example.chatbar.lansync` application/data area, named CCB 局域网预览. Ordinary debug/release identity remains unchanged. It is a Fork test build, not official Android integration or permission to overwrite an existing phone install.
- Desktop `0.1.0-lan.*` packages disable public startup/manual update queries and show the separate-delivery reason. Sync state has its own `ChatChatBarDesktopLanSync` local-profile root, separate from the existing credential-store authority; independent launch profiles isolate this state along with data and credentials.
- The explicit preview-only offline sample uses the same journal and repository reload path; it never auto-seeds a root or calls a provider. Comparison ignores top-level audit `updatedAt`; records carrying `sourcePresetKey` also ignore installation `createdAt`, while preserving actual stored values. This does not identify different random IDs as the same preset; unique-provenance projection remains pending. Resource content and model-facing text remain comparison inputs.
- Resource tokens carry a stable reference identity separately from SHA-256. Equal bytes in distinct ordered gallery references remain distinct; comparison normalizes device-specific identities by within-record alias pattern. Desktop projects materialized image/document references back to existing relative-path contracts and keeps originals beneath `images/character-covers`; Android retains canonical private absolute paths.

- Shared implementation: `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/lanSync/`. `LanSyncScope` declares the negotiated complete coverage; excluded stores are informational and never deletion authority. `LanSyncModel/Plan` use three-way whole-conversation units and deterministic fork identities. Graph/identity/memory-proof adapters originate from the established Desktop backup implementations; keep their opaque-text, version and ancestry behavior aligned.
- `LanSyncWorkspace` normalizes resource references to content hashes, captures immutable blobs and compares the local source again before journal authorization. Its journal is platform-local, outside portable app data. Bootstrap recovery must precede repositories; complete journal/payload/target validation precedes publication.
- `LanSyncText` strictly decodes source JSON, local journal/state, QR envelopes, package manifests and wire text as UTF-8; malformed bytes refuse before publication rather than becoming replacement characters in saved user text.
- `LanSyncTls` uses P-256 device certificates and pinned mutual TLS 1.2/1.3 AEAD. A two-minute one-use QR capability admits initial pairing, with explicit phone confirmation. Private identity bytes use DPAPI or Android Keystore. UDP39237 supplies address hints only; a pinned TLS handshake authenticates every discovered endpoint.
- `LanSyncRuntime` owns foreground-page host/poll jobs, conflict waits, retained transaction plans and bilateral completion receipts. A local apply receipt is not a shared completed baseline. Interrupted commits resume the same identity mapping; do not generate a second fork to resolve a lost acknowledgement.
- First-version UI permits one remembered peer at a time. Temporary captures/received blobs use depth-one invocation-owned scratch; completed transfers release redundant retained blobs and retire older committed payloads while keeping receipts and the latest safety journal. Completed rebases also follow locally recorded peer-bound superseded plans to reclaim their exact hash-verified transfer sets; unknown children or malformed/cyclic history retain evidence and surface a cleanup notice. Pending evidence remains separate.
- SaveSlot belongs to its conversation unit. Legacy inline records use separate historical memory proofs. V8 packages remain immutable with validated shared library-envelope rebinding; copied library IDs use their own canonical package filenames, while internal archive source/version/media identities remain intact for the existing restore owner. Interrupted single-sided application rebases subsequent edits against that side's original captured ancestor, retaining the superseded plan and existing fork IDs.
- Desktop adapters/UI: `desktop/lanSync/DesktopLanSync*`, Data workspace. Reuse task, automatic-backup, audio and data-coordinator maintenance. Android adapters/UI: `lanSync/AndroidLanSync`, `LanSyncActivity`; storage gate admission and AI maintenance reservation are both necessary.
- Cloud verification uses `lan-sync-ci.yml`; exact-source request files separately trigger `lan-sync-device.yml` (API26 Keystore/TLS/root checks), `lan-sync-package.yml` (ordinary image, audited independent ZIP, native launch/normal close), and `lan-sync-apk-proof.yml` (read-only original-artifact manifest/signature/hash inspection). `StartupPathEvidence.java` records original/canonical temporary roots before Windows startup tests. Desktop process tests use the existing read-only test classpath for real DPAPI reopen and an abrupt `Runtime.halt` followed by journal recovery in another JVM. `AndroidLanSyncKeyProtection` owns the Keystore wrapping boundary.

Current implementation is under engineering validation; no real-device/LAN acceptance or full-scope completion is implied by compilation or comparison tests. The scope matrix in `docs/desktop/LAN_SYNC_V1_SCOPE_AND_PROTOCOL.md` tracks remaining stores and platform differences.
