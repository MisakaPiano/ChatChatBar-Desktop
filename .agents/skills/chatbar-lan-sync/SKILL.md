- Matching endpoint coverage may expand an existing ancestor's coveredTypes by subset, retaining its revision/hash history and old deletion authority. - Single-applied expansion rebases filter the expected ancestor by the old common coverage; mixed units use the old common hash rather than a local-only expanded hash. Plans retain `commonCoveredTypesBefore` and explicitly resolved units. An already-applied endpoint may persist peer/owner-bound deferred deletion evidence only for unchanged newly covered records deleted after that apply, outside explicit conflict choices. A following ordinary round propagates the preserved local deletion after bilateral expanded authority exists. Changed records, explicit choices or invalid graphs cannot silently use this overlay.
- Resource tokens carry a stable reference identity separately from SHA-256. Equal bytes in distinct ordered gallery references remain distinct; comparison normalizes device-specific identities by within-record alias pattern. - Format-card `isDefault` is a device-local choice, like session model bindings. Wire captures normalize it tofalse, unchanged local records retain their flag and changed existing records restore it; new incoming formats cannot become default. Preset equivalence therefore ignores differences in the local default selection. Never repair this by editing format content or choosing by name/sort order.

- Shared implementation: `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/lanSync/`. `LanSyncScope` declares the negotiated complete coverage; excluded stores are informational and never deletion authority. `LanSyncModel/Plan` use three-way whole-conversation units and deterministic fork identities. - `LanSyncWorkspace` normalizes resource references to content hashes, captures immutable blobs and compares the local source again before journal authorization. Its journal is platform-local, outside portable app data. Bootstrap recovery must precede repositories; complete journal/payload/target validation precedes publication.
- `LanSyncText` strictly decodes source JSON, local journal/state, QR envelopes, package manifests and wire text as UTF-8; malformed bytes refuse before publication rather than becoming replacement characters in saved user text.
- `LanSyncTls` uses P-256 device certificates and pinned mutual TLS 1.2/1.3 AEAD. A two-minute one-use QR capability admits initial pairing, with explicit phone confirmation. Private identity bytes use DPAPI or Android Keystore. UDP39237 supplies address hints only; a pinned TLS handshake authenticates every discovered endpoint.
- `LanSyncRuntime` owns foreground-page host/poll jobs, conflict waits, retained transaction plans and bilateral completion receipts. A local apply receipt is not a shared completed baseline. Interrupted commits resume the same identity mapping; do not generate a second fork to resolve a lost acknowledgement.
- Legacy protocol1/2 chat envelopes use fixed `legacyChatTypes`; v3 additionally permits the known Moment schemas and v4 also permits the player singleton; validation normalizes only current device-local fields on a copy and never rewrites the old evidence. A transport-version or negotiated-coverage change forces a superseding fresh plan for one-sided application even without later business edits. If both sides already applied, `APPLIED_FINISH/APPLIED_COMMITTED` finishes receipts without replay, then requests a fresh round so later edits survive. Incompatible legacy bodies stop with `SYNC_LEGACY_PLAN_UNSUPPORTED`; no pending/baseline clear is used.

- User sync requests use distinct atomic tokens; a round consumes only its captured token after pending cleanup. A newer click during either endpoint's completion tail survives for another round. Do not replace this with a shared Boolean reset after durable receipts.
- A trusted host-side nonnetwork failure pauses data work and replies `PAUSED` to subsequent authenticated polls without capturing/transferring snapshots. The phone keeps only that observation poll alive, showing which owner needs an explicit retry; PC retry resumes the remembered peer without requiring a second phone click. Rejected pre-trust/protocol/pair commands cannot acquire this pause authority. `failureCode` is body-free UI evidence, cleared by retry/new work; pending/common records are retained.

Pending evidence remains separate.
