# Speaker history rename

- Shared `domain/chat/SpeakerTagHistoryService.kt` is the neutral owner used by both Android and Desktop. `createTask` derives protocol1 work; `SpeakerTagRenameTask.rewritePlan` persists message/session IDs, complete-message before/after SHA and the accepted timestamp before any message write. Bodies are not duplicated into tasks.
- `RoleplaySpeakerRenamePolicy` remains the marker substitution authority. `ChatRepository.rewriteSpeakerTagsForTask` validates every planned source before writes, recognizes already-applied hashes, reconciles message indexes and session previews, and keeps non-marker content/alternative metadata. Do not replay overlapping A→B→C or swapped names by current name alone. The older direct renames-only method remains for its original callers.
- `JsonFileStorage.readEntitiesByPrefixStrict` is selected-session JSON proof without index repair, skipped corrupt records or a new file-size cap; storage IDs/session/message relationships are checked by the repository. `CharacterRepository.mutatePendingSpeakerTask` opts into the existing writer lock's strict-fields reader to update only task metadata, retaining newer card/index fields and refusing unknown card fields rather than dropping them. Other atomic mutation callers retain their original decoding behavior. Observer callbacks do not replace these write owners.
- Legacy pending tasks without protocol/plan may run only when targets do not overlap old names. Unknown protocol, ambiguous legacy progress or changed/missing planned source stays pending with a visible error; never infer progress or erase the task. A remapped/restored source whose full fingerprint changed also remains unconfirmed.
- Portable selected-card backup (wire84–86) refuses overlapping pending tasks/ambiguous legacy progress, including null/empty plans before publication because official147 drops the new fields then blindly replays names. `forMerge` internal snapshots and local recovery retain the full tasks; unaffected selection and idempotent work are not blocked. See `chatbar-desktop-full-backup` for the narrow consumer boundary and frozen147 replay proof.
- Desktop derives renames by stable person ID during ordinary `DesktopCharacterEditorController.save`, includes the task in the durable card, and retains the existing post-commit draft marker until title rename, speaker work and cache agree. `CharacterEditorSemanticProjection` already excludes pending-task/index metadata. `retryCommittedCleanup` adopts only semantically matching task progress. The panel shows pending count/error.
- `DesktopAppContainer` injects the shared service with existing normal/audio/session-message/voice leases and memory quiescence. Startup resumes pending work before normal ready; no synthesis or model call is added. The original memory source-change callback is notified separately from textual rename, including partial-write failure/cancellation once a durable plan exists; this notification does not claim that asynchronous memory repair has completed. Independent SaveSlots/recordings are retained.
- `SpeakerTagHistoryRecoveryTest` covers partial write/reopen, task-clear failure, swapped labels, source edit refusal, legacy ambiguity and newer card/index metadata. `DesktopSpeakerRenameTest` covers real editor saves, chained labels/content/alternatives, post-commit recovery across container reopen and task admission. Original Android `SpeakerTagHistoryServiceTest` remains valid against the shared owner. See270 for actual verification state; source/test presence is not a completed run.
