# Desktop API accounts

- `ModelRepository.initialize` admits normal storage work before its initialization mutex. Account mutation calls `getAllModels` under an existing coordinator lease, while the ordinary model list/account picker may initialize a cold repository independently; queued maintenance must not let that later reader hold the init mutex ahead of the admitted account operation. `DesktopChatRepositoryAdmissionTest` covers the actual cold repository/coordinator cycle; initialization, migration and protected hydration still run once inside the mutex.

- `security/DesktopAccountStore.kt` wraps the existing SecretStore. One atomic protected `AccountProfiles(service)` bundle owns aliases, explicit provider names, credentials and selection; the separately protected `AccountProfilesRequired(service)` marker makes a missing bundle refuse legacy fallback. First-save rollback restores both. Opening account management adopts an existing singleton as an ordinary renameable account, leaving its old slot intact. `managesLegacyDefault` prevents deselection from reviving that old slot. LLM supports per-model endpoint-matched selection and `defaultLlm` for the existing SiliconFlow fallback; NovelAI/Fish have independent defaults. These new fields are omitted at their default values. Active/referenced accounts cannot be deleted. Corrupt metadata refuses reads rather than borrowing a legacy key.
- `DesktopApiAccounts.kt` provides the management dialog through `LocalDesktopApiAccounts`; `DesktopApiAccountController` admits mutations through the data gate, refreshes models and reloads cached settings after LLM changes. The default-connection target and model targets choose from the same account list. UI summaries exclude keys. Keep saved model names separate from presentation account labels so filenames/card exports do not acquire account metadata.
- Model hydration attaches runtime-only `ModelConfig.credentialAccount`; it is transient in official serialization. Model persistence verifies the account stamp. Account mutations share the model credential policy mutex; refresh/hydration runs outside that mutex. Deleting a model removes its legacy slot, retaining the reusable account; only strictly missing model references can be pruned, and a reimported missing ID starts unbound. Corrupt/unreadable records are not absence. Duplication detaches the new model from the old account reference. Existing global fallback and local no-auth rules remain owned by the shared resolver.
- `DesktopCredentialCall` captures a key and identity together. Fish batches and generated previews capture before queued work; child synthesis inherits it. Preview caches are account-specific; a picker clears stale catalog selection on account change. NovelAI Studio freezes one account across guidance, generation batches and processing; changed-account quota results are discarded. Switching does not issue provider requests. DesktopMomentGeneration captures the selected NovelAI account/key on each scheduled/debug/manual entry before text/design work, preserving an already matching frozen call. Manual work uses its original worker UUID/post context; a mid-flight account change affects only future work.
- A captured call also carries the selected account ID from the same protected read. Formal Fish TTS reuses that call via `DesktopFishAudioCredentials.currentCall` and attributes local media statistics to its frozen ID; switching defaults during a rejection retry cannot relabel the already captured request. No key or account alias is added to numeric records.
- Character cover/avatar requests capture the selected NovelAI call before Prompt design and retain it through image generation. Cover design labels come from the actual resolved LLM's safe account/provider label; deterministic avatars explicitly bypass that LLM. A mid-request account switch affects future requests without changing the captured call.
- `DesktopStudioCredentialRecovery.kt` guards Studio identity/capture reads and projects unavailable protected storage separately from absent integration. Composition, refresh, generation and processing use the same fixed failure signal; cancellation propagates. Its dismissible recovery surface offers explicit retry or API accounts, never clears slots or borrows a legacy key. Suppress it while any API editor is open, and use compare-and-set when opening NovelAI so another service's unsaved draft is retained. Header Refresh re-reads the projection; only explicit retry fetches usage. `DesktopStudioCredentialRecoveryTest` and `DesktopStudioGenerateGateTest` cover faults, protected-slot retention, editor drafts and task ownership; native process/root-lock acceptance is separate.
- The original Studio model-list refusal is separate: `readDesktopStudioModels` wraps resolver/repository reads as an explicit catalog result. Unsafe persisted model credentials retain their repository refusal and receive a model-specific recovery surface, not a NovelAI key prompt. Close preserves the error inline; explicit retry and existing model/data navigation do not rewrite JSON or keys. The Scene test seeds an independent synthetic unsafe model, checks original bytes and task continuity, and keeps direct repository refusal until explicit test-only external repair.
- Backup uses the three typed `desktop*Accounts` preference fields. `DesktopBackupExportCredentials` includes full LLM collections only with the models setting, otherwise only dependencies; NovelAI/Fish follow their credential options. Legacy-slot copies are transported inside the selected bundle. `DesktopImportSecrets` removes all three fields before staging. `mergeNamedAccounts` retains both collections, forks same-ID/different accounts, applies model data choices and remaps bindings; global choices govern default selection. Fresh-root writes restore legacy slots and save a normalized protected bundle. Android retention is not guaranteed; legacy restore refuses these credentials.
- A changed named binding creates a model conflict even when raw legacy keys agree. Taking an incoming legacy model with an explicit key clears its PC binding; BOTH keeps the original PC binding and applies only the fork's incoming binding. Missing/empty imported credentials retain compatible PC bindings, including credential-free directory relocation; incompatible endpoints detach. Default-null account extension fields are omitted from unchanged official packages.
- Tests: `DesktopAccountStoreTest`, `DesktopAccountPresentationTest`, `DesktopSecureRepositoryWiringTest`, `DesktopNamedAccountBackupTest`, `DesktopMergeCredentialsTest`, `DesktopBackupSelectionTest`. Use synthetic credentials and loopback only.
