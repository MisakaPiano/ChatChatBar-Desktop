# Desktop Task Center

- `DesktopTaskCenter` observes registered owner flows; it does not schedule feature work. Row IDs are namespaced by owner, stop/retry dispatches to the original ID, and stopRequested remains active until the real owner publishes a terminal state or retires its session activity. Observer shutdown joins its own collectors/commands, separate from business shutdown.
- `DesktopTaskCenterSources` projects TaskRuntime chat/image/repair and its existing document/card-design children. `ownedWork` uses the same UUID and Job already in TaskRuntime's shutdown drain, with completion observed after that child finishes. Format-card completion means candidate work, not applying/saving an entity. Unknown repair commit remains UNCONFIRMED and is not replayable retry.
- `withCardDesign` is shared by creative owners; only the format caller sets `formatCardCandidate=true`. Character, appearance, image and world-book callers pass explicit creativeKind values and their existing draft session. Unclassified callers remain generic with no invented editor target. Manage uses the matching controller's revealTaskDraft under original leave guards; that helper opens only the current unchanged pin, without model refresh/recreation/apply/save. Document preparation uses its actual usage session to distinguish chat-history indexing from a character document.
- Memory rows observe actual coordinator.runningSessions, including manual actions/reads. They are session activity, not paid-call proof. Stop uses coordinator.stopAndJoin(rowSession), never DesktopMemoryController.stop()'s selected panel session or permanent deletion cancellation. Session disappearance is not synthesized success/history.
- Fish rows observe the already-created voice coordinator's actual batch ID/session/message, phase and true counts. Streamed text, confirmations and error bodies are not copied. Stop calls that batch's existing `cancel(id)`; it is not a blanket session stop or a separate drain proof. Batch disappearance does not synthesize a completed notification. Retry/text-confirmation states remain waiting, and confirmation stays in the original voice UI.
- Full-backup export/check/restore-preparation rows use a UUID bound to the controller's original operation Job. Original cancel acceptance publishes owner stopRequested, retained by the aggregate center until actual completion clears it. Tests await this owner evidence, not only the center's synchronous command intent. Terminal publication occurs in its completion handler after password wiping and inspection cleanup; stale IDs cannot stop a newer operation. Picker cancellation is explicit metadata, not successful export. Cleanup uncertainty or cancellation/error with an already scheduled restart remains UNCONFIRMED, never a claim that durable restore preparation was undone. Catalog/leave cleanup are not notified. DATA targets select the matching export/check surface without starting work.
- AppContainer registers projections when each lazy owner is constructed; displaying the center must not initialize unrelated feature owners. It drains the observer after the existing business owners. Local context labels resolve only relevant session/card/document/draft names, are cached for retained rows, and remain separate from the fixed kind/status notice payload.
- Merge-import inspection/preparation rows bind the original controller operation Job and stopTask UUID. Fixed progress labels may be shown, never staging paths, conflicts, secret choices or source bodies. MERGE_CHECK completion means inspection/preview only; MERGE means result preparation, not activation after restart. Publication.INDETERMINATE or interruption with a sealed restart stays UNCONFIRMED, without replay/undo. Destination refusal retains the original preview and publishes a failed preparation; picker cancellation is CANCELLED. MERGE_IMPORT navigation selects the existing import surface without choosing conflicts or submitting work.
- SaveSlot rows bind only original mutating controller Jobs; ordinary list/binding reads stay unnotified. The original service journal and archive file move mark a Job-context publication attempt. Interrupted/failed work after that boundary is UNCONFIRMED, never proof of rollback; metadata does not alter transactions. Stop checks the original UUID, completion waits for its Job, and no mutation is automatically replayable. SAVE_SLOT targets reopen the session's original archive panel, not a message or automatic restore.
- AutomaticBackupScheduler projects only its actual executeOnce call, through the existing runtime to the center. A live/delayed loop is not active work. SkippedNotDue removes that check row without success history/notice or erasing earlier retained outcomes. Created becomes automatic-snapshot completion; cleanup warnings stay UNCONFIRMED with a fixed label, not raw paths/errors. No per-row Stop is offered: scheduler.stop controls future ticks and cannot substitute for cancelling only the current copy. DATA navigation selects existing automatic-backup settings; scheduling, stop/join and maintenance ordering remain original.
- Moments observe their actual worker through NonCancellable cleanup/refresh and completion; exact UUID stop cancels that worker, not future scheduling. withCardDesign(publishWorkRow=false) suppresses only its duplicate child row, retaining original activeJobs/admission/drain. SKIPPED is not published-post success history; cleanup or record uncertainty is UNCONFIRMED. Raw progress, checkpoint/reason/error and image receipts stay in the feature owner. No unavailable final post ID is invented for navigation.
- Document/history children carry DesktopIndexPublicationEvidence in the original Job context, chained to an existing RagController batch. The original index journal marks the forced intent/live-write boundary and clears that child's change flag only after verified rollback. Parent child flags preserve earlier committed documents. A failed/cancelled original child after possible publication projects publicationUnconfirmed as UNCONFIRMED; precommit cancel/proven rollback keep ordinary cancellation/failure. The existing document durable/cache safety check runs NonCancellable after late stop. No index transaction, source policy or retry is replaced.
- Shell entry uses the existing modal/root/leave guards and native title-bar hit exclusions. A target carries actual session/card/document/draft IDs; opening a generic route does not prove target navigation. Preserve dirty editors and verify that the exact target still exists.
- Chat message targets use `revealMessage` and the repository's bounded page/viewport anchor, retaining the composer. Character document focus validates both current draft and persisted card, then expands/scrolls without reloading the same dirty editor. Format candidate navigation only reveals its still-pinned draft; it never creates/replaces a draft. Manage target requests wait for existing transfer owners to become idle and then use the normal section leave guards. Local rows retain a short task ID even when names match.
- When leaving a busy Manage route for another task target, keep the center open with an explicit busy message. A same-route Manage request is retained until its original owners become idle. User-cancelled dirty-editor leave remains cancelled, without automatic later navigation.
- `DesktopModalKind` distinguishes only the backup workflow and task center from general modals. A busy backup surface exposes its compact task entry through LocalDesktopTaskCenter; Shell permits observation/original stop over that category, while navigation and reminder-preference changes stay blocked. Idle export selection, general dialogs, root movement and restart-required still defer/block the center. Full Shell coverage belongs in DesktopB1CIntegrationTest, not only an isolated task-panel Scene.
- Feature-specific verification starts with DesktopTaskCenterTest, actual owner cancellation/drain and DesktopTaskCenterPanelTest (narrow/wide synthetic captures via CCB_TASK_CENTER_REVIEW_DIR). Message paging tests need more than ChatRepository.MAX_WINDOW_TURNS real User/Assistant groups: consecutive assistant messages are intentionally one group. Await the original async stop callback within its existing budget, not only the synchronous stopRequested projection. Runtime, UI, tray capability, OS notification delivery and human acceptance are separate evidence; current scope is tracked in docs/desktop/251_TASK_CENTER_AND_TRAY.md.
- `DesktopTrayController` owns one AWT backend, explicit hide/show/tasks/exit actions and settings-backed `taskNotifications`. Main keeps the same Window composition with `visible=false`; ordinary X still uses the original close/guard/drain. Unsupported/failed attachment cannot hide the window. Notification payload is only fixed kind/status; successful displayMessage submission is not proof of OS delivery. AppContainer detaches the tray after feature drains and before closing the task observer. Headless tests inject a backend and do not initialize SystemTray.
