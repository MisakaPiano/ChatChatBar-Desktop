# Desktop Current-page Help

- `DesktopContextHelp.kt` maps each actual primary route to localized short instructions. Its User guide action switches to `DesktopTutorialGuide` inside the same help modal. Static bilingual copy and the 14-topic/29-section Desktop adaptation live in `DesktopUiStrings`; they do not read feature owners, navigate workspaces or invoke maintenance. World-book editor help and typed recovery remain separate entries.
- The manual guide uses shared workspace navigation items in a wide topic column and a collapsible narrow chooser that temporarily replaces the reader, retaining the fixed header/footer. Selecting a topic or previous/next returns to the reader. Selected-topic reveal waits for a measured viewport; previous/next callbacks reread their own boundaries so stale enabled actions cannot index outside the topic list. Opening/reading/closing does not change imported Android `tutorialVersion`, saved preferences or first-use progress. An automatic first-use reminder is still separate work.
- `DesktopPrimaryShell` captures the current route on open, blocks help under root/backup/restart locks and existing modals, and reports it as GENERAL modal activity. Help opening/closing never reloads editors or changes navigation, filters, drafts, candidates or work. Task-center and startup notices retain their existing deferred handling.
- `DesktopTitleBar` provides the small question-mark entry and records its actual bounds in `DesktopChromeLayoutRecorder.interactive`. Route tabs alone can scroll at the smallest native width; selected tabs reveal on selection/viewport changes, retaining fixed help/tasks/native captions and all enabled feature routes. Disposal clears stale hit rectangles.
- `DesktopContextHelpTest` exercises localized route headings, close geometry, 330/420/720/1100 title bounds and client/native hit contracts. Cloud captures use `CCB_CONTEXT_HELP_REVIEW_DIR`. `DesktopB1CIntegrationTest` exercises real Shell open/close/reopen and modal priority while preserving repository bytes, dirty editor/composer and request/work baselines.
- `DesktopTutorialGuideTest` exercises both languages, 330×650/330×420/1100×650, stale next at the last topic, narrow list close/reopen, actual selected bounds inside its viewport, manual list scroll, return and close. The real Shell test also reads, returns, closes and reopens the guide while retaining the original draft/file/work assertions. These checks are scoped to the manual reader, not automatic onboarding or all platform keyboard behavior.
- Offscreen reveal-animation checks must advance the scene's frame timestamp (`render(System.nanoTime())`); default render time is zero. Preserve the same visibility deadline and actual bounds assertions. Native drag tests find measured blank intervals between controls, since fixed help/tasks may touch caption buttons; their shared boundary is not a drag region.
