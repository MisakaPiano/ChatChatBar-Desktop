# Desktop original character covers

- Shared `CharacterCard.coverImage`/`chatBackgroundImages` and packaged `coverImageResourceId`/`chatBackgroundImageResourceIds` retain independent original, ordered gallery and separate default. Ordinary exports default to `COMPLETE_V11`; explicit `OFFICIAL_V9` omits independent cover/gallery/person gates, retaining aliases used by avatar/default/person images. Reader accepts3–11 including Android gallery10 and old Desktop cover10 by actual optional fields. Gallery duplicates resolve by first reference occurrence, never by equal image bytes; default outside gallery is legal. Person gates emit `enabled` and accept old `desktopEnabled`; Desktop Kotlin names stay unchanged. Frozen official1.4.11 remains3–9; schema numbers alone do not prove interoperability.
- `OriginalCharacterCover` validates PNG framing/CRC and strips case-insensitive ChatBarCharacter/chara/ccv3 text chunks (tEXt/zTXt/iTXt), preserving every other encoded block. `CharacterCardPngPackageCodec` uses it before attaching current data. Classifier and typed native/ST ingress prefer embedded originals. PNG resources exclude nested old card data; nonPNG sources stay byte exact.
- `DesktopCharacterResourceStore` owns CREATE_NEW `images/character-covers` and only that additional nested directory. `DesktopCharacterDraftResources` stages/copies/materializes covers and admits restored absolute draft paths only within its strictly validated root. Editor draft/save fields and `desktopCharacterResourceReferences` retain covers.
- Editor replacement/clear/copy-avatar retain original crop behavior. JSON/PNG choices default to complete11, with explicit compatibility9 loss warning. JSON choice uses a compatible baseline so missing omitted originals do not block that choice; final full capture requires every cover/gallery file and rechecks card/captured compatible resources. Rendering, same-file guards, original-PNG appearance and stale/canceled draft refusal remain. Temporary layout/title/replacements affect export copies only.
- `requireDifferentCoverOutput` retains the canonical owned cover location even when an unused original or its directory is absent. Compatible JSON does not require that optional file to exist; exporting onto its missing location is still refused. Existing unsafe directories/symlinks and present-file/hardlink alias checks stay strict.
- PNG bases come from prepared current-card resources, including read-only projected legacy gallery, never disk-wide or another card. Raw-base save strips prior PNG card payload in its output copy. `DesktopCoverExportAssets` embeds a replacement as an independent export original and retains an old cover resource still used by gallery/default/avatar/person. No saved card fields change. Display title, original/layout rendering precedence and live native picker owner remain separate. Tests cover raw reuse, full reimport, source custody and compatible-reader neighbors.
- `DesktopCharacterExportDialogs` is mounted once by the management root or standalone bootstrap root. The nested `DesktopTypedTransferPanel` starts export actions but never owns their dialogs; this avoids two JSON popups/PNG windows in the management Transfer section. The real nested-panel Compose test checks one modal owner and close/reopen reset.
- Explicit generated-cover application stages a separate full-image cover in addition to its existing avatar crop/background; candidate-only application retains the candidate boundary. `DesktopCharacterImageTest` covers retained original assignments and cover save alongside its existing retry/rollback checks.
- Backup resource registry, `desktopName` and merge `addMedia` retain dedicated cover storage. Existing reference cleanup remains authoritative. Checks: shared `OriginalCharacterCoverTest`/`CharacterCardExportCompatibilityTest`; Desktop original-cover/backup and `DesktopCharacterExportCompatibilityTest`/`UiTest`, plus transfer/classifier/editor neighbors. The frozen `interop/official1411` DTO/reader has namespace-only transforms and per-file origins; its user-tool dependency additionally aliases the Android Prompt facade import to the shared authority, without changing validation methods. It validates compatible outputs and refuses full11. Actual explicit compatible controller JSON/PNG and default full routes retain independent source bytes. Android prepared source is not execution evidence.
- `DesktopCharacterBackgrounds` retains old private images/preferred. Production new imports write original encoded bytes to the portable card gallery; private preferred and session override remain separate. Read-only export projects unmigrated legacy refs without writes. Explicit migration publishes card first then a retained `migrated` marker; repetition is reference-idempotent and failure keeps source. Later removal does not reintroduce migrated entries or delete retained legacy files. Default rereads, draft materialization, reference cleanup and backup array mapping share that owner. Old normalized library files cannot recover their earlier external encoding.
