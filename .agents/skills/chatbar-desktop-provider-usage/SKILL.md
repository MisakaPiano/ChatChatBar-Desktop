# Desktop Provider Usage

- `DesktopProviderUsage.kt` owns typed numeric records, cumulative counter replacement, query filters, checked Long totals and atomic local custody in `diagnostics/provider-usage`. This local directory is excluded from portable full backups. Missing counters remain null; reported zero is retained. Cache counts are annotations, not additions to prompt tokens.
- Token records keep schema 1 and omit `media`; formal Fish TTS records use schema 2 with typed `DesktopUsageMedia`, no token counters. Old token files are not rewritten. The store rejects mixed units, wrong schema, negative measurements and changed attempt identity. Summaries deduplicate revisions before checked sums and exclude media attempts from unreported-token counts; local Unicode code points, valid audio milliseconds and bytes remain distinct from unknown provider billing. Older readers may refuse media records; this is a local diagnostics format, not an official Entity/backup schema upgrade.
- `DesktopProviderUsageOwner` coalesces pending snapshots by physical attempt on an IO writer. Failed writes keep the latest pending record and expose a save error; read errors remain independent. Close drains after all producer transports/editors and before the data gate closes. Process death can leave RUNNING records; they remain uncertain and never imply no billing.
- After committed root maintenance sets RESTART_REQUIRED, final close uses `withLocalDiagnosticsShutdownDrain` solely for the old root's local statistics. It holds exclusive admission, keeps normal admission closed and preserves RESTART_REQUIRED on release. It is not an entity write or a new provider request; the root lock is still held. This avoids stranding an asynchronous numeric tail during restart.
- Close serializes concurrent calls and becomes a no-op only after all pending rows are saved and the writer is drained. A failed close retains pending rows and can retry; an empty/already-completed close never reacquires a closed data gate.
- `DesktopUsageDrainException` is a specific retained-tail recovery result. `closeDesktopDataRuntimes` leaves the gate/backup/root lifetimes intact for it; `closeDesktopWithRecovery` offers safe-close retry with a storage-specific message. It does not classify arbitrary statistics/entity failures as resumable, and does not open a CLOSED gate. Successful repeated close and production failed-write→repair→retry are separately covered.
- `ProviderTransportDiagnostics.onAttemptStarted` marks actual transport attempts: one per main-chat retry, one per isolated stream/complete call. `DesktopUsageAttemptRecorder` allocates independent request/attempt UUIDs and replaces cumulative SSE reports. Retry notices and UI stream collectors do not add counters a second time.
- `DesktopTransportDiagnosticsOwner` optionally receives a numeric sink. Its bounded raw request/response records remain process-local and are never serialized as statistics. Clearing diagnostic rows does not erase active numeric capture.
- `DesktopUsageContext` carries immutable actual task/session/card identities separately from diagnostic UI groups. Moments sets a coroutine `DesktopUsageParent`; `moments:JUDGE/GENERATE` are display groups, not real session IDs. Card editor draft IDs use separate `editorSessionId`, with optional `personId`/`subjectId`; `Pin.session` in appearance is an editor draft, not ChatSession. Named account ID/provider come from the actual resolved model credential attribution, not names or URL parsing.
- `DesktopTaskRuntime.launchNovelAi` installs its actual task UUID and optional real ChatSession/message identity inside the owned job, including retry jobs. Standalone Studio work remains OTHER without a fabricated chat/editor ID; chat-bound work is CHAT. Card identity and editor/person context still belong to their actual feature caller rather than a display label.
- Current capture covers main chat, character/format/world-book AI, Moments judge/copy/debug, the NAI auxiliary text/linked-vision graph, embedding and memory/RAG text requests. `withDesktopAuxiliaryUsage` reads the immutable coroutine parent inside collection; unknown callers remain OTHER with no invented chat/task identity. The explicit vision-diagnostics overload stays singly captured by its caller. Infrastructure drains its HTTP transport after producer/editor shutdown, before usage custody closes. Binary NAI, independent voice-preview and other provider coverage remain separate work; formal TTS metadata is covered below, not full billing coverage. `DesktopProviderUsagePanel` is under management's other settings, with time/source filters and per-model/provider/account groups. No monetary estimate is inferred.
- Voice translation/tagging uses `DesktopFishAuxiliaryGateway` over the existing `streamFishVoice` transport. `FishVoiceTextGateway.withLogicalRequest` spans each feature retry loop: TRANSLATE and TAG get distinct logical recorders, while actual dispatches advance one physical-attempt sequence. `DesktopFishGenerationCoordinator.networkWork` supplies its real batch/session/card/message parent; diagnostic `voice:*` labels are never session identities. Raw text/keys stay outside numeric records. Voice producers drain before usage custody. `DesktopVoiceAuxiliaryUsageTest` covers actual default gateway and retry accounting.
- Formal TTS uses `DesktopMediaDiagnosticRecorder` at original `DesktopFishVoiceTransport` enqueue/response/drain boundaries. Its frozen credential/account and actual coroutine parent survive rejection retries; one logical request has one row per physical attempt, with known HTTP status and independently measured returned audio. Refused/prestart work adds no row. Cleared process logs do not erase numeric capture; a synchronous numeric-sink failure is visibly separate and cannot fail or replay synthesis. The original writer retains asynchronous save failures and drains. `DesktopFishMediaUsageTest`, `DesktopMediaUsageCustodyTest` and `DesktopMediaUsagePanelTest` cover loopback transport, persistence and 420/1100 Scene output; captures use `CCB_MEDIA_USAGE_REVIEW_DIR`. NAI binary calls, picker previews, account/session/request detail UI and complete pagination/grouping remain separate work.
- `DesktopEmbeddingGateway` captures one physical attempt after configuration/admission checks, keeps its existing one-shot/no-replay transport, and reads optional usage from the already parsed response through `OpenAiSseParser.parseUsage(JsonObject)`. Counters survive later vector validation failure; malformed/missing optional usage stays unknown and does not invalidate valid vectors. IDs/model names use the actual embedding configuration and the existing credential scrubber; provider/account remain unknown because EmbeddingConfig has no attribution. No vector/input/URL enters statistics. The actual document-preparation child supplies its registered task UUID plus card/document, history maintenance explicitly supplies the real ChatSession, and retrieval carries real card/session/user IDs; chat work keeps its actual task parent. The existing embedding transport drains before usage custody. `DesktopEmbeddingUsageTest` uses actual container HTTP, persistence, cancellation and rejection paths.
- `DesktopMemoryRagTextClient.withTaskRun` reuses the shared caller's logical retry boundary: same kind/model repairs advance one physical-attempt sequence; explicit nested summary work ends the preceding plan purpose independently. The existing transport receives its recorder, without changing prompts, caps or retries. A swallowed planner failure/timeout retains the last real FAILED/CANCELLED outcome despite normal fallback return; a successful later attempt supersedes it. AppContainer resolves the diagnostics supplier only at request time to avoid lazy graph cycles. `DesktopMemoryController.withSessionUsage` binds the actual session inside both platform maintenance and the separate manual-action gate, with no invented task/card ID. `DesktopMemoryRagUsageTest` drives shared head repair, nested purposes, actual planner fallback and child cancellation; `DesktopMemoryLifecycleTest` also drives manual node regeneration through the real controller into the shared AI boundary.
- Tests: `DesktopProviderUsageTest` (unknown/zero/partial, retry dedup, overflow, reopen), `DesktopProviderUsageCaptureTest` (actual synthetic HTTP modes/retry, diagnostic clear, private-body exclusion, failed-write and restart-tail recovery), `DesktopAuxiliaryUsageTest` (actual design stages/vision, parent inheritance, explicit capture, truncation and cancellation), `DesktopProviderUsagePanelTest` (narrow/wide actual statistics and source filtering).
