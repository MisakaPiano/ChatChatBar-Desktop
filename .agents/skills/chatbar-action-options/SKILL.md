---
name: chatbar-action-options
description: Maintain declared action blocks, per-reply rule snapshots and shared chat/image/voice projections.
---

`ActionOptionsFormat` declares literal opening/closing/title and numeric or alphabetic labels. `RoleplayActionOptionsPolicy` is the only recognition and validation owner. The default recognizes complete titled short/legacy long rules and explicitly named legacy action fences. Declared custom fences must match their literal markers. Ordinary, nested, quoted, indented and incomplete code examples remain text; unsupported boundary combinations fail validation. `MarkdownCodeFences.ranges` owns top-level code boundaries.

`FormatCard.actionOptionsFormat` travels through standalone `FormatCardPackage`, character-linked default formats and editor drafts. `ChatMessage` captures the request-time rule and aligned alternative rules; `MessageAlternativeVersionPolicy` carries them through append, selection, edit and removal. Null means the default conventions. Default-absent fields retain old wire omission and unbounded Desktop alternative retention remains independent.

Desktop `DesktopFormatActionOptions` edits the declaration and shows a literal example. `DesktopActionChoices` consumes the shared result; `DesktopComposerInput` retains cursor insertion, exact undo and conditional draft persistence. `DesktopPrimaryChatPresentation` hides custom action text only for the interactive view, preserving copy/export text, original source bounds and voice indexes. Existing STATUS action disclosures keep their placement; custom blocks use the same compact disclosure after the message.

`ChatHistoryActionProjection`, `NovelAiPromptAuthority` scene sources and `VoiceGenerationPolicy`/`VoiceAnchorPolicy` consume the active reply's captured rule. Speech filtering preserves original segment coordinates; old recordings can match either old unfiltered or new filtered source text. Historical numeric or ambiguous references keep conservative chat-history admission. Standalone unknown letters retain their sources; ambiguous English A/I do so when an earlier recognized active letter menu actually defines that label. Lowercase a requires an earlier literal lowercase menu label, except A/a immediately before Chinese (optionally horizontal whitespace) also retains a prior A/a source. Ordinary English articles and numeric-menu controls stay separate.

The A/a-to-Chinese script check uses Unicode code points, not ICU regex property aliases, so Android and Desktop consume the same classifier. Adjacent-Han B–Z agreement/possessive references, including horizontal spacing around the label, require that an earlier actual letter menu supplied it; an unoffered C or a number-only menu does not invent that letter choice. Penultimate references retain their source. Desktop format repair completes only reliably recognized trailing blocks and compares existing option text/count/order before either completed or stopped publication. Only an independent, non-code-indented closing line ends a declared block; the same marker within final option text or an indented continuation remains content. Quote/list code containers, including bare/empty item markers, never create an action block or closing-line repair. Its requirement builder lives with `FormatRepairPromptAuthority` and the Android `PromptTemplates` facade. Original recovery/restore/redo remains with `DesktopMessageFormatRepairController`.

Tests: shared `ActionOptionsFormatTest`, `ActionOptionsDeclaredFenceCompatibilityTest`; Desktop `DesktopActionOptionsFormatIntegrationTest`, existing `DesktopActionChoicesTest` and `DesktopActionOptionsRequestTest`. Use actual source coordinates and reply alternatives when testing presentation or voice; a string-only parser result does not cover those owners.

Automatic retrieval always strips recognized menus and carries only provable selections. Fresh sends and resumed users have distinct proof rules; direct chat history remains conservative. Named choice dependencies travel as `actionChoiceSourceIds` through raw-turn indexes, session copies and merge ID mapping.
