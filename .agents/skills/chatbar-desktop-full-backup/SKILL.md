# Desktop Full-App Backup

`DesktopDataWorkspace` separates export, merge import, file-only verification, root selection, automatic backup and updates. Subsection changes retain preparation/choices; in-flight merge and restart states force the merge surface. `DesktopMergeImportPanel` groups conflicts using existing backup setting labels and preserves every per-record choice. Final credential consent remains explicit; category navigation never selects or submits a merge.

## Entry points and format authority

- User-facing export is `DesktopBackupExportDialog` → controller catalog/selection → `DesktopFullBackupService.exportModern`. `backup/BackupExportSelection.kt` adapts official147's 51 setting options, card/session dependency policy, all/light/clear presets and per-session media choices; selection is applied in `DesktopFullBackupMapping.export` BEFORE resolving resources, so a broken unselected card cannot block another card. Writer emits the exact selected scope and media choices. Optional encryption uses a volatile repeated password (8–1024 chars); a nonempty password alone does not select encryption. Keep the legacy inspect password separate.
- Export password/confirmation and both import/check password fields share `BackupPasswordField`: default masking, eye reveal/hide, volatile visibility reset on empty or disabled input. `AppBackupPasswordRequired` distinguishes an encrypted envelope without a valid-length password; streamed refusal retains only its typed `passwordRequired` flag and safe locations. Controllers display a password-required message without interpreting this case as corrupted data.
- `DesktopBackupExportCredentials` captures only selected exact global fields and known included model/embedding consumers from the protected store under snapshot maintenance, then verifies unchanged before publication. `DesktopFullBackupWriter` overlays credentials in memory into official entity/preference fields, computes transport inventory from those bytes and rechecks the separate credential-free source proof. The staging snapshot and live entities stay credential-free. Import uses existing authenticated `DesktopFullBackupStaging`/`DesktopImportSecrets` and fresh-root credential choices, never the legacy restore path.
- `DesktopBackupAuxiliary` classifies only recognized rebuildable Studio SQLite/index/vibe cache paths under `auxiliary/novelai`; unrecognized files still refuse export. `DesktopBackupMissingResource` carries a bounded owner/resource label for local UI; do not silently omit a selected missing attachment. Desktop historical/preservation custody is indivisible: partial selection with such custody currently refuses explicitly, full selection retains it. This is not Android Moments runtime support.
- Service error classification must retain fixed `UNCLASSIFIED_ROOT_ENTRY`, `UNCLASSIFIED_HIDDEN_BACKUP_ENTRY` and `DESKTOP_CUSTODY_REQUIRES_FULL_SELECTION` rejection identities; the controller maps these exact codes to local explanations. Unknown exception text remains hidden. The two `P11S2*ProbeTest` suites enforce original-content retention and no partial output for these failures.

- Session/SaveSlot participation, its default-off automatic-pause option and card-person `desktopEnabled=false` are typed Desktop extensions, not upstream code84–86 features. Empty/default values are omitted. `DesktopBackupPolicy.hasDesktopParticipation` feeds legacy inspection and modern merge disclosure; serializers retain them in both envelope routes. `DesktopMergeIdentity` remaps card IDs and both manual/automatic person-ID sets without declaring identities or altering text. Arbitrary logical ID values remain values, not object keys or credential fields.

- `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/backup/`: selected official ChatBar 1.4.5 @ `1198a13cf3008de1358b8a69aa5e40b64797c8d9` v1 envelope, Tink 1.23.0 codec, registry and streaming JSON transducer. The formal upstream baseline is still 1.4.1. Version code 84 comes from the selected official build source.
- `DesktopFullBackupArchive`: bounded authenticated scan without plaintext disk output, then credential-free staging and ZIP central/inventory verification. Preserve original input and transaction evidence; inspection/snapshot/mapping scratch has a separate owned lifetime.
- `DesktopBackupReadOnlyInspector` is a separate S0 API for v1/v2 and official codes 84–86. Its `ReadOnlyInspection` never authorizes restore or becomes `Prepared`; existing service/codec restore admission remains v1. Transport scope DTOs/options follow pinned 1.4.7. Checks are memory-only (64 MiB source/decrypted ZIP, 128 MiB expanded, ZIP32); unsupported schemas are explicitly uninterpreted, not portability-approved. Results contain only categories/counts/digests; known credential fields are classified without SecretStore access. This API has no GUI wiring and does not verify nested SaveSlot or dependency/resource graphs.
- S1 `inspectMoments` invokes `MomentArchiveReadOnlyValidator` only after the same complete S0 scan. `MomentArchiveSnapshots` are extraction DTOs, not live entities. Reports bind exact record SHA/length to the source digest and independently classify senderAvatar/body/metadata edges plus card/session/sender/Task.postId links. Only code85/86 top-level missing avatars receive the historical exception; code84 stays strict. Scope omissions, unresolved dependencies, unknown schemas/external references and known credentials cannot become runnable or persisted objects. No seal, restore, scheduler or repository is created. Focused tests: `MomentArchiveReadOnlyValidatorTest`; wire fixtures remain independent R1 DTOs.
- `BackupJsonStream` is the package-only pinned147 transport transducer; default handlers preserve existing scans. Typed identity/key hooks, strict streamed replacement and sequence support are available for merge preparation. `BackupMergeJsonStreamTest` covers payload preservation and discarded-subtree validation; no automatic entity merge is implied.
- `DesktopFullBackupMapping` / `DesktopBackupPolicy`: explicit store registry, logical model ID to Windows physical key, flat image/document resources and verified MP3 ownership. An existing session-matching Desktop clip reuses its staged file only after its registered receipt/hash/MP3 verification; a bad supplied receipt refuses, never falls back to derivation. Unowned/Android clips still gain a managed copy and retain their imported originals. Original duration must be nonnegative and declared positive byteLength must match before either route. Unknown fields/stores fail before commit. Internal brush preferences survive in a local singleton and return to official preferences.json on export.
- Mapping inventory refuses unclassified hidden ancestor/file bytes (`UNCLASSIFIED_HIDDEN_BACKUP_ENTRY`) before export scratch instead of silently omitting them. Existing single-file `.part`/`.tmp`/`.backup` and the explicit translation-cache exclusion remain; this is refusal, not a Moments preservation adapter. Current G0/G0R tests assert refusal; original omission evidence remains historical.
- `DesktopBackupScratch`: registers only invocation-created files/directories with native identity. Removes redundant decrypted ZIP immediately; prepared entries live until confirm/discard/replacement/panel leave/cancellation/shutdown. Export and mapped plans close after use. Cleanup never traverses unknown children or touches restore journals; identity changes report cleanup unconfirmed. No sweeping historical or crash-left work without ownership evidence.
- `DesktopBackupCompatibility`: payload-free categories distinguish unsupported Moments, other unknown entity types, incompatible fields, and external credentials. This legacy compatibility path still rejects before its own commit; it does not authorize the separate confirmed fresh-root merge workflow.
- `DesktopFullBackupGraphValidation`: offline message/version/voice, memory graph, media and SaveSlot checks; no model calls or default-filling repair.
- `DesktopFullBackupService`, `Controller`, `Panel`: app-owned current-format selected export. The GUI file-check button uses `verifyFile` → bounded streaming `DesktopFullBackupSource` for v1/v2, including selected credential-bearing exports; it retains only a summary, creates no plaintext scratch/restore preparation and never accesses SecretStore. A successful check is not a merge or activation proof. Legacy `inspect`/scheduled replacement remain internal regression routes and still reject incoming credentials. Export result state distinguishes success/failure; success includes the normalized saved path, shown in a dismissible modal. Passwords are volatile and cleared; the lazy SecretStore supplier is used only for an explicitly selected credential-bearing export.

- LR4 `backup.preparation` contains unwired `FreshRootPreparation` (synthetic fresh-root/protector/typed-target/legacy-retention assessment delegating to G2A recovery intent checks) and `DormantPreservationPreparation` (bounded memory-only strict raw voice/Moment and media candidates). - `DesktopFullBackupSource` is the bounded streaming production input (4 GiB ZIP32 source/expanded, 256 MiB entry, 64 MiB aggregate structured data). `StrictBackupZipReader` promotes the LR4 local/central/CRC/EOF checks without decrypted ZIP output. Its sink is explicitly tentative: only a private non-runnable staging workspace may consume it. A `Verified` result requires complete authentication, inventory/hash/counts, pinned Entity schema and scope validation. It alone proves neither dependency/media semantics nor activation eligibility. Cancellation propagates. `Refusal.failureLocations` retains only the original exception class and bounded application code frames; the original Throwable/cause/message remains discarded. Legacy Prepared/service replacement admission and S0 small-memory budgets remain separate.

- `DesktopFullBackupWriter` writes explicit code86/v2 from a frozen mapped credential-free snapshot, using the existing codec's separate v2 encoder and same bounded streaming verification before no-overwrite publication. Transport DTO default omission matches pinned147. Incoming retainedPreferences must be empty (official BackupArchive); target-only retention is derived later from scope, never accepted as an archive instruction. Tests: DesktopFullBackupWriterTest and DesktopFullBackupSourceTest; independent R1 DTOs/official fixture decryptor cover the wire.

- `DesktopFullBackupStaging` consumes that tentative stream into an owned, non-runnable scratch and publishes only after Verified. ## Restore lifecycle

- Prepare and verify under normal admission; flush the chat composer before snapshot/schedule. Join the automatic backup scheduler before reserving audio. Confirm audio stop/close, then enter exclusive coordination.
- `DesktopFullBackupCommitJournal.schedule` copies old/new evidence and atomically authorizes the next startup; it does not replace live content. Seal the coordinator as restart-required with the authorization marker. UI prevents further navigation/writes and offers normal exit, never automatic restart.
- `DesktopStartupGate` holds the root lock and calls whole-app recovery before index/session recovery and before constructing repositories. Partial startup installation rolls back; committed evidence is verified. Foreign bytes or changed evidence block startup. Old/new journals remain retained, never swept.
- Local root selection, desktop-settings, diagnostics/backups and the separately located protected SecretStore are preserved. A full archive containing Desktop-specific entities (including retrieval_model_config, absent from the selected Android registry) is not claimed Android-compatible.

## Verification

- `tools/desktop/windows/snapshot-recovery/` is a test-only, direct-compiler companion against explicit frozen1010 JARs. Two Python-driven process tests cover coordinated snapshot restore/restart admission, independent repository/media reopen and corrupt-snapshot refusal in six headless JVMs; no Gradle rebuild, bootstrap or SecretStore. It does not prove the retained historical real-root snapshot restored.

- Focused suites: DesktopFullBackupArchiveTest, MappingTest, CommitJournalTest, ServiceTest, plus StartupGate, data coordination and audio-maintenance regressions. Synthetic fixtures only; no real root restore.
- S0 suites: `DesktopBackupReadOnlyInspectorTest` and `DesktopReadOnlyBackupRedTest`; the latter now asserts old restore rejection and separate inspection admission. `Official147FixtureCodec` is test-only pinned upstream code, not an alternative production codec.
- `DesktopFullBackupProcessTest` exercises schedule/recover, hard child-JVM exit during apply, and corrupt evidence refusal in independent JVMs. `tools/desktop/interop/` provides opt-in pinned-official Android instrumentation and Desktop archive consumers; require per-test results, not just build/ADB exit success.
- Plain/encrypted format tests do not substitute for actual Android 1.4.5 or Windows restart acceptance. `.cbsave`, full `.cbbackup`, native installer retention and Preview release approval remain distinct evidence categories.

- DesktopTaskRuntime.withMaintenance temporarily rejects task/message admission and joins owned writers before merge exclusive IO. Timeout keeps admission stopped; permanent shutdown cannot be reopened by lease release. Existing closeAndDrain semantics remain. Tests: DesktopTaskRuntimeTest.

- `DesktopMergeImportService` / Controller / Panel is the default Data-page merge workflow. Incoming authenticated staging and a credential-free frozen PC export produce choices; confirmed commit drains tasks/scheduler/audio before exclusive source rechecks, safety snapshot and new-root data/key preparation. Only protected completion precedes bootstrap CAS. Committed/indeterminate publication seals old IO and retains destination ownership until container storage close; failures keep old data/keys and inert preparation. Desktop settings are separately preserved/rechecked. Fresh-root authority is injectable for synthetic container tests. CLI/Portable source mode currently refuses. Source version/scope, original package/Moments custody and G2A/S0 contracts remain separate. Tests: DesktopMergeImportServiceTest.

- Merge preview model details are explicit local UI projections of provider/endpoint/remote model/ID, never raw JSON or keys; global secrets do not prove remote account identity. Legacy v1 replacement remains regression-tested internally but has no production UI action. Modern Service export checks owned source/pending journals and whole-root graph before snapshot. Tests: DesktopFullBackupServiceTest, DesktopMergeImportServiceTest.

- `DesktopHistoricalVoiceCustody` is the Desktop-only original top-level historical recording/owner JSON and MP3 domain. Verified source and selected graph bindings produce a seal only under the exact owned PREPARING capability; cancellation invalidates it. Unknown nonblank versions can pass whole-root validation only with matching stable record binding and live audio SHA/length. Staged validation receives verified evidence plus the future root; ordinary unproven history still refuses. Raw originals/media remain outside live cleanup, survive snapshots/modern backups and are never rebound or made current. Index/path/file-set/hash/type/budget checks fail closed. Source staging must keep raw chat/voice bytes for original inventory hashes. Test: DesktopMergeRootPreparationTest, including mutation, cancel, actual audio deletion and roundtrip cases.
- The same domain dispatches the distinct `DesktopSlotHistoricalVoiceCustody` index kind for session restores. It retains an independent original v8/legacy archive and exact target bindings, published append-only by DesktopSessionCommitJournal with the restored graph. Full-backup/snapshot preservation does not depend on a mutable library slot or a live audio artifact. Strict source-package inspection and actual media hash bind unknown versions; no generic unknown-version admission. Tests: DesktopHistoricalSaveSlotProcessTest (independent processes, deletion, mutation, cancellation and modern whole-backup roundtrip).
- Merge progress is a fixed Stage plus verified target-file count, exposed through opt-in Service methods while preserving the original method signatures. Controller messages never include source records or keys. File counts advance only after copy/hash verification; notifications stop before the non-cancellable bootstrap section, and success remains the returned Publication result. Cancellation still retains inert preparation and both source sides.
- `DesktopMergeImportController` exposes bounded code-location diagnostics after failure through `failureDetails`; only exception class names and application class/method/line frames are included, never exception messages, file paths or entity values. The panel keeps these details collapsed. Draft/reading-position persistence failures and source-verification refusals receive distinct messages. Cleanup errors are retained as suppressed diagnostics without hiding the initial failure.
- `DesktopBoundRootMigration` is the controlled directory-switch route for an existing fresh-root binding or app-owned images/audio. It captures a credential-free self archive and separately compares raw-root proof and authenticated wire proof, then reuses the normal merge publisher for a newly bound target. Task, backup and audio maintenance cover preparation/publication; old root/keys remain. Existing byte-copy materializer still refuses bindings. Legacy media roots also enter this route to avoid retaining absolute paths into the old root; an unbound source keeps its global store untouched while known consumers are copied into the new independent namespace. Historical snapshot/recovery directories remain at the old root with an explicit UI notice; they are not claimed migrated. Limits and unknown-root refusal remain those of the full-backup path. `DesktopBoundRootLifecycleTest` covers media rebasing, external edit, protection failure, cancellation, final task write and restart admission; its native DPAPI case is explicit `CCB_PREVIEW_NATIVE_DPAPI=1`, using only invented values and owned roots.
- `DesktopMergeDestinationPlan` coalesces matching logical-path/hash media only when no incoming records are selected, preventing identical self-import resource growth. Different bytes and newly selected/forked incoming consumers retain separate resources. Full-backup limits and all source files remain preserved; relocation tests compare the complete media byte multiset before/after.
- StartupGate's `DesktopIndexStartupPreflight` observes metadata before journal recovery/repositories. Windows directory allocation size is not a stable content length; stamps normalize it while retaining identity/type/timestamps, reparse checks and regular-file byte lengths. `DesktopIndexStartupPreflightTest` covers the actual 0-to-4096 directory discrepancy and continued regular-file drift refusal.
