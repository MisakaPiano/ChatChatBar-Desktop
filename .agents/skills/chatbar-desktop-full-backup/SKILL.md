# Desktop Full-App Backup

## Entry points and format authority

- `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/backup/`: selected official ChatBar 1.4.5 @ `1198a13cf3008de1358b8a69aa5e40b64797c8d9` v1 envelope, Tink 1.23.0 codec, registry and streaming JSON transducer. The formal upstream baseline is still 1.4.1. Version code 84 comes from the selected official build source.
- `DesktopFullBackupArchive`: bounded authenticated scan without plaintext disk output, then credential-free staging and ZIP central/inventory verification. Preserve original input and transaction evidence; inspection/snapshot/mapping scratch has a separate owned lifetime.
- `DesktopBackupReadOnlyInspector` is a separate S0 API for v1/v2 and official codes 84–86. Its `ReadOnlyInspection` never authorizes restore or becomes `Prepared`; existing service/codec restore admission remains v1. Transport scope DTOs/options follow pinned 1.4.7. Checks are memory-only (64 MiB source/decrypted ZIP, 128 MiB expanded, ZIP32); unsupported schemas are explicitly uninterpreted, not portability-approved. Results contain only categories/counts/digests; known credential fields are classified without SecretStore access. This API has no GUI wiring and does not verify nested SaveSlot or dependency/resource graphs.
- S1 `inspectMoments` invokes `MomentArchiveReadOnlyValidator` only after the same complete S0 scan. `MomentArchiveSnapshots` are extraction DTOs, not live entities. Reports bind exact record SHA/length to the source digest and independently classify senderAvatar/body/metadata edges plus card/session/sender/Task.postId links. Only code85/86 top-level missing avatars receive the historical exception; code84 stays strict. Scope omissions, unresolved dependencies, unknown schemas/external references and known credentials cannot become runnable or persisted objects. No seal, restore, scheduler or repository is created. Focused tests: `MomentArchiveReadOnlyValidatorTest`; wire fixtures remain independent R1 DTOs.
- `DesktopFullBackupMapping` / `DesktopBackupPolicy`: explicit store registry, logical model ID to Windows physical key, flat image/document resources, re-persisted verified MP3 and ownership receipts. Unknown fields/stores fail before commit. Internal brush preferences survive in a local singleton and return to official preferences.json on export.
- Mapping inventory refuses unclassified hidden ancestor/file bytes (`UNCLASSIFIED_HIDDEN_BACKUP_ENTRY`) before export scratch instead of silently omitting them. Existing single-file `.part`/`.tmp`/`.backup` and the explicit translation-cache exclusion remain; this is refusal, not a Moments preservation adapter. Current G0/G0R tests assert refusal; original omission evidence remains historical.
- `DesktopBackupScratch`: registers only invocation-created files/directories with native identity. Removes redundant decrypted ZIP immediately; prepared entries live until confirm/discard/replacement/panel leave/cancellation/shutdown. Export and mapped plans close after use. Cleanup never traverses unknown children or touches restore journals; identity changes report cleanup unconfirmed. No sweeping historical or crash-left work without ownership evidence.
- `DesktopBackupCompatibility`: payload-free categories distinguish unsupported Moments, other unknown entity types, incompatible fields, and external credentials. All still reject the whole archive before live commit; no credential-transfer permission or opaque-preservation contract is implied.
- `DesktopFullBackupGraphValidation`: offline message/version/voice, memory graph, media and SaveSlot checks; no model calls or default-filling repair.
- `DesktopFullBackupService`, `Controller`, `Panel`: app-owned operation and explicit replacement confirmation on the Data page. Passwords are volatile and cleared. No SecretStore interface is injected; nonempty incoming credential fields are rejected before plaintext staging.

- G2A `DesktopCredentialImportPlan` and `RecoverableIntentContract` are internal, unwired metadata contracts only. Inputs are trusted decoder/target-observation facts, not archives or keys; Community has no sink, endpoint/provider and name conflicts block candidates. Intent checks reject missing participants, old/new proof, generations and mixed/ambiguous completion; they never write, authorize business, or prove durability. Focused tests: DesktopCredentialImportPlanTest, RecoverableIntentContractTest, G2AOfficialWireTest. The strict test-only wire subset is not a production credential decoder.

- G2B `inspectCredentialSources` is opt-in inside the same S0 scan and publishes only after final validation. `DesktopCredentialSourceCensus` covers pinned145/code84/v1 preferences, settings and model/embedding metadata; unknown entities, media/packages and opaque custom parameters make it incomplete. `VerifiedCredentialSourceMetadata` owns copied char buffers and must be closed; comparison/plan integration consumes it. Target readers are injected synthetic-only assertions, never OS identity/CAS evidence; Community is never offered to a key comparator. Existing inspect/inspectMoments and restore guards remain separate. Focused suite: DesktopCredentialSourceCensusTest.

- T1 `DesktopTargetIdentityEvidence` and `ExplicitSyntheticDirectoryWitnessReader` are internal, unwired synthetic-only target metadata observers. Explicit sandbox directories reuse native read-evidence handles; injected configuration generations are not OS CAS. Directory identity, account/endpoint conflicts and unavailable declarations stay separate from always-UNKNOWN protection/account binding/global consumer closure; targets always have UNKNOWN secret relation and never authorize restore. No secret read, discovery, registry, namespace or transaction write. Focused suite: DesktopTargetIdentityEvidenceTest.

- LR4 `backup.preparation` contains unwired `FreshRootPreparation` (synthetic fresh-root/protector/typed-target/legacy-retention assessment delegating to G2A recovery intent checks) and `DormantPreservationPreparation` (bounded memory-only strict raw voice/Moment and media candidates). Neither performs IO, store access, publication or runtime activation. Preparation evidence is injected/synthetic, never OS identity or durable authority. Tests are `FreshRootPreparationTest` and `DormantPreservationPreparationTest`; `tools/desktop/interop/lr4` provides opt-in historical-voice continuation while keeping semantic/restore BLOCKED. Snapshot/backup/GC/Portable/downgrade/P13 participation is not implemented.

- LR4 code86 entity recognition uses `Official147EntityWire` only after authenticated Manifest/Inventory checks: strict pinned 1.4.7 CharacterCard image settings and Studio generation settings, with immutable original JSON retained. It does not change code84/85 admission, baseline, runtime models or restore. Focused suites: `Official147EntityCompatibilityTest`, `HistoricalVoiceUpstreamReproductionTest`; the latter demonstrates undesirable existing rebinding, not a safety PASS.

- LR5 `tools/desktop/interop/lr5` is a test-only, file-backed synthetic journal actor and focused child-JVM halt/reopen suite. `Run-Jvm.ps1` snapshots sources into unique rounds; `Audit-Evidence.py` indexes only LR5 public evidence and its exact task-owned synthetic roots. It reuses unchanged `DesktopDocumentIndexReadEvidence.observe` for directory object witnesses; fake protection, receipts and cooperating locks do not establish DPAPI identity, global consumer closure, old-writer fencing or a production authority schema.

- `DesktopFreshRootAuthority` owns the new import root activation fence at `backups/.restore-app.tmp/active-isolated-import` and a separate protected namespace. Startup journal recovery and WindowsSecretRootResolver verify native root/context binding before opening it; PREPARING/corrupt/cloned roots refuse, legacy roots remain unchanged. Genesis data/key hashes are checked once before activation; normal later edits remain possible. Tests: `DesktopFreshRootAuthorityTest`, including explicitly opted-in native DPAPI with invented values in task-owned directories. Merge/materialization, root-migration rebind and UI remain separate implementation work.

## Restore lifecycle

- Prepare and verify under normal admission; flush the chat composer before snapshot/schedule. Join the automatic backup scheduler before reserving audio. Confirm audio stop/close, then enter exclusive coordination.
- `DesktopFullBackupCommitJournal.schedule` copies old/new evidence and atomically authorizes the next startup; it does not replace live content. Seal the coordinator as restart-required with the authorization marker. UI prevents further navigation/writes and offers normal exit, never automatic restart.
- `DesktopStartupGate` holds the root lock and calls whole-app recovery before index/session recovery and before constructing repositories. Partial startup installation rolls back; committed evidence is verified. Foreign bytes or changed evidence block startup. Old/new journals remain retained, never swept.
- Local root selection, desktop-settings, diagnostics/backups and the separately located protected SecretStore are preserved. A full archive containing Desktop-specific entities (including retrieval_model_config, absent from the selected Android registry) is not claimed Android-compatible.

## Verification

- Focused suites: DesktopFullBackupArchiveTest, MappingTest, CommitJournalTest, ServiceTest, plus StartupGate, data coordination and audio-maintenance regressions. Synthetic fixtures only; no real root restore.
- S0 suites: `DesktopBackupReadOnlyInspectorTest` and `DesktopReadOnlyBackupRedTest`; the latter now asserts old restore rejection and separate inspection admission. `Official147FixtureCodec` is test-only pinned upstream code, not an alternative production codec.
- `DesktopFullBackupProcessTest` exercises schedule/recover, hard child-JVM exit during apply, and corrupt evidence refusal in independent JVMs. `tools/desktop/interop/` provides opt-in pinned-official Android instrumentation and Desktop archive consumers; require per-test results, not just build/ADB exit success.
- Plain/encrypted format tests do not substitute for actual Android 1.4.5 or Windows restart acceptance. `.cbsave`, full `.cbbackup`, native installer retention and Preview release approval remain distinct evidence categories.
