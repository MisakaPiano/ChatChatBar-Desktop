---
name: chatbar-character-card-transfer
description: Maintain character PNG export, independent export cover, package transfer and preset dependency restoration.
---

- CharacterCard.coverImage is an independent original image in images/character-covers; avatar and chatBackground remain separate. Character drafts, backup resource mapping and deletion ownership retain the cover reference. Source files are never edited by preview/export. CharacterCardPackage v11 carries coverImageResourceId plus image bytes; older packages without a cover remain readable, without guessing a background is their original.
- Native PNG import retains an existing embedded independent cover; legacy native/ST PNG captures the image without card-data chunks via OriginalCharacterCover. Original PNG export preserves encoded image chunks and replaces native/card text payloads, avoiding stale chara/ccv3 or recursively embedded exports. Non-PNG originals stay unchanged on disk and decode to PNG only for output.
- ManageScreen.CharacterPngExportDialog defaults to original-cover output when available; explicit rendered-cover mode offers the existing styling controls and never overwrites the original. It selects a base from current-card cover/avatar/default/gallery/person images or OpenDocument. Selected base is retained as the independent cover in the exported copy only; the saved card/default/gallery are unchanged. Standalone base export saves clean PNG chunks or untouched non-PNG bytes through SAF. Optional displayText affects rendering only, never card.name. Complete format11 preserves cover/gallery/gates; explicit legacy9 drops those fields/resources with a visible loss warning.
- CharacterCardPngRenderer bounds-decodes source images before downsampling; an explicitly chosen unreadable image fails visibly. CharacterCardTransferService retains packaged character assets and optional defaultImageGenerationSettings.
- PresetCatalogService.characterPackage delegates to PresetCharacterDependencies: combine embedded world books with manifest worldBookPresetKeys; embedded defaultFormatCard wins, otherwise resolve optional defaultFormatPresetKey. Missing declared manifest dependencies fail before import. Never invent a default format for an unbound preset.
- CharacterCardTransferService imports dependency resources and binds resulting IDs. WorldBookReusePolicy reuses preset identity; FormatCardTransferService.importCharacterDefault reuses matching sourcePresetKey without replacing local edits, otherwise reuses equal content or imports a separate card.
- Synthetic tests: PresetCharacterDependenciesTest, FormatCardTransferServiceTest, CharacterCardPngRendererInstrumentedTest.

- Multi-background gallery: CharacterCard.chatBackgroundImages and PackagedCharacterCard.chatBackgroundImageResourceIds retain original image assets (introduced in Android package10, combined with cover in complete11). chatBackground remains the default; conversation overrides choose from the gallery without changing the card. Draft materialization reuses one copied path for shared default/gallery assets. CharacterBackgroundRetention protects references in other cards, conversations, drafts and streaming SaveSlot summaries during unlink/overwrite/delete.

- CharacterInfo/PackagedCharacter.enabled is the portable card-level gate (legacy Desktop desktopEnabled is a read alias). ChatSession.characterParticipation stores per-card manual choices (legacy desktopCharacterParticipation read alias); SessionCharacterParticipationPolicy is adapted from the neutral Desktop policy. Request-only filtering leaves formal cards/history intact; old automatic pause state is retained and manually controllable, while Android automatic residency production remains separate/pending.

- Complete11 reads legacy3–10 including both Android gallery10 and Desktop cover10. Default background need not belong to the gallery; duplicate gallery references are accepted then resolved/exported in first-occurrence order, never deduplicated by image bytes. PNG character text chunks are stripped from every packaged image resource as well as the outer PNG, so avatar/background copies cannot retain old card payloads. Original files are never rewritten; cover references participate in shared-image retention. New multi-scene entry work remains pending.

- Retained CharacterEditViewModel observes EditorDraftRepository.drafts: external management-list deletion of its loaded/pending draft resets to the latest formal card and cancels pending autosave, using the same discard path. WorldBookEditViewModel follows the same rule; internal save/discard suppresses observer reset while saving/not ready. ManagementDraftDiscardTest covers existing/new editors, pending restore prompts, no recreation and unrelated-draft isolation.

- A running reply freezes its request-side people view. Its later world-book timing write uses ChatRepository.updateSessionWorldBookClock to patch only the latest clock under the settings mutex, preserving subsequent quick people choices/settings and rejecting a different bound card.

- Ordinary ChatRepository.updateSession snapshot writes also preserve the latest participation/auto-pause fields, like the existing narrative-mode protection. The existing explicit save-slot restoration flag restores stored choices; first writes retain supplied initial choices. Dedicated quick toggles and settings-draft saves remain the mutation paths.

- PlayerRolePolicy reuses the neutral Desktop explicit card/person identity rules, with independent follow-name/avatar flags. Global PlayerSetting.desktopAvatar and ChatSession.desktopPlayerAvatar are player resources, not character-package assets; linking does not change person gates or card data. A missing/ambiguous role falls back without name-based rebinding. Main chat request/rendering/home previews use the same resolved player name.
