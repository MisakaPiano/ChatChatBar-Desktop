# ChatBar Feature Map

Use this as a first-hop map. Read a specific skill or listed files, then search only if the map misses.

## Workflow

1. Match request to one or two rows.
2. Read the listed skill first when present.
3. Read listed files before broad search.
4. Use focused search only after first-read files do not answer location.
5. Replace stale rows when ownership moves; do not grow this file into an architecture guide.

## Feature Rows

- Explicit status ownership: shared `RoleplayStatusOwnership` validates closed STATUS blocks and owner labels, including emoji/bullet prefixes and Markdown emphasis. `CharacterResidencyPolicy` uses it only for the ending status sequence; `DesktopChatPeoplePolicy` requires one unique owner per block for the latest-status projection. Ordinary prose, unknown/ambiguous names, code and action choices stay excluded. `DesktopRoleplaySegmentSurface` left-aligns STATUS in both chat and screenshot export while narration retains its existing centered layout.

- Desktop person editor focus: `DesktopCharacterEditorPanel` selects the requested person, waits for that detail's `onGloballyPositioned` before `BringIntoViewRequester`, and consumes the focus revision after scrolling. A fixed one-frame wait can target the previous detail; test both heading and profile viewport geometry in `DesktopChatPeoplePresentationTest`.

- Desktop residency: shared `CharacterResidencyPolicy` recognizes known speaker output and explicit owners in the ending status sequence over source-turn groups. `DesktopCharacterResidency` runs only for a newly retained completion; `DesktopChatPeoplePolicy` derives display without changing settings on load/scroll. `desktopAutoPauseAbsentPeople` defaults off. The settings draft edits only that Boolean; `ChatRepository.saveSessionSettingsDraft` clears automatic reasons after merging the latest session, retaining current manual reasons.

- App wiring and navigation: app/app/src/main/java/com/example/chatbar/ChatBarApp.kt, Navigation.kt, NavigationKeys.kt.
- Desktop inline/full composer: `DesktopFullComposer.kt` shares the input/draft owner; `DesktopContinuationConfirmation.kt` is the blank-send confirmation. `DesktopPrimaryChatPanel` routes ordinary sends separately from confirmed blank continuation. `DesktopPrimaryChatController.continueEmptyComposer` rechecks captured session, empty draft and attachments at admission; the existing request planner owns the transient continuation request. Blank Ctrl+Enter stays disabled; the confirmation owns its own Escape dismissal.
- Desktop action choices: `DesktopActionChoices.kt` recognizes explicitly titled, closed STATUS fences with consecutive numbered options; ordinary code/links and streaming pseudo-messages remain inert. `DesktopPrimaryChatController.actionChoiceForDraft` rechecks the persisted current message/alternative; `editComposerIfCurrent` pins writes to the session and exact prior draft. `DesktopComposerInput` inserts after the selection without replacing original text and owns explicit choice undo, invalidated by later manual/external text edits. Both editor presentations share the same durable draft sink; no send is invoked.
- Desktop chat people/status: `DesktopChatPeoplePolicy.kt` projects explicit single-owner closed status blocks from persisted current alternatives across the full session, separately from its viewport; duplicate names, mixed owners, code and action choices are not status ownership. Controller computes the projection off the UI thread. `DesktopChatPeople.kt` owns the wide rail, compact dialog, avatar hover/context and source disclosure. `DesktopPrimaryShell` delivers card/person IDs through `DesktopManagePanel.initialPerson`; `DesktopCharacterEditorController.openPerson` preserves same-card edits and uses the ordinary leave guard across cards. `personFocusId/revision` selects and scrolls the actual fields. Catalog `load` reads first, then updates only catalog fields on the latest state, so concurrent opens/edits survive.
- Desktop person participation: shared `SessionCharacterParticipationPolicy` owns the structured-card request view. `CharacterInfo.desktopEnabled` is the card-level gate, edited in `DesktopCharacterEditorController.setCharacterEntryEnabled`; session enable cannot override it. The optional gate travels through `PackagedCharacter` and the shared transfer core, with the enabled default omitted; this is a Desktop extension. `ChatSession`/`SaveSlot.desktopCharacterParticipation` retain typed card/person references. Controller session changes reserve voice/text mutation; planner, repair roster, chat image design and Fish generation consume the effective card. Freeform body exclusion is deferred. Original profiles/history/recordings remain intact. `SettingsDraftMerge` handles omitted cleared defaults while retaining newer unedited fields.
- Character card edit UI: Android `ui/character/CharacterEditScreen.kt`, `CharacterEditViewModel.kt`; Desktop `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/DesktopCharacterEditorPanel.kt`, `DesktopCharacterEditorController.kt`, and `DesktopCharacterDraftResources.kt`. Both use shared `EditorDraftRepository`/`CharacterRepository` and `domain/draft/CharacterOpenModalState.kt`/`CharacterEditorDraftUiState.kt` for legacy-compatible modal and post-commit draft state; legacy Character WorldBook bindings use shared `domain/card/CharacterWorldBookBindings.kt`. Renaming a card name rewrites bound session titles via `ChatRepository.rewriteSessionTitlesForCharacterCard`.
- Character default format binding: `CharacterCard.defaultFormatCardId`, character editor draft/save, and shared authority `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/chat/CharacterSessionService.kt` (initializes new sessions only). `CharacterCardPackage` v9 optionally embeds one `FormatCardPackage`; `CharacterCardTransferService` covers JSON/PNG/copy/overwrite, and `FormatCardTransferService.importCharacterDefault` reuses matching name/content/ordered tools or imports a non-default copy. Null binding omits the embedded package; versions 3–8 remain readable. Missing references are shown in the editor and rejected on export; new sessions log the missing reference and use the existing global default path.
- Structured character transfer into another character card or a World Book: shared `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/card/CharacterSectionImportPolicy.kt` and `StructuredCharacterFreeformConverter.kt`, plus the Android character/world-book editors and Desktop WorldBook editor.
- Character-card AI auto-fill, rewrite, image-to-appearance fill, diff, apply, cover, or per-character avatar: use chatbar-character-card-ai.
- Chat prompt composition, stable/dynamic/tail cache layers, history roles, previous-turn hot zone, World Book/RAG/Archive/HEAD order, final logical `ChatApiMessage` ordering/cache key, Prompt Inspector, or prompt-delivery diagnosis: use chatbar-prompt-pipeline. Phase 4 shared authorities include `PromptAssembler.kt`, `MainChatRequestAssembler.kt`, `ChatHistoryPromptPolicy.kt`, `ChatRequestMemoryPolicy.kt`, `ChatApiMessage.kt` and `PromptCacheKeyFactory.kt` under sharedCore. Desktop Phase 4 uses common `DesktopChatRequestPlanner.kt`; `DesktopFakeChatRuntime.kt` performs persisted fake-request orchestration and `DesktopPromptInspector.kt` is the strict read-only projection. Both must stay transport-free and consume shared authorities rather than fork them.
- Format-card editing, ordered user tools, request-only user-message suffixes, drafts, or transfer: shared contract `app/sharedCore/src/main/kotlin/com/example/chatbar/data/local/entity/FormatCard.kt`, shared validation `FormatCardUserToolValidator.kt`, shared request runtime `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/card/FormatCardUserToolPolicy.kt`; Android `ui/format/FormatCardEditScreen.kt` and `FormatCardEditViewModel.kt`; Desktop `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/DesktopFormatCardEditorController.kt` and `DesktopFormatCardEditorPanel.kt`. Both use shared `FormatCardRepository` and `EditorDraftRepository`; use chatbar-prompt-pipeline for final logical placement.
- Character-specific format-card AI creation, creative guidance/example, candidate validation, and blank-new-card apply: use chatbar-format-card-ai.
- Any main-chat Prompt text/template/builder change: use `chatbar-prompt-pipeline` and start from shared `domain/prompt/MainChatPromptAuthority.kt`; Android `PromptTemplates.kt` is the compatibility facade. For non-migrated auxiliary Prompt families still in `PromptTemplates.kt`, use the same skill and maintain its file-header AI prompt directory.
- Chat screen behavior outside a specific skill: ui/chat/ChatScreen.kt, ChatViewModel.kt, and DebugLogDialog.kt. The authoritative chat entities, repository, and pure ordering policies live under `app/sharedCore/src/main/kotlin/com/example/chatbar/` (`data/local/entity`, `data/repository/ChatRepository.kt`, and `domain/chat`). Archived chats expose an explicit character-card picker; `ChatRepository.relinkArchivedSession` validates missing old/present new cards and changes only the current session's card binding under the settings mutex, preserving history, memory, and settings. Use chatbar-image-generation-runtime and chatbar-long-term-memory for anchor/source-turn effects.
- Home session list, long-press actions, pin/delete, or display-title override: ui/home/HomeScreen.kt, HomeViewModel.kt, plus sharedCore `SessionDisplayTitlePolicy.kt`, `ChatSession.kt`, and `ChatRepository.kt`. Session duplication: domain/chat/SessionCopyService.kt and SessionCopyPolicy.kt; uses SaveSlot streaming media transfer, current memory snapshot, fresh message IDs, and copied voice anchors.
- Long-term memory, HEAD, Episode/Arc/Era, source-turn/T mapping, Gap/backfill, historical source repair, compression, tier history, Archive injection, or SaveSlot memory migration: use chatbar-long-term-memory.
- Message AI format repair, automatic checks, restore-original notices, repair model selection, or repair state: use chatbar-message-format-repair.
- Shared AI background protection, foreground-service lifecycle, network guard, notification stop action, wake/Wi-Fi locks, or `ForegroundServiceDidNotStartInTimeException`: use chatbar-background-work-runtime.
- Model fallback, provider request fields, HTTP/local auth, thinking controls, connection tests, SSE timeout/reset, or auxiliary text requests: use chatbar-model-request-runtime.
- Desktop static images, chat attachments/backgrounds, native crop/preview, and export-only PNG cover: use chatbar-image-generation-runtime; start with DesktopChatImages, DesktopOwnedImageCleanup, DesktopImageWorkspace, DesktopImageViewer, and DesktopCoverExportDialog under desktopApp.
- Generated-image runtime, NovelAI HTTP generation, 429 retry, editable regeneration, metadata, dimensions, seeds, concurrency, or file replacement: use chatbar-image-generation-runtime.
- Assistant segmented bubble rendering: ui/components/ChatBubble.kt; marker parsing in domain/chat/RoleplayContentSegments.kt; per-turn protocol in PromptTemplates.kt and ChatViewModel.kt; edit/delete in ChatViewModel.kt; Android selection/screenshot in ChatScreenshotSelection.kt and ChatLongScreenshot.kt. Desktop uses DesktopChatScreenshotSelection (text/images only), DesktopChatScreenshotHost and independently owned selection/preview DesktopScreenshotWindow shells; preview scroll/zoom never changes export pixels.
- Fish Audio API, credentials, voice library/bindings, AI tags and confirmation, generation batches, anchors, persistence, playback, SaveSlot transfer, or voice UI: use chatbar-fish-audio-voice.
- Character speaker names/history: domain/card/CharacterSpeakerNamePolicy.kt, CharacterSpeakerMigration.kt, domain/chat/SpeakerTagHistoryService.kt, and ChatRepository.rewriteSpeakerTagsForCharacterCard.
- Settings navigation/search: ui/kit/SettingsBrowser.kt; global eight-category content in ui/manage/GlobalSettingsScreen.kt, session six-category content in ui/chat/SessionSettingsContent.kt. ChatSettingsDialog.kt retains tool tabs and session drafts; ManageScreen.kt owns the global save entry. SettingsRepository.kt and ChatRepository.kt merge edited settings fields through SettingsDraftMerge.kt. Navigation.kt carries the global unsaved-settings guard.
- Chat save slots/archive transfer: shared `app/sharedCore/src/main/kotlin/com/example/chatbar/data/local/entity/SaveSlot.kt`; Android data/repository/SaveSlotRepository.kt, domain/chat/SaveSlotJsonTransfer.kt, ChatViewModel.kt, ChatSettingsDialog.kt. Desktop external inspection remains DesktopSaveSlotInspector / DesktopSaveSlotInspectionPicker; DesktopSaveSlotController/Panel, DesktopSaveSlotService/Archive/RestorePlan and DesktopSessionCommitJournal own managed create/import/export/restore/copy/rebind with startup recovery. Shared domain/chat codecs and policies are used by both platforms. Use chatbar-save-slot.
- RAG/search/indexing: shared `domain/rag/{RagManager,RagRepository,ChunkingEngine,VectorSearchEngine,ChatMemoryIndexPolicy,RagSourcePlan,RetrievalPlanner}` and `ui/chat/RagRetrievalPolicy`. Desktop `DesktopDocumentIndexService`/`DesktopChatMemoryIndex` stage bounded embeddings and publish through `DesktopIndexCommitJournal` after strict source/config reproof; startup replays that journal under root ownership. `DesktopDocumentRagReader` and history candidates use normal-operation admission for production reads. `DesktopChatRetrieval` uses the official split document/history ranking, then `DesktopChatRequestPlanner` delegates Prompt ordering. `DesktopRagController` owns index jobs, settings and retry status. Metadata-only G0 and the earlier offline `DesktopDocumentRagIndexPreparation` remain separate. RAG is raw chat/document knowledge, not Archive/HEAD vectors; use chatbar-long-term-memory for shared source-turn boundaries.
- NovelAI prompt/tag design: use chatbar-novelai-prompt, then read domain/image/NovelAiPromptDesigner.kt.
- Home image prompt tool, reference-image reverse prompting, or manual NovelAI prompt editing: use chatbar-novelai-prompt and chatbar-image-generation-runtime, then read ui/imageprompt/ImagePromptToolScreen.kt and ImagePromptToolViewModel.kt. Independent studio AI-design conversations and their natural-language mode use NovelAiDesignScreen.kt, NovelAiDesignViewModel.kt, domain/image/NovelAiDesignConversationModels.kt, and data/repository/NovelAiDesignConversationRepository.kt.
- APNG disguise/restore, static/GIF/APNG inspection, mosaic-editor image processing, or direct share/save: use chatbar-image-generation-runtime, then read ui/components/ImageMosaicEditor.kt, domain/image/ImageProcessingService.kt, domain/image/ApngDisguiseCodec.kt, and ui/components/ImageActions.kt.
- Moments: use chatbar-moments before Moments UI, ViewModel, scheduler, prompts, storage, or post image policy.
- Community: use chatbar-community-platform before community UI or Supabase/Edge Function code.
- UI kit and Compose styling: use chatbar-shadcn-compose, then read ui/kit/ and target screen.
- Emulator/device/build verification: use chatbar-emulator-test.
- Crash diagnostics and report sharing: domain/diagnostics/CrashDiagnosticReport.kt, utils/diagnostics/CrashReportManager.kt and SystemExitInfoReader.kt, ui/components/CrashReportDialog.kt, ChatBarApp.kt, MainActivity.kt, Navigation.kt, ui/manage/GlobalSettingsScreen.kt.
- App update checks, release APK download, system installer handoff, or release publishing: use chatbar-app-update.
- Import/export/card packages: shared contract, Character materialization, SillyTavern JSON/PNG parsing/mapping, PNG payload codec/options, content-classifier authority, and production `CharacterTransferPromptPolicy` under `app/sharedCore/src/main/kotlin/com/example/chatbar/domain/card/`; the Character NAI default-negative Prompt authority is `sharedCore/.../domain/prompt/CharacterNaiPromptDefaults.kt`. Android Character/Uri/Prompt/log facades remain in `CharacterCardTransferService.kt`, `AndroidCharacterTransferAdapters.kt`, `SillyTavernCardParser.kt`, `SillyTavernCardMapper.kt`, and `SharedImportClassifier.kt`; Android visual rendering remains in `CharacterCardPngRenderer.kt`. Desktop management-style typed transfer, AWT PNG rendering, native picker, and external writer are under `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/DesktopTypedTransferController.kt` and adjacent Desktop files. SAF export contract is in `ui/components/CreateOpenableDocument.kt`; Android export UI is in `ManageScreen.kt`. Use chatbar-shared-import only for external ACTION_SEND/ACTION_VIEW/text routing, content detection, FIFO staging, conflicts, unknown-type recovery, and shared-image handoff.
- Persistence/entities: data/local/entity/, shared storage at `app/sharedCore/src/main/kotlin/com/example/chatbar/data/local/JsonFileStorage.kt`, related repository under data/repository/. Singleton reads return null only for missing files; corrupt/unreadable files throw `SingletonReadException` and block overwrites. `singletonReadFailures` feeds `MainActivity`/`StorageReadFailureScreen`; retry rereads failed files and resumes `ChatBarApp.initializePersistentState`. SettingsRepository serializes initialization/read-create/write. `saveAll` is per-file, with completed writes reflected in cache even on failure; MemoryRepository owns journal recovery. Desktop editor post-commit draft cleanup uses `DesktopEditorDraftCleanup.kt`; the shared Character, FormatCard, WorldBook, and EditorDraft repositories expose `refreshFromStorage()` for read-only cache reconciliation. Regression entry: sharedCore `JsonFileStorageSafetyTest`.
- World books: shared contract `app/sharedCore/src/main/kotlin/com/example/chatbar/data/local/entity/WorldBook.kt`, repository/transfer/draft authority, and `domain/draft/WorldBookEntryModalState.kt` plus `WorldBookEditorDraftUiState.kt` for modal/raw numeric and optional post-commit draft state; `EditorPostCommitFingerprint.kt` supplies Character/WorldBook recovery digests. Authoritative shared runtime `WorldBookEngine.kt`, `WorldBookScanContext.kt`, and `WorldBookRequestPlanner.kt` lives under sharedCore `domain/worldbook`. Android editor: `ui/worldbook/WorldBookEditScreen.kt` and `WorldBookEditViewModel.kt`. Desktop manual editor: `app/desktopApp/src/main/kotlin/com/example/chatbar/desktop/DesktopWorldBookEditorController.kt` and `DesktopWorldBookEditorPanel.kt`. For AI creation, blank-content fill, research, candidates, apply, or resume, use chatbar-worldbook-ai.
- Tutorial/help: ui/tutorial/TutorialScreen.kt.

All abbreviated source paths are relative to app/app/src/main/java/com/example/chatbar/.
