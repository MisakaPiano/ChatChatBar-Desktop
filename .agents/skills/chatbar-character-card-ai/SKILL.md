# ChatBar Character Card AI

Manual character avatar/background/person-image selection, crop and text-document staging use the AppContainer-injected `manualResourceAccess`. Its short synchronous normal lease begins after the native picker returns; an active/pending maintenance operation refuses before any staging or assignment, leaving the original draft and visible resource error for retry. It must not hold a lease across a human picker. Generated image application retains its separate already-admitted owner. `persistDraft` and clean-obsolete work acquire normal admission before their draft mutex; confirmed draft deletion plus draft-asset cleanup share that normal lease. Resource-cleanup retries admit draft-session deletion separately from the full-reference image cleaner's exclusive lease.

Desktop's shared `CharacterCardTransferCore` injection also supplies `postCommitResourceCleanup` for typed overwrite and deletion. Capture retired references only after the entity commit, keep document-RAG cleanup in its normal operation, then release that lease before `DesktopOwnedImageCleanup` takes exclusive full-reference custody. Historical Moment sender avatars/images, other cards, messages and drafts can retain the original files. Default/Android Core cleanup stays inline when this optional callback is absent; materialization rollback remains exact-new-resource cleanup. A failed postcommit reference scan reports the existing committed-transfer warning, never restores the old entity or treats the commit as a failed save.

The card post-commit retry owner serializes with `committedCleanupMutex`; state and committed identity are re-read after acquiring it. While exclusive cleanup waits for other operations, retain the original committed-warning/marker edit guard. The actual admission test also holds another normal operation and starts a duplicate retry before allowing the next draft.

The maintenance-wait UI fixture must not request a new normal repository read while it owns the blocker: that read correctly queues behind the exclusive waiter and prevents the test from releasing itself. Inspect only its known synthetic durable entity JSON during the wait, then recheck through the production repository after release. Keep the stage/independent daemon stack/original-exception diagnostics and failure deadline; no-case timeouts are not business reproduction.

Desktop normal card save releases its commit's normal data admission before invoking the original `retryCommittedCleanup` owner. AppContainer first excludes previous resource references positively retained by the verified current cards; remaining candidates still use `DesktopOwnedImageCleanup`'s exclusive full-reference scan. Parameter-only saves do not require unrelated JSON to be readable. The durable-marker/cache/rename/draft checks remain. Active or blocked postcommit work retains the same scroll form with an input guard; the committed marker still guards controller edits, pickers and staging. Completed resource failures remain nonblocking, with explicit saved-versus-maintenance wording and retained in-process card/session cleanup intents for explicit retry without saving again. Those intents are not a persistent cleanup journal. `DesktopCharacterSaveUiIntegrationTest` uses the actual container, parameter switch and Save/retry callbacks; `DesktopCharacterImageSaveAdmissionTest` retains real removed-resource and corrupt-authority coverage.

Desktop normal character editing keeps its five tool entries in the fixed `character-editor-tools` FlowRow above the existing scroll owner: image/style jump, cover candidate, field budget, structured-only fill and rewrite. Use the common compact tertiary entry style; keep original owner callbacks/availability and the fixed save/cancel footer. `DesktopEditorPromptBudget(toolEntry=true)` changes only this entry presentation; other editors retain their original button. The style jump measures the actual post-toolbar viewport.

Desktop character image defaults use `DesktopCharacterImageDefaults` inside the normal editor draft. AppContainer supplies the real settings Flow for an inherited image model; unknown global model is not guessed. Model capabilities filter samplers/Variety+, while hidden card values stay stored until an explicit edit/reset. Editor save copies both nullable model/settings fields; validation precedes persistence. Cover/avatar candidates freeze the effective card-or-global model and card parameters in retry identity, retain original random seed/512 avatar/crop/credential/explicit-apply behavior, and pass applied parameters to the existing generation gateway. See276; a Package roundtrip alone does not prove this editor/consumer path.

Desktop fill/rewrite, image-to-appearance and cover/avatar work pass explicit CHARACTER_AI/CHARACTER_APPEARANCE/CHARACTER_IMAGE purposes to the original TaskRuntime child. Task completion is operation/candidate work, not durable card save. Each revealTaskDraft only opens the still-matching original pin without refreshing models, selecting another source, regenerating or applying; changed/closed pins refuse. Manage task navigation uses normal section guards and never reloads the editor to satisfy a stale target.

Character image generation supplies its actual card/draft/person as optional usageContext to withCardDesign; that owner injects its existing child UUID before the original work. DesktopCharacterImageGeneration reuses the frozen credential and original image service for metadata-only image statistics. The candidate overlay's compact image-log entry shares the original DebugOverlay and editor group; opening/clearing does not generate or apply candidates. Cached finalImage reuse never creates a new network row. See259.

## Domain Rules

- Fill, rewrite and image-to-appearance ViewModel jobs each own an `AiStreamProgress` observer, rendered by `AiStreamProgressPanel`. Nested image understanding, research planning/briefs, generation and JSON repair stream into the same operation panel without mixing reasoning into parsed JSON. Appearance and character JSON repair now use streaming completion. Optional research failures preserve the existing continuation policy but publish the cause; cancellation/refusal must propagate.

- Fill/rewrite/appearance requests declare CHARACTER_FILL, CHARACTER_REWRITE or CHARACTER_APPEARANCE; repair uses stage REPAIR. Nested research and retries share AiTaskRun. Both fill and rewrite reject terminal stream errors before checkpointing or JSON repair, while keeping partial previews visible. Research refusal/cancellation propagates through CharacterResearchService and LlmResearchBriefSummarizer without producing fallback facts.

- Auto-fill and rewrite search planning, research-brief cleaning, and final generation share the corresponding dialog's selected model, or the default chat model when unset. Both `CharacterAutoFillService.buildResearchBrief` and `CharacterRewriteService.buildResearchBrief` pass their resolved generation model directly.
- Auto-fill reference images support batch selection and append through `GetMultipleContents`; numbered previews define request order. `copyReferenceImages` copies each batch sequentially and rolls back that batch on failure. `generateAutoFillDraft(imagePaths)` includes the ordered paths in its retry signature and encodes them in order. Multimodal requests retain that order; linked vision models describe images sequentially. Dialog disposal cleans all retained reference images; list changes must not delete images still retained.
- Auto-fill generation and JSON repair defer output-token limits to `ModelConfig` (including custom output-token fields); they no longer impose 6000 tokens. Streaming errors, including length termination, stop before parsing, repair, or final-output checkpointing even with partial content. Partial output stays in the preview; prepared research remains reusable. Only successfully completed raw output is checkpointed for JSON repair retries. Repair has explicit progress status and a stage-specific truncation error.
- If AI output seems wrong, first inspect service parsing/materialization and UI merge paths.
- Preserve data: applying a candidate mutates in-memory edit fields only; saving remains separate.
- Saving a card materializes draft assets into persistent storage and then deletes the draft session dir. After a successful save, `CharacterEditViewModel.saveCharacterCard` re-syncs its editable state (`avatar`, `chatBackground`, `charactersList`, `documentsList`) from the persisted card, so a later save in the same session never references deleted draft paths; save re-entry is guarded by `_isSaving`, and `materializeCharacterAssets` failures surface as a `_indexingStatus` error instead of crashing.
- Preserve mode split: structured mode uses `characters`; freeform mode uses `freeformCharacterText`.
- Treat `CharacterInfo.fishAudioVoice` as user-owned configuration. Auto-fill/rewrite output must not create, clear, or replace it; materialization and merge must preserve the current binding for retained character IDs.

## Rewrite Model

- `CharacterRewriteService.rewriteStreaming` returns a materialized draft: omitted existing fields are filled from current card.
- `mergeInto(current, draft)` is source of truth for post-apply card content.
- Existing structured characters must keep stable `id`; new characters get generated ids; deletions use `deleteCharacterIds`. Draft entries with missing or unknown `id` first name-match (case-insensitive) existing non-deleted characters as patches; redundant duplicates of an already-matched character are dropped, unmatched visible entries become additions. Both rewrite Json configs coerce `null` lists and tolerate trailing commas.
- Diff UI should compare `buildCurrentCard(markDirty = false)` against `mergeInto(current, draft)`, not raw AI JSON.
- Current, auto-fill, and rewrite cover actions open `CharacterCoverRequestDialog` with optional image content and editable special requirements. First open loads `NovelAiStudioRepository.loadDraft().extraRequirement`; retries retain the submitted fields and never overwrite Studio. Both fields reach the existing `PromptTemplates.novelAiImagePromptCharacterCard` manual-requirement builder. Resume requires unchanged card content (excluding volatile identity/timestamps), requirements, target image model, and ratio; only final image bytes qualify for save-only retry.
- Cover previews use Fit and shared full-screen viewing. `CharacterCoverImageUiState.avatarPath` holds an optional PNG crop in generated-image storage, so saving the card before applying a candidate cannot delete its crop with the editor draft directory. Applying a cover/candidate uses that crop for `avatar` and the complete generated image for `chatBackground`. Crop alone never applies the candidate; replacement/discard cleans the owned crop with its candidate.
- Per-character avatar candidate bypasses AI Prompt design and tag research. `CharacterAvatarImagePolicy` directly builds original card style + CharacterInfo.imagePrompt + the approved fixed avatar positive; freeform uses original manual positive + the same suffix. The user separately adopted fixed147 positive/negative composition (258): CharacterAvatarImagePolicy appends the avatar negative after the original explicit or default card negative. It retains fixed Small Square512x512 and does not change cover plans.
- The deterministic avatar policy now lives under sharedCore `domain/image`; its positive/negative builders and constants live in `CharacterCardAiPromptAuthority`, with Android PromptTemplates facades. Sharing that policy alone does not connect Desktop avatar generation or candidate resource ownership.
- Desktop `DesktopCharacterImageController`/Panel handles current-card and fill/rewrite-candidate covers, plus per-person structured/freeform avatars. Covers seed the saved Studio requirement without writing Studio, show the actual resolved design provider/account/model, and reuse completed design on retry; avatars bypass design. A full image and optional independent avatar crop remain transient until explicit apply. `stageGeneratedCardImage` stages only new draft assets, rejects stale basis/candidate assignments and rolls back refused references; normal editor save materializes resources. AI-candidate cover apply does not alter the ordinary draft until that candidate is explicitly applied.
- All three Desktop B2 owners reset cancelled pre-start jobs via epoch-scoped completion, including image apply retaining its finished candidate. A queued dispatcher regression covers cancellation before the body enters; this differs from cancellation of an already running network flow.
- Avatar debugging displays only final NovelAI positive Prompt. Avatar generation requires NovelAI credentials but does not require the default image-design model/API key.
- Failed cover retries reuse completed Prompt design. Failed avatar retries rebuild the deterministic Prompt plan; if NovelAI already returned a final image and only saving failed, retry saves those bytes without generating again. Changed avatar inputs, negative Prompt, or fixed size invalidates its checkpoint.
- Auto-fill/rewrite failure retry inherits completed image understanding, research plan, prepared research, and final raw output, then resumes from the next unfinished phase without clearing prior results. Cleaned source excerpts remain only until an AI-organized research brief succeeds; that brief then replaces the excerpts in UI state, checkpoints, and final card-generation input. If brief JSON parsing fails (or the brief AI call throws with partial output), `LlmResearchBriefSummarizer.rawOutputFallbackBrief` keeps the full sanitized AI raw text as the brief facts with a `CHARACTER_RESEARCH_BRIEF_RAW_FALLBACK_NOTE` note; `CharacterResearchService` uses that raw brief instead of cleaned webpage excerpts and keeps `briefFailureReason`/`briefRawResponsePreview` visible in the debug snapshot and progress status. Cleaned-source `ResearchCleaner.fallbackBrief` now runs only when the AI produced no usable output at all.
- Encyclopedia research plans accept at most 30 queries. `CharacterResearchService` searches, extracts, and AI-cleans them in batches of 10, then combines and deduplicates each batch brief for both auto-fill and rewrite; manual-page and reference-document sources join the first applicable cleaning batch.
- Auto-fill and rewrite use a role-card-specific 600-second inactivity read timeout for final generation, JSON repair, encyclopedia planning, and research-brief cleaning. Keep the shared chat/default timeout unchanged; user cancellation must still cancel the active request immediately.
- Candidate dialogs expose a separate final-result retry. It clears only final raw output while retaining prepared research/image context; normal generate starts a fresh pipeline. Changed input, source image, reference document, research options, or current card content invalidates reuse; switching the generation model does not (research output is model-independent and the final step always re-runs with the current model).
- Resume reuse is gated by a content signature in `CharacterEditViewModel` (`generateAutoFillDraft`/`generateRewriteDraft`) that excludes card-level `id`, `createdAt`, `updatedAt`, and the selected model: `buildCurrentCard` falls back to a fresh random UUID and timestamps for new cards on every call, so any of these fields in the signature would make resume never match. The resume decision is visible as a progress line and logged under the `CharacterEditResume` logcat tag.
- Auto-fill and rewrite dialogs separately persist `CharacterResearchSourceMode` in `AppSettings.characterAutoFillResearchSourceMode` and `characterRewriteResearchSourceMode`. Modes are `NONE`, `ENCYCLOPEDIA_SEARCH`, `MANUAL_URLS`, and `ENCYCLOPEDIA_SEARCH_AND_MANUAL_URLS`; changed mode or normalized manual URL list invalidates prepared retry context.
- Manual URL input accepts up to five transient HTTP(S) URLs and reads only those pages through `HttpManualWebPageRetriever`. `MANUAL_URLS` never calls search planning or `SearchBackend.search`; combined mode runs both encyclopedia planning/search and manual retrieval, then merges both source sets. URL text and fetched page content are not persisted. Partial page failures remain visible; combined mode may continue with encyclopedia results, but no usable source across selected paths stops generation. Prepared-source retry skips downloading and searching again.
- Auto-fill and rewrite accept one transient TXT/MD/JSON reference document. `RagCharacterReferenceDocumentRetriever` matches user input plus current card against temporary document chunks, retrieves Top 20, then `CharacterResearchService` sends those hits through the same `ResearchCleaner`, brief summarization, checkpoint, and final-generation flow as encyclopedia results. Uploaded reference documents are not added to the card document library or persisted. Changed document content invalidates prepared retry context; document RAG failure must remain visible and stop generation instead of silently generating without the requested source.
- `CharacterInfo.appearanceImage` means character-owned chat/Moments avatar. It must not enter chat-model image understanding or character appearance text.
- Per-character image-to-appearance fill uses the current default chat model when multimodal; otherwise it requires that model's exact linked multimodal `visionModelId`. Results stay as an explicit appearance/clothing candidate until apply.

## Workflow

1. Read First Read files matching request.
2. Identify affected path: auto-fill, rewrite, apply, diff, cover, or tests.
3. Prefer local helpers and existing UI kit before adding new abstractions.
4. Add/update JVM tests for service, parser, materialization, or merge changes.
5. For UI-only behavior, compile and run CI-equivalent UI checks.
